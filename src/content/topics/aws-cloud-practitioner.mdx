المسار ده معمول لحد <Hl c="y">لسه مبيعرفش أي حاجة عن AWS</Hl>. مش هنحفظ قاموس خدمات؛ كل مفهوم هيبدأ بموقف حقيقي من شغل production، وبعدها نمشي في الـ request أو الحادثة خطوة بخطوة ونشوف القرار الصح وليه البديل مش مناسب.

<Box type="story" icon="🛒" title="الـ production system اللي هيتبني معانا">

عندنا **e-commerce platform** عليها web app وAPI وdatabase وصور منتجات وعمليات دفع وشحن. الـ traffic طبيعي أغلب اليوم، لكنه بيزيد عشر مرات وقت العروض. لازم النظام يفضل متاح، بيانات الطلبات متضيعش، والفريق يعرف يكتشف العطل ويتحكم في التكلفة.

هنبدأ من حساب AWS فاضي، ونبني الصورة جزء جزء: نأمّن الوصول، نختار compute وstorage وdatabase، نصمم network، نفصل العمليات بالـ events، نراقب production، ونحسب التكلفة. كل خدمة هتقابلها عشان تحل requirement واضحة، مش عشان اسمها موجود في الامتحان.

</Box>

## طريقة الشرح

كل فصل هيمشي غالبًا بالترتيب ده:

1. **سيناريو من الشغل:** system موجود وrequirement أو failure واضح.
2. **المشهد خطوة بخطوة:** timeline أو request flow بأرقام وأوقات.
3. **معنى المفهوم:** السؤال اللي بيجاوب عليه وحدود مسؤوليته.
4. **القرار:** إمتى الاختيار ينجح وإمتى يفشل، وإيه البدائل القريبة.
5. **تطبيق:** تمرين واقعي، checklist، وquiz يختبر الفهم مش حفظ الاسم.
