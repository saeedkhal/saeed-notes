## مش اختيار واحد

الحزمتين مش بديل لبعض. الشغل المعتاد يجمعهم:

| عايز إيه | الأمر | الحزمة |
| --- | --- | --- |
| تشغّل وأنت بتكتب | `tsx watch src/main.ts` | `tsx` |
| تتأكد إن الأنواع سليمة | `tsc --noEmit` | `typescript` |
| تطلّع `dist` للسيرفر | `tsc` | `typescript` |
| تشغّل الناتج في production | `node dist/main.js` | Node بس |

<File name="package.json">

```json
{
  "scripts": {
    "dev": "tsx watch src/main.ts",
    "typecheck": "tsc --noEmit",
    "build": "tsc",
    "start": "node dist/main.js"
  }
}
```

</File>

<Hl c="g">`dev` يسرّع الكتابة. `typecheck` و`build` هما اللي بيمنعوا غلط الأنواع من ما يوصل للسيرفر.</Hl>

## فين تتحط الحزمة

- **الاتنين `devDependencies`** لو الإنتاج بيشغّل `dist` بـ `node`.
- **`tsx` تبقى dependency عادية** بس لو السيرفر نفسه بيشغّل ملفات `.ts` بأمر `tsx`. ده أثقل في أول تشغيل، وبرضه مش بيفحص أنواع.
- **الـ CI يشغّل `typecheck`** حتى لو التطوير كله على `tsx`. محرر الكود بيعرض الغلط وانت بتكتب، بس ده مش خطوة في الـ pipeline.

## إمتى متجيبش tsx

- **ملف `.ts` بأنواع بتتشال بس**، وNode عندك بيشيلها لوحده: التشغيل ممكن من غير الحزمة. الفحص لسه محتاج `tsc`.
- **مكتبة هتتنشر:** المستهلك عايز JavaScript وملفات `.d.ts` من `tsc`، مش أمر `tsx`.
- **واجهة React:** المتصفح مش بيشغّل `tsx`. البناء هناك لـ Vite أو أداة تانية، و`tsc --noEmit` يفضل خطوة الفحص.

<Box type="warn" title="التشغيل الناجح مش عقد">

لو `tsx` خلّص من غير ما يقع، ده معناه إن JavaScript اشتغل. مش معناه إن `TS2322` مش موجود. الغلط النوعي يظهر لما السطر الغلط يتنفّذ، أو يفضل مستخبي لو السطر متعملش.

</Box>
