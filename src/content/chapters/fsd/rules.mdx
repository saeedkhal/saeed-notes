- **Public API:** كل Slice تصدّر فقط ما يحتاجه باقي التطبيق من `index.ts`.
- **ممنوع الاستيراد العشوائي:** لا تستورد من `features/add-to-cart/model` خارج الـ Slice. استورد من `features/add-to-cart`.
- **ممنوع Circular Dependencies:** الـ Entity لا تعتمد على Feature تستخدمها.
- **Server State:** استخدم React Query للبيانات القادمة من السيرفر، بما فيها الكاش والـ invalidation.
- **UI State:** استخدم State محلي للـ Modal المفتوح أو الـ Dropdown. لا تحوّل كل شيء إلى Global Store.
- **Cross-feature orchestration:** لو فيه Workflow يجمع أكتر من Feature، خلي التنسيق في Page أو Widget أو طبقة مناسبة للـ Use Case، من غير اعتماد مباشر بين الـ Features.
- **Domain boundaries:** لو المشروع كبير، مش شرط كل حاجة تتسمى Entity. اختار الـ Slices بناءً على مفاهيم الدومين الحقيقية.

<Box type="idea" title="ترشيح المتجر المتوسط أو الكبير">

استخدم FSD لتنظيم الكود، و TanStack Query للـ Server State، و Zustand فقط لو عندك Client State مشتركة فعلًا، زي حالة واجهة معقدة أو بيانات مؤقتة لا يمتلكها السيرفر.

</Box>

بكده يبقى فيه فصل بين مسؤوليات الـ UI، وأفعال المستخدم، وبيانات الدومين، والبنية التحتية. من غير ما كل Feature تتحول إلى جزيرة مستقلة، أو شبكة اعتماد متشابكة.
