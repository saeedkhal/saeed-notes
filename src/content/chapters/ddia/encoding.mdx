التطبيق بيتغير والـ schema بتتغير، بس مش في لحظة واحدة. السيرفر بيتعمل له <En>rolling upgrade</En>: الكام نود الجداد ينزلوا من غير downtime. والموبايل ممكن مايتحدّثش لشهور.

## أشكال الـ encoding

في الرام الداتا objects. على الديسك والشبكة لازم تبقى بايتات. التحويل encoding، والعكس decoding.

**فورمات لغة واحدة** (Java Serializable، pickle): مربوطة بلغة، والـ decoding يقدر ينفّذ كود، والـ versioning متهمل. تجنّبها على الحدود.

**JSON و XML و CSV:** مقروءين ومنتشرين، بس:

- الأرقام بتتلخبط. JavaScript بيبوّظ الأرقام الأكبر من ٥٣ بت، عشان كده فيه APIs بترجع الـ ID رقم ونص.
- الـ binary مش مدعوم إلا Base64 وده بيزوّد الحجم.
- الـ schema اختيارية، والـ CSV مفيش اتفاق ثابت على الـ escaping.

كويسين للتبادل بين شركات. جوه السيستم، الفورمات الثنائي بـ schema أوفر.

**Thrift و Protobuf:** schema إجباري، وبدل اسم الحقل بيتكتب رقم (tag). تغيّر الاسم تمام لأن الاسم مش في الداتا. تغيّر رقم الـ tag يبوّظ كل القديم. حقل جديد لازم يكون optional عشان القديم يتقري. متستخدمش رقم tag اتحذف تاني أبدًا.

**Avro:** مفيش tags في الداتا خالص. الـ reader بيقارن writer's schema بـ reader's schema بالاسم. حقل في الكاتب مش عند القارئ يتجاهل. حقل عند القارئ مش في الكاتب ياخد default. ممتاز لما الـ schema تتولد من جدول لوحدها، ومش محتاج code generation.

<Box type="idea" title="ليه الـ schema عمومًا؟">

حجم أصغر، توثيق محدّث، وتتأكد من الـ compatibility قبل الـ deploy. والـ code generation يديك type checking.

</Box>

## الداتا بتمشي إزاي؟

**عبر الداتابيز.** اللي بيكتب واللي بيقرا ممكن يكون أنت في المستقبل. مع الـ rolling upgrade، نسخة قديمة ممكن تقرا داتا نسخة جديدة، فالـ forward compatibility لازم.

<Box type="warn" title="فخ خطير">

كود قديم قرا record فيه حقل جديد، حوّله لـ object والحقل ضاع، عدّل حاجة، وكتبه تاني. الحقل الجديد اتمسح. الكود لازم يحافظ على الحقول المجهولة.

</Box>

الداتا بتعيش سنين والكود بيتبدل في دقايق. الـ migration الكامل نادر. الداتابيز بتسيب القديم زي ما هو.

**عبر الخدمات.** REST أنسب للـ public APIs: URLs و cache و curl. الـ RPC بيحاول يخلي نداء الشبكة شكله function call محلية، وده وهم:

- النداء المحلي يا نجح يا فشل. الشبكة ممكن timeout ومتعرفش حصل إيه.
- الـ retry ممكن ينفّذ مرتين، فلازم idempotence.
- الوقت مش متوقع، ومينفعش تبعت pointers.
- الطرفين ممكن يبلغات مختلفة.

gRPC أسرع جوه الشركة. السيرفرات بتتحدث الأول، فلازم backward في الريكوست و forward في الرد.

**عبر الرسايل.** الوسيط (Kafka، RabbitMQ) بيفصل المرسل عن المستقبل: buffer لو المستقبل مش متاح، وإعادة إرسال، ورسالة واحدة لكذا مستقبل. الـ actor model (Akka، Erlang) كل actor ليه state ومش بيشاركه، وبيفترض أصلًا إن الرسايل ممكن تضيع.
