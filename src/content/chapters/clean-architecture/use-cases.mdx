## الـ use case بيعمل إيه؟

الـ use case هو **سيناريو** من وجهة نظر المستخدم: "انشر الوظيفة"، "احفظ مسودة"، "انقل المرشح للمرحلة الجاية". بينسّق الخطوات:

<Flow items={[{"t": "يجيب الداتا", "c": 1, "s": "من الـ repository"}, "→", {"t": "يسأل الـ domain", "c": 3, "s": "canPublish؟"}, "→", {"t": "يغيّر الحالة", "c": 2, "s": "publish()"}, "→", {"t": "يحفظ", "c": 4, "s": "save()"}]} />

القواعد نفسها في الـ domain، والـ use case **بيرتّب** الخطوات بس.

## الغلطة المشهورة: import مباشر

أسهل طريقة تكتبه بيها:

<File name="src/application/publishJob.ts">

```ts
import { canPublish, publish } from "../domain/job";
// ❌ الـ use case بقى معتمد على تفصيلة infrastructure
import { getJobApi, saveJobApi } from "../infrastructure/jobApi";

export async function publishJob(id: string) {
  const job = await getJobApi(id);
  if (!canPublish(job, new Date())) throw new Error("Job is not ready");
  await saveJobApi(publish(job));
}
```

</File>

الكود ده شغال، وأمثلة كتير على النت (ومنها المقالة اللي المذكرة دي مبنية عليها) بتكتبه كده. بس بص على اتجاه الـ import: الـ application بقى بيشاور **لبره** على الـ infrastructure. يعني:

- عشان تختبره لازم تعمل mock للموديول نفسه (`vi.mock`)، وده هش.
- لو غيّرت REST لـ GraphQL، هتفتح ملف الـ use case.

## الحل: Port = interface بيملكه الـ application

بدل ما الـ use case يدوّر على الـ API، **هو بيقول هو محتاج إيه** على شكل interface. ده اسمه **port**. والـ infrastructure هي اللي تنفّذه.

<File name="src/application/ports.ts">

```ts
import type { JobPosting } from "../domain/job";

/** الـ application محتاج حد يجيب ويحفظ الوظايف، ومش فارق معاه إزاي */
export interface JobRepository {
  getById(id: string): Promise<JobPosting | null>;
  save(job: JobPosting): Promise<void>;
}

export interface Clock {
  now(): Date;
}
```

</File>

<File name="src/application/publishJob.ts">

```ts
import { publish, publishProblems, type JobProblem } from "../domain/job";
import type { Clock, JobRepository } from "./ports";

export type PublishResult =
  | { ok: true }
  | { ok: false; reason: "not-found" }
  | { ok: false; reason: "invalid"; problems: JobProblem[] };

export function makePublishJob(deps: { jobs: JobRepository; clock: Clock }) {
  return async function publishJob(id: string): Promise<PublishResult> {
    const job = await deps.jobs.getById(id);
    if (!job) return { ok: false, reason: "not-found" };

    const problems = publishProblems(job, deps.clock.now());
    if (problems.length > 0) return { ok: false, reason: "invalid", problems };

    await deps.jobs.save(publish(job));
    return { ok: true };
  };
}
```

</File>

دلوقتي كل الأسهم بتشاور **لجوه** تاني. ده اسمه **Dependency Inversion**: الطبقة اللي جوه بتحدد الـ interface، واللي بره بتلتزم بيه.

<Box type="story" icon="🔌" title="الفيشة والبريزة">

الـ use case هو **البريزة** على الحيطة: بتقول "أنا شكلي كده، ٢ رجل". أي جهاز (الـ adapter) عايز يشتغل يجيب فيشة على المقاس. البريزة متعرفش إذا كان اللي داخل خلاط ولا شاحن.

</Box>

## ليه `makePublishJob(deps)`؟

ده **dependency injection** بأبسط شكل: دالة بتاخد اللي محتاجاه وترجع الـ use case. من غير مكتبات ولا decorators. وتقدر تعمل نفس الحكاية بـ class فيها constructor، المهم الفكرة.

والمكسب في التيست:

<File name="src/application/publishJob.test.ts">

```ts
import { expect, it } from "vitest";
import { makePublishJob } from "./publishJob";
import { InMemoryJobRepository } from "../infrastructure/inMemoryJobRepository";

it("refuses to publish a job past its deadline", async () => {
  const jobs = new InMemoryJobRepository([
    { id: "j1", title: "QA", description: "x".repeat(60), salary: null,
      deadline: new Date("2026-01-01"), status: "draft" },
  ]);
  const publishJob = makePublishJob({ jobs, clock: { now: () => new Date("2026-02-01") } });

  expect(await publishJob("j1")).toEqual({ ok: false, reason: "invalid", problems: ["past-deadline"] });
});
```

</File>

مفيش `vi.mock`، ولا MSW، ولا متصفح. بتديله repository حقيقي بس في الذاكرة.

<Box type="tip" title="ليه رجعنا result مش throw؟">

الـ UI محتاج يعرض **كل** المشاكل جنب الحقول. `PublishResult` بيخلّي الحالات صريحة في الـ type، والـ TypeScript بيجبرك تتعامل معاها. الـ `throw` سيبه للحاجات اللي مش متوقعة، زي إن الشبكة وقعت.

</Box>
