## المكاسب

<Grid2>
<Card title="🧪 Testability" c={3}>

قواعد البيزنس والسيناريوهات بتتختبر كدوال عادية، من غير متصفح ولا mocks معقدة. التيستات بتبقى سريعة وبتفشل لأسباب حقيقية.

</Card>
<Card title="🔧 Maintainability" c={2}>

تغيير الـ API أو مكتبة الـ HTTP أو حتى الـ framework بيتحصر في طبقة واحدة، بدل ما تلف على كل الشاشات.

</Card>
</Grid2>

<Card title="📈 Scalability" c={4}>

الكود بيكبر من غير ما يتلخبط: كل حاجة ليها مكان معروف، وأي حد جديد في الفريق يعرف يدوّر فين. وفرق مختلفة تشتغل على الـ UI والـ adapters بالتوازي.

</Card>

## التمن

مفيش حاجة ببلاش:

| التمن | إمتى بيوجع |
| --- | --- |
| ملفات وطبقات أكتر | شاشة بسيطة بتعرض list من API |
| تحويل DTO لـ entity والعكس | الـ API والـ UI نفس الشكل تقريبًا |
| تعلّم الفريق للحدود | فريق صغير ومشروع قصير العمر |
| interfaces زيادة | لو مفيش غير implementation واحد ومفيش تيستات |

<Box type="story" icon="🧰" title="شنطة العدة">

مش هتجيب شنطة عدة كاملة عشان تعلّق برواز. بس لو بتبني شقة، من غيرها هتتعب كل يوم. الـ Clean Architecture للمشاريع اللي فيها **قواعد بيزنس حقيقية** وهتعيش سنين.

</Box>

## إمتى تستاهل؟

<Chips items={["قواعد بيزنس كتير ومعقدة (توظيف، فواتير، صلاحيات)", "نفس المنطق بيتستخدم في أكتر من شاشة", "الـ backend بيتغير أو لسه مش جاهز", "عايز تيستات سريعة ومحترمة", "المشروع هيعيش سنين وفريق بيتغير"]} />

ومش محتاجها في: landing page، أو dashboard بيعرض داتا من غير قواعد، أو prototype هيترمي بعد شهر.
