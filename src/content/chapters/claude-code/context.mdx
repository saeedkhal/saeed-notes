## تختار أنهي موديل؟

`/model` بيوريك الموديلات المتاحة وتبدّل بينها. أسامي الموديلات بتتغير مع الوقت، فمتحفظهاش. فكّر في نوع المهمة:

- **موديل سريع وعام**: للشغل اليومي، والتعديلات الصغيرة، والكود العادي.
- **موديل أقوى في الـ reasoning**: للـ architecture، والـ debugging الصعب، والـ refactor الكبير، أو لما كذا system بيشتغلوا مع بعض.

<Hl c="o">تغيير شكل كارت منتج مش محتاج أقوى موديل عندك. لكن إنك تقرر المخزون هيتصرف إزاي بين الداتابيز والمتجر والـ checkout، ده ممكن يحتاجه</Hl>.

## يعني إيه context window؟

ده كل اللي Claude شايفه في الجلسة دي: كلامكم مع بعض، والملفات اللي قراها، والـ output بتاع الترمينال، ونتايج الأدوات، وملف `CLAUDE.md`، وأي memory اتحمّلت. والـ context ده ليه حد أقصى.

<Box type="story" icon="🗂️" title="ترابيزة الشغل">

تخيّل الـ context ترابيزة شغل. كل ورقة بتحطها عليها بتاخد مكان، وبتشتت انتباهك. ورق مشكلة الـ login اللي خلصت امبارح مش هيساعدك وإنت بتصمم صفحة النهارده، هيزحم الترابيزة وبس.

</Box>

`/context` بيوريك إنت استهلكت قد إيه، ومقسّم على إيه. و `/context all` بيفصّل أكتر.

## الـ context rot

جودة Claude مش بتفضل ثابتة لحد ما الـ context يتملي وبعدين تقع مرة واحدة. هي بتقل بالتدريج ومن بدري. الكورس بيقول إن موديل الـ context window بتاعه 200 ألف token ممكن أداؤه يبدأ يقل بشكل واضح من حوالي 50 ألف، يعني وهو لسه في الربع الأول.

<Box type="warn" title="الرقم المكتوب على العلبة هو الحد الأقصى، مش الحد الآمن">

ماتستناش لحد ما الـ context يقرب يخلص. أول ما تبدأ شغلانة جديدة، ابدأها بـ context نضيف.

</Box>

## امتى تستخدم `/clear`؟

`/clear` بيفتحلك محادثة جديدة فاضية.

مثال: قعدت نص ساعة بتصلّح مشكلة في الـ auth. Claude قرا كود الـ auth، وشاف إيرورات، وجرّب كذا حل. بعد كده قلتله: "عيد تصميم كروت المنتجات". كل كلام الـ auth لسه في الـ context، ومش هيفيد الكروت في أي حاجة. هنا `/clear` مفيد.

بس مش لازم تعمله بعد كل مهمة. استخدمه لما تنقل لحاجة مالهاش علاقة باللي قبلها. وفيه كمان أمر اسمه `/compact`، هنشرحه في فصل لوحده.
