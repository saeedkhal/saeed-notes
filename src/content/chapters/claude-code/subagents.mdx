المتجر بقى شغال من ناحية العميل، بس لسه محدش يقدر يديره. مفيش مكان تضيف فيه منتج، أو تحدّث المخزون، أو تشوف الطلبات وتغيّر حالتها. محتاجين لوحة admin.

وقبل ما Claude يبني الـ admin، لازم يفهم حاجات كتير: الـ auth، والمنتجات، والـ schema، والمخزون، والطلبات، وشكل الـ UI الموجود. لو عمل كل البحث ده في المحادثة الرئيسية، كل الملفات اللي قراها وكل نتايج البحث هتملى نفس الـ context اللي هيبني بيه بعد كده.

<Hl c="g">الـ subagent هو agent تاني بياخد مهمة محددة، ويشتغل عليها في context لوحده، ويرجع للـ agent الرئيسي بالخلاصة بس</Hl>.

فايدته الحقيقية إنه بيفصل الـ context. هو مش أذكى من Claude العادي.

## متدّيلوش لقب

ناس كتير بتعمل subagents بأسامي زي "Senior Backend Engineer" أو "World-class React Expert". بس Claude مش هيعرف حاجة زيادة لمجرد إنك سميته كده.

السؤال الصح: إيه الشغل اللي ممكن يتعمل لوحده، والمحادثة الرئيسية مش محتاجة تشيل تفاصيله؟

## خمس تحقيقات في نفس الوقت

البرومبت في الكورس كان تقريبًا كده: قبل ما نبني الـ admin، استخدم subagents منفصلة، كل واحد يدرس حاجة:

1. المنتجات والـ categories والـ Drizzle data model.
2. المخزون وبيتصرف إزاي.
3. الـ auth، وإيه أأمن وأبسط طريقة نضيف بيها صلاحية admin.
4. الطلبات ودورة حياتها.
5. شكل الـ UI الموجود عشان نستخدمه تاني.

كل واحد يرجع بـ: الكود شغال إزاي دلوقتي، والملفات المهمة، والقيود، والطريقة اللي يقترحها. ومن غير ما ينفذ أي حاجة. وفي الآخر، اجمع كل النتايج في ملخص واحد.

Claude شغّل الخمسة في نفس الوقت. ده اسمه parallel fan-out، لأن ولا واحد فيهم محتاج يستنى نتيجة التاني عشان يبدأ. والـ agent الرئيسي بيستنى لحد ما يخلصوا كلهم، وبعدين يجمع اللي رجعوا بيه.

تقدر تشوف كل subagent شغال بقاله قد إيه وصرف كام token، وتدخل على أي واحد تشوف بيعمل إيه. الشغل ده كله خد 3 دقايق بدل حوالي 15 دقيقة.

وعدد الـ tokens اللي بتصرفها الـ subagents ممكن يبان كبير. بس لو agent واحد عمل نفس البحث، كان هيصرف أكتر وياخد وقت أطول.

## طب ليه منخليش Claude الرئيسي يقرا كل حاجة؟

تخيّل إن بحث المنتجات قرا 10 ملفات، والـ auth قرا 8، والطلبات 12، والـ UI 10. الـ agent الرئيسي محتاج كام استنتاج من كل واحد عشان يبني، مش محتاج الأربعين ملف.

الـ subagents بيخلّوا كل الرحلة دي تحصل في مكان تاني، والمحادثة الرئيسية تاخد النتيجة بس.

## الـ subagents الجاهزة

Claude Code فيه subagents جاهزة: **Explore** للبحث في الكود من غير تعديل، و **Plan** للـ research وقت التخطيط، و **general-purpose** للمهام العامة. وممكن تلاقي Claude بيستخدمهم لوحده.

وتقدر تطلب صراحة: "استخدم explore subagent يشوف صلاحية الـ admin هتدخل إزاي في الـ Better Auth الحالي". الأداة اللي ورا ده اسمها Agent، بس مش محتاج تناديها بنفسك. قول إيه اللي عايزه يتعمل في subagent، و Claude هيتصرف.

## بعد ما الملخص يرجع

متقولش على طول "اعمل admin dashboard". حدد الأول النسخة الأولى هيبقى فيها إيه:

- صلاحية admin بس.
- صفحة overview بسيطة.
- إدارة المنتجات والـ categories والطلبات.
- تحديث المخزون.

ومن غير: مستويات صلاحيات مختلفة، ولا كذا مخزن، ولا analytics، ولا دعوات للموظفين، ولا refunds. على الأقل دلوقتي.

<Box type="warn" title="إخفاء لينك الـ admin مش حماية">

التأكد من صلاحية الـ admin لازم يحصل على السيرفر. العميل العادي مينفعش يقدر يفتح صفحة admin بالـ URL، ولا ينادي admin action مباشرة. وده قرار تراجعه في الخطة قبل ما الكود يتكتب.

</Box>

وبعدين ابني feature ورا feature: صلاحية الـ admin الأول، بعدين المنتجات، بعدين المخزون، بعدين الطلبات.

وقبل ما تبدأ الـ admin، اعمل commit و push، واعمل security scan تاني. التطبيق دلوقتي بقى فيه auth، وبيانات عملاء، ودفع، فاتغير كتير من آخر scan.

حدّثه بإيدك، أو اطلب من Claude يحلل الكود ويحدّثه وإنت تراجع. أو استخدم skill زي sync، بتبص على آخر commits، وتحدّث `CLAUDE.md` و `AGENTS.md`، وتعلّم على أي حاجة مبقتش مطابقة للمشروع.
