لما تقفل Claude Code وترجعله بكرة، مش هيفتكر إنك بتستخدم pnpm، ولا إنك بتعرّف الـ schema بـ Drizzle، ولا الغلطة اللي صححتهاله مرتين قبل كده. ومش منطقي تعيد الكلام ده في كل جلسة.

<Hl c="b">CLAUDE.md ملف markdown بتكتب فيه تعليمات المشروع، و Claude بيقراه لوحده أول ما الجلسة تبدأ، قبل ما تكتب أول طلب</Hl>.

مثلًا: "استخدم pnpm مش npm"، و "استخدم Drizzle لأي حاجة في الداتابيز"، و "شغّل `pnpm typecheck` قبل ما تخلص أي تغيير كبير".

وفي النسخ الجديدة من Claude Code، لو مفيش `CLAUDE.md` في الفولدر، بيقرا `AGENTS.md`. ده الملف اللي باقي أدوات الـ AI بتستخدمه. فأي حاجة هنقولها عن `CLAUDE.md` تنطبق على `AGENTS.md` كمان.

## ده تعليمات، مش قفل

<Box type="warn" title="CLAUDE.md بيوجّه، مش بيمنع">

لو كتبت "متعدّلش ملفات الـ migration بإيدك"، Claude المفروض يلتزم. بس هو لسه يقدر يوصل للملفات دي. لو فيه حاجة لازم متحصلش أبدًا، ده شغل الـ permissions والـ sandboxing والـ hooks، مش شغل `CLAUDE.md`.

</Box>

## الملف بيتحط فين؟

مش مكان واحد. فيه كذا مستوى:

<Tree>

```text
~/.claude/CLAUDE.md          # تعليماتك الشخصية لكل المشاريع
project/CLAUDE.md            # تعليمات المشروع، وبتتعمل commit
project/AGENTS.md            # بيتقري لو مفيش CLAUDE.md
project/CLAUDE.local.md      # ليك إنت بس على المشروع ده، برا Git
project/apps/web/CLAUDE.md   # تعليمات لجزء معين من المشروع
```

</Tree>

- **الملف الشخصي**: حاجات عايز Claude يمشي عليها في كل مشاريعك.
- **ملف المشروع**: ده اللي هتستخدمه أكتر حاجة. بتحط فيه الـ stack، والأوامر، وقواعد الداتابيز، والتستات، وقواعد التصميم. ولأنه بيتعمله commit، كل اللي شغالين على المشروع بيدّوا Claude نفس التعليمات.
- **الملف الـ local**: ليك إنت بس، زي حساب تست أو sandbox URL خاص بيك. ده بيفضل برا Git.
- **ملفات جوه فولدرات**: في الـ monorepo أو المشروع الكبير، تقدر تحط `CLAUDE.md` جوه فولدر معين. Claude بيحمّل تعليمات الجزء ده بس لما يشتغل فيه.

Claude بيجمع التعليمات من كل المستويات دي مع بعض.

## وإيه هي الـ auto memory؟

Claude Code كمان عنده memory بيكتب فيها لوحده:

<Grid2>
<Card title="CLAUDE.md" c={5}>

اللي إنت قررت تقوله لـ Claude بنفسك. إنت اللي بتكتبه، وإنت اللي بتراجعه، وإنت اللي بتمسح منه اللي مبقاش صح.

</Card>
<Card title="Auto memory" c={2}>

اللي Claude اتعلمه وهو شغال معاك. زي مشكلة غريبة في الـ setup بتاعك، أو حاجة صححتهاله أكتر من مرة. كل مشروع ليه فولدر memory، والملف الأساسي فيه اسمه `MEMORY.md`.

</Card>
</Grid2>

`/memory` بيوريك الـ memory شغالة ولا لأ، وأنهي ملفات تعليمات اتحمّلت، وبيفتحلك فولدر الـ auto memory.

## خلّي الملف قصير

<Box type="warn" title="كل سطر بياكل من الـ context">

الملف بيتحمّل في كل جلسة، يعني كل سطر فيه بياخد من الـ context ومن انتباه Claude. متحطش حاجة لمجرد إنه "ممكن يحتاجها في يوم". حط اللي لازم يعرفه كل مرة يشتغل على المشروع.

النصيحة المشهورة إن الملف يبقى أقل من 200 سطر. بس الـ 200 دي حد أقصى مش هدف. لو كل الكلام المفيد طلع 30 أو 40 سطر، يبقى أحسن.

</Box>
