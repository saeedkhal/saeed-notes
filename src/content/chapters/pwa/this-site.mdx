## ٣ أنواع ملفات، ٣ قرارات

| النوع | الاستراتيجية | الصلاحية |
| --- | --- | --- |
| صفحات المذكرات (HTML) | Cache First **بصلاحية** | لحد أول deploy جديد، وبحد أقصى ٧ أيام |
| `_astro/` (CSS و JS والخطوط) | Cache First | مفيش، لأن الاسم فيه hash. وحد أقصى ٢٠٠ ملف |
| فهرس البحث والأيقونات | Stale-While-Revalidate | مفيش، بيتحدث في الخلفية كل مرة |

وقت الـ build، `src/pages/sw.js.ts` بيبدّل `__BUILD__` في الكود بالرقم ده. فكل deploy بيطلّع `sw.js` مختلف، والمتصفح بيلاحظ. وكل صفحة بتتحفظ بختم:

<File name="src/pwa/sw.js">

```js
async function stamp(res) {
  const headers = new Headers(res.headers);
  headers.set("x-sw-cached-at", String(Date.now()));
  headers.set("x-sw-build", BUILD);
  return new Response(await res.blob(), { status: res.status, statusText: res.statusText, headers });
}

function isFresh(res) {
  if (res.headers.get("x-sw-build") !== BUILD) return false; // من deploy قديم
  return Date.now() - Number(res.headers.get("x-sw-cached-at")) < PAGE_MAX_AGE;
}
```

</File>

<Box type="story" icon="🥛" title="ختم الزبادي">

كل علبة في التلاجة عليها رقم التشغيلة. المحل عارف رقم آخر تشغيلة. لو رقم العلبة أقدم، يجيب جديدة لو المصنع فاتح، ولو قافل يديك القديمة أحسن من مفيش.

</Box>

<Box type="warn" title="أول صفحة بعد الـ deploy لسه قديمة">

الـ SW الجديد بيتسطّب **في الخلفية** وإنت فاتح الصفحة الأولى، فالصفحة دي بتيجي من الكاش القديم. التحديث بيبان من الصفحة اللي بعدها. والموقع بيستخدم `ClientRouter` بتاع Astro (تنقل من غير reload)، فالمتصفح بيلاحظ `sw.js` الجديد لما تفتح الموقع أو تعمل refresh.

</Box>

## ليه `stamp` بيعمل Response جديد؟

لو السيرفر عمل redirect (مثلًا `/docker` ← `/docker/`)، الرد بيبقى `redirected: true`. المتصفح **بيرفض** يستخدم رد redirected كرد على navigation جاي من Service Worker. نسخ الـ body في `new Response(...)` بيعمل رد جديد نضيف، ومعاه بنحط الختم.
