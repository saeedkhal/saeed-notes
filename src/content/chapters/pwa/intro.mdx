## موقع بيتصرف زي تطبيق

الـ <En>Progressive Web App</En> مش framework ولا مكتبة. هو **موقع عادي** زوّدناه بحاجات بتخليه:

<Chips items={["يتسطّب على الـ home screen بأيقونة", "يفتح في شباك لوحده من غير شريط المتصفح", "يشتغل من غير نت أو بنت ضعيف", "يفتح أسرع لأن الحاجات محفوظة عنده"]} />

وكلمة **Progressive** معناها إن الموقع بيشتغل عادي في أي متصفح، واللي بيدعم المميزات دي بياخدها زيادة. مفيش حد بيتحرم من الموقع.

## الـ ٣ مكونات

<Grid2>
<Card title="🔒 HTTPS" c={1}>

الـ Service Worker بيقدر يغيّر أي رد راجع للصفحة، فالمتصفح مش بيسمح بيه غير على اتصال آمن. (`localhost` مستثنى عشان التطوير.)

</Card>
<Card title="📄 Manifest" c={2}>

ملف JSON فيه اسم التطبيق وأيقوناته ولونه وبيفتح إزاي. ده اللي بيخلّيه **يتسطّب**.

</Card>
</Grid2>

<Card title="⚙️ Service Worker" c={4}>

ملف JavaScript بيشتغل **في الخلفية**، منفصل عن الصفحة، وبيعدّي عليه كل request الصفحة بتعمله. ده اللي بيخلّي الموقع **يشتغل offline**.

</Card>

النقط اللي بتتحرك على الأسهم دي الـ requests والـ responses وهي ماشية. الصفحة **مش عارفة** الرد جه من التلاجة ولا من المطبخ. هي بس طلبت وجالها رد.

<Box type="warn" title="الـ Service Worker مش بيلمس الـ DOM">

بيشتغل في thread لوحده زي الـ Web Worker، فمفيش `document` ولا `window` جوّاه. بيتكلم مع الصفحة بالرسايل (`postMessage`)، وبيتحكم في الـ requests بس.

</Box>

## Cache Storage غير HTTP cache

المتصفح عنده أصلًا HTTP cache بيمشي على headers زي `Cache-Control`. الفرق:

| | HTTP cache | Cache Storage |
| --- | --- | --- |
| مين بيتحكم؟ | المتصفح، على حسب headers السيرفر | **إنت** بالكود جوه الـ Service Worker |
| بيتمسح إمتى؟ | المتصفح يقرر | لما إنت تمسحه (أو المساحة تخلص) |
| offline | مش مضمون | مضمون طول ما الملف محفوظ |
