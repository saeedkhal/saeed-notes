## بيمسك throw حصل جواه

`try/catch` بيمسك استثناء حصل **في نفس الشوط** جوه الـ `try`، أو `await` لـ promise اترفضت جواه. لو مسكته، العملية **متخرجش**. تطبع أو ترد على الطلب، وتكمّل.

```js
try {
  await Promise.reject(new Error("caught"));
} catch (e) {
  console.log("caught", e.message);
}
```

ده طبع `caught caught` وخرج بكود `0`.

`finally` بيشتغل في الحالتين: نجح الـ `try` أو وقع. ينفع تقفل ملف أو اتصال هناك، بس متبلعش الغلط جواه من غير ما ترجّعه.

## تلات حاجات مش هيشوفها

<Hl c="p">الـ catch مش شبكة حوالين العملية كلها. هو حوالين البلوك ده بس.</Hl>

- **Promise من غير `await` ومن غير `.catch`:** الـ `try` بيخلّص قبل ما الرفض يحصل. التجربة طلعت `Error: missed` والكود `1`، وجملة `caught` متطبتش.
- **`setTimeout` أو `setImmediate`:** الـ callback بييجي بعدين، بره الـ `try`. التجربة طلعت `Error: later` والكود `1`.
- **`SyntaxError` في نفس الملف:** الملف متركّبش أصلاً، فالسطر اللي فيه `try` منفّذش. غلط التركيب في `syn.js` خرج بكود `1`.

```js
try {
  Promise.reject(new Error("missed"));
} catch (e) {
  console.log("caught");
}
```

```js
try {
  setTimeout(() => {
    throw new Error("later");
  }, 10);
} catch (e) {
  console.log("caught");
}
```

الصح في الوعد: `await` جوه `try`، أو `.catch` على نفس الـ promise. الصح في المؤقت: `try` **جوه** الـ callback، مش برّاه.

دالة `async` لو عملت `throw` من غير ما حد يعمل لها `await`، الرفض يبقى unhandled. الـ `try` اللي حوالي استدعاء من غير `await` مش هينفع.
