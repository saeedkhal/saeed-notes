## الأمر بيشغّل عملية وبيستناها تخلّص

`node index.js` (وعلى بعض أجهزة Linux نفس البرنامج اسمه `nodejs`) بيفتح **عملية**. Node يقرا الملف، ينفّذ السكربت، ويستنى الـ event loop. لما مفيش شغل مستني، العملية **تخرج** وترجّع رقم للشل. الرقم ده الـ exit code.

اتجرّب:

```bash
node -e 'console.log("done")'
echo $?
```

الناتج `done` وبعدين `0`.

<Hl c="y">كود 0 يعني العملية خلّصت من غير فشل. مش معناه إن فيه crash، ومش معناه إن التطبيق "وقف بالغلط".</Hl>

لو الملف فيه `throw`، نفس التجربة رجّعت `1`، وNode طبع الـ stack. كود غير صفر يعني اللي شغّل الأمر (شل، أو CI، أو Docker، أو PM2) يعتبر التشغيل فاشل.

## ليه ساعات بيخرج لوحده

السكربت خلّص آخر سطر، ومفيش حاجة ماسكة العملية:

- **مفيش** `server.listen`.
- **مفيش** `setInterval` لسه شغّال.
- **مفيش** اتصال أو مؤقت مستني.

قبل الخروج Node بينادي `beforeExit` وبعدين `exit`. الاتنين اتطبعوا بالكود `0` لما السكربت فاضي.

```js
process.on("beforeExit", (code) => console.log("beforeExit", code));
process.on("exit", (code) => console.log("exit", code));
```

في `beforeExit` لسه تقدر تبدأ مؤقت أو تفتح سيرفر، فالعملية تفضل. في `exit` متقدرش تعمل شغل async. العملية خلاص بتخرج.

## ليه السيرفر مش بيخرج

`listen` بيحط مقبض مفتوح في الـ event loop. Node مستني اتصالات، فمش بيخرج. لما تقفل السيرفر ومفيش حاجة تانية، يخرج بكود `0`. ده قفل مرتب، مش سقوط.

| اللي بتشوفه | المعنى |
| --- | --- |
| رجع للشل والكود `0` | خلّص الشغل ومفيش مقبض مفتوح |
| رجع والكود `1` | غلط متتمسكش، أو `SyntaxError`، أو rejection من غير `catch` |
| فضل واقف ومفيش prompt | فيه سيرفر أو مؤقت أو اتصال لسه مفتوح |
| `130` | العملية اتخضت بـ Ctrl+C (`SIGINT`) |
| `143` | جالها `SIGTERM`، زي إيقاف من Docker أو systemd |

قاعدة الإشارة: `128` زائد رقم الإشارة. `SIGINT` رقمه 2 فالكود 130، و`SIGTERM` رقمه 15 فالكود 143. الاتنين اتقاسوا. `SIGKILL` متتمسكش من جوه Node، والكود الشائع ليها 137.
