## ٩ أنماط، ٣ عائلات

الأنماط شكلها مختلف، بس السؤال اللي بيفرّقهم واحد: <Hl c="y">إيه اللي بيحصل لما المستخدم يعمل scroll؟</Hl>

| العائلة | إيه اللي بيحصل | الأنماط | الأداة |
| --- | --- | --- | --- |
| **Layout** | العنصر بيتصرّف بشكل خاص وهو بيتحرك | Sticky، Scroll snap | CSS بس |
| **Triggered** | حاجة **بتحصل مرة** لما عنصر يدخل الشاشة | Fade on enter، Infinite scroll، Scrollytelling | `IntersectionObserver` |
| **Driven** | قيمة **ماشية مع كل بيكسل** scroll | Progress bar، Zoom، Parallax، Horizontal | CSS scroll-driven animations |

## الفرق بين Triggered و Driven

ده أكتر لبس بيحصل، فخليه في دماغك:

<Grid2>
<Card title="🔔 Triggered" c={3}>

زي **جرس الباب**: بيرن مرة لما حد يعدّي. العنصر بيدخل، الـ animation بتشتغل لآخرها بسرعتها هي، حتى لو المستخدم وقف.

</Card>
<Card title="🎚️ Driven" c={4}>

زي **مفتاح الصوت**: كل ما تلف أكتر، الصوت يعلى. الـ animation مربوطة بمكان الـ scroll، تقف لما تقف وترجع لما ترجع.

</Card>
</Grid2>

## ٣ قواعد لكل الأنماط

<Box type="warn" title="١. متسمعش لـ scroll event عشان شغل تقيل">

`window.addEventListener("scroll", ...)` بيضرب عشرات المرات في الثانية على الـ main thread. لو بتحسب layout جوّاه (`getBoundingClientRect`) هتلاقي الصفحة بتقطّع. البديل: `IntersectionObserver` للـ triggered، و scroll-driven animations للـ driven، والاتنين المتصفح بيعملهم بكفاءة أعلى.

</Box>

<Box type="tip" title="٢. حرّك transform و opacity بس">

الخاصيتين دول المتصفح يقدر يحرّكهم على الـ compositor من غير ما يعيد حساب الـ layout. تحريك `top` أو `height` أو `width` مع الـ scroll وصفة للتقطيع.

</Box>

<Box type="idea" title="٣. احترم prefers-reduced-motion">

ناس كتير بيجيلها دوخة من الحركة الكتير، وبيفعّلوا "تقليل الحركة" في الجهاز. كل ديمو في المذكرة دي بيوقف الحركة لو الإعداد ده شغال، واعمل نفس الحكاية في شغلك:

```css
@media (prefers-reduced-motion: reduce) {
  .reveal, .parallax-layer { animation: none; transition: none; }
}
```

</Box>
