## SuperTest وMSW في نفس backend؟

آه، لأنهم على ناحيتين مختلفتين:

<Flow items={[
  { t: "SuperTest", s: "يبعت request للـ app", c: 5 },
  "→",
  { t: "Your API", s: "route + service", c: 2 },
  "→",
  { t: "MSW", s: "يعترض outbound HTTP", c: 3 },
  "→",
  { t: "Payment API", s: "مش هنتصل بيها", c: 1 },
]} />

مثال: تختبر `POST /checkout` بـ SuperTest، والـ route جوه التطبيق تحاول تكلم payment provider. MSW يعترض اتصال الـ provider ويرجع success أو timeout.

## إمتى الأداة تبقى زيادة؟

- Chai مع Jest/Vitest: غالبًا تكرار لأن `expect` موجودة.
- Sinon مع Jest/Vitest: غالبًا تكرار لأن `jest` و`vi` عندهم spies/mocks/timers.
- SuperTest لاختبار دالة pure: مستوى HTTP زيادة بلا فايدة.
- MSW لدالة واخدة callback واضح: fake function أبسط.
- Jest وVitest سوا في نفس package: migration مؤقتة، مش نهاية مريحة.

<Box type="interview" title="إجابة سؤال المقابلة">

«Mocha وJest وVitest runners، لكن Jest وVitest frameworks أكمل. Chai assertions، وSinon test doubles. SuperTest يختبر Node HTTP app من ناحية الـ inbound request، بينما MSW يعترض outbound network في Node أو browser. باختار أداة واحدة لكل دور إلا لو عندي boundary مختلفة بوضوح.»

</Box>

## متبدأش بالـ mocks

ابدأ باختبار behavior حقيقي. لما تلاقي boundary بطيئة أو غير مستقرة أو مكلفة — database، email، payment، clock — اختار أضيق double يحلها.
