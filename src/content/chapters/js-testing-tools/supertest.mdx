## مش بيقلّد API خارجية

SuperTest بيبعت HTTP request للـ Node app أو server **بتاعك**، وبعدين يؤكد status وheaders وbody. لما تمرّر Express app، يقدر يربطه على port مؤقت، فمش محتاج تشغّل server منفصل.

<Hl c="o">SuperTest يختبر السيرفر اللي أنت كاتبه. MSW يعترض الطلب اللي كودك بيبعته لسيرفر تاني.</Hl>

## افصل app عن listen

<File name="app.js">

```js
import express from "express";

export const app = express();
app.use(express.json());

app.post("/users", (req, res) => {
  res.status(201).json({ id: 7, name: req.body.name });
});
```

</File>

<File name="server.js">

```js
import { app } from "./app.js";

app.listen(3000);
```

</File>

الفصل ده يخلي test تستورد `app` من غير ما تفتح port ثابت.

## مع Vitest

```bash
pnpm add -D supertest @types/supertest
```

<File name="users.test.js">

```js
import request from "supertest";
import { describe, expect, it } from "vitest";
import { app } from "../src/app.js";

describe("POST /users", () => {
  it("ينشئ مستخدم", async () => {
    const response = await request(app)
      .post("/users")
      .send({ name: "سعيد" })
      .expect("Content-Type", /json/)
      .expect(201);

    expect(response.body).toEqual({ id: 7, name: "سعيد" });
  });
});
```

</File>

SuperTest نفسه framework-agnostic؛ نفس request ينفع جوه Mocha أو Jest.

## إيه اللي الاختبار ده بيثبته؟

بيعدّي على routing وbody parser والـ middleware والـ controller وتحويل response لـ HTTP. ده أقرب لـ integration test، حتى لو قاعدة البيانات fake.

مبيثبتش إن frontend عرف يتعامل مع الرد، ولا إن API خارجية شغالة، ولا إنه E2E كامل بمتصفح.

## Session وcookies

لو السيناريو محتاج يحتفظ بالـ cookies بين requests، استخدم agent:

```js
const agent = request.agent(app);

await agent.post("/login").send({ email, password }).expect(204);
await agent.get("/me").expect(200);
```

<Box type="warn" title="متنساش dependencies الحقيقية">

لو route بتكلم database أو queue حقيقية، الاختبار ممكن يبقى بطيء أو يبوّظ بيانات. استخدم test database مع reset واضح، أو حقن adapter بديل حسب مستوى الثقة المطلوب.

</Box>
