## ابدأ بنوع الحاجة

Database لها transactions وschema، الملفات لها paths وpermissions، والـ legacy app ممكن يحتاج share محلي. مفيش أداة واحدة تنقل كل حاجة.

<Box type="story" title="نقل ملفات الطلبة">

درجات الطلبة في database غير صور الشهادات في file server. وشركة التصوير اللي تبعت كل يوم بـ SFTP غير أرشيف ضخم هيتشحن مرة واحدة. الاسم الصح يطلع من نوع النقل.

</Box>

## AWS DMS: حرّك بيانات الـ database

`AWS Database Migration Service (DMS)` ينقل ويكرر data بين databases ومخازن مدعومة. يقدر يعمل one-time migration ويكمل `change data capture (CDC)` لتقليل downtime.

- **Homogeneous**: نفس engine تقريبًا، زي PostgreSQL إلى RDS for PostgreSQL.
- **Heterogeneous**: engine مختلف، زي Oracle إلى Aurora PostgreSQL؛ هنا schema conversion مهم.

<Hl c="b">DMS ينقل الـ data؛ تحويل schema والكود مهمة منفصلة حتى لو تحت نفس عيلة DMS.</Hl>

## DMS Schema Conversion وSCT

`DMS Schema Conversion` خدمة managed على الويب تحول tables وviews وprocedures لصيغة target متوافقة، وتطلع assessment للحاجات اللي محتاجة تعديل يدوي.

هي مبنية على conversion engine بتاع `AWS Schema Conversion Tool (SCT)`. في سيناريو جديد، راجع DMS Schema Conversion أولًا؛ مواد CLF-C02 القديمة ممكن تسأل عن SCT كتطبيق يحول schema.

<Box type="warn" title="التحويل مش سحر">

اختلافات engines ممكن تحتاج تعديل يدوي واختبارات. متحوّلش production database من غير backup، validation، وخطة رجوع.

</Box>

## DataSync: ملفات وobjects أونلاين

`AWS DataSync` يحرك file وobject data أونلاين بين on-premises وAWS، وبين storage services مدعومة. بيهتم بالجدولة والتشفير والتحقق من سلامة النقل وإعادة المحاولة.

اختاره لنقل NFS/SMB أو object storage إلى خدمات زي S3 وEFS وFSx، سواء مرة أو بصورة دورية. هو مش database replication engine.

## Transfer Family: بروتوكول الشريك

`AWS Transfer Family` يوفر endpoints مُدارة لبروتوكولات file transfer زي `SFTP` و`FTPS` و`FTP`، والملفات تروح لـ S3 أو EFS.

لو مورد خارجي عنده برنامج قديم بيبعت SFTP كل ليلة ومش عايز تغيّره: Transfer Family. لو أنت بتعمل bulk copy مُحسن بين storage systems: DataSync.

## Storage Gateway: باب هجين مستمر

`AWS Storage Gateway` يدي تطبيقات on-premises وصول هجين لـ AWS storage بواجهات مألوفة:

- `S3 File Gateway`: file shares وتخزين objects في S3.
- `FSx File Gateway`: وصول محلي لـ FSx for Windows File Server.
- `Volume Gateway`: block storage مع snapshots في AWS.
- `Tape Gateway`: virtual tapes للأرشفة والـ backup.

ده integration مستمر مع cache محلي، مش مجرد مشروع copy وينتهي.

## Snow Family: المعلومة التاريخية والحالية

`AWS Snowball Edge` كان جهاز تشحنه لنقل كمية ضخمة أو تشغيل edge compute لما الشبكة ضعيفة. `Snowcone` أصغر، و`Snowmobile` كان لنقل هائل جدًا.

لكن في **أكتوبر ٢٠٢٦**، Snow Family لم يعد متاحًا لعملاء commercial جدد، ودعم Snowball في الـ commercial Regions مقرر ينتهي **٣١ ديسمبر ٢٠٢٦**؛ العملاء الحاليون وGovCloud لهم تفاصيل مختلفة.

<Box type="tip" title="البديل الحالي">

للنقل physical الجديد، AWS بتوجّه إلى `AWS Data Transfer Terminal` وحلول partners حسب البلد والسعة. الامتحان الحالي المنشور قد يفضل يسأل Snow Family، فاعرف الغرض مع caveat الزمن.

</Box>
