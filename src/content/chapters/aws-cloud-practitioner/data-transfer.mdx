## 🧠 افهم: الداتا تقيلة

خطة نقل «الأمانة» من الفصل اللي فات فيها ٣ أنواع داتا:

1. **database Oracle** فيها ١٠ سنين حسابات، وبتتكتب كل ثانية. مينفعش نقفل السوبر ماركت يومين عشان ننقلها.
2. **٥٠ TB ملفات** (صور، فواتير ممسوحة) على file server.
3. **موردين** بيبعتوا ملفات أسعار كل يوم بـ **SFTP**، ومش هيغيّروا طريقتهم.

كل نوع ليه أداة. والسؤال الأول دايمًا: **هل الشبكة تكفي؟**

<Hl c="b">DMS بينقل databases وهي شغالة. DataSync بينقل ملفات على الشبكة بسرعة. Transfer Family بيستقبل SFTP/FTP ويحط في S3. ولو الشبكة مش كفاية، النقل بيبقى offline بأجهزة.</Hl>

<Box type="story" icon="🚛" title="نقل محل وهو فاتح">

- **DMS** = إنك تنقل البضاعة للمحل الجديد **والمحل القديم لسه بيبيع**: تنقل الأساس الأول، وكل حاجة بتتباع أو تتضاف بتتسجل وتتنقل وراها، ولما الاتنين يبقوا متطابقين تقفل القديم في دقايق.
- **DataSync** = **عربية نقل** سريعة ومنظمة بتنقل الكراتين على الطريق وتتأكد إن كل كرتونة وصلت سليمة.
- **Snow / الأجهزة** = لما البضاعة كتيرة جدًا والطريق ضيق، **تملا شاحنة** وتبعتها بدل ألف مشوار.

</Box>

1. **حوّل الـ schema:** الجداول والـ procedures من Oracle لـ PostgreSQL (DMS Schema Conversion أو SCT). ده بس لو الـ engine هيتغير.
2. **Full load:** DMS ينسخ كل الصفوف الموجودة.
3. **CDC (Change Data Capture):** DMS يفضل ينقل كل insert وupdate بيحصل في القديمة وهي شغالة.
4. **Cutover:** لما الاتنين متطابقين، توجّه التطبيق للجديدة. الـ downtime دقايق.

## 🔍 من جوه: كل أداة

### AWS DMS (Database Migration Service)

- بينقل داتا بين databases (و S3 وغيرها) **والـ source شغالة**.
- **Homogeneous** (MySQL ← MySQL): DMS لوحده (أو أدوات الـ engine نفسه).
- **Heterogeneous** (Oracle ← PostgreSQL): محتاج تحويل الـ schema الأول بـ **DMS Schema Conversion** (أو **AWS SCT**، الأداة الأقدم اللي ممكن تظهر في الأسئلة).
- ممكن يفضل شغال للـ **replication المستمر** مش للهجرة بس.

### AWS DataSync

- نقل **ملفات online** من NFS/SMB/HDFS/object storage لـ S3 أو EFS أو FSx (وبين خدمات AWS).
- أسرع بكتير من scripts بإيدك، بيتحقق من سلامة الملفات، وبيجدول، وبيشفّر.
- محتاج **agent** في الـ data center للمصادر اللي عندك.

### AWS Transfer Family

server مُدار لـ **SFTP وFTPS وFTP وAS2**، والملفات بتتحفظ في **S3 أو EFS**. الموردين بيكملوا بنفس طريقتهم، وإنت مش بتدير سيرفر.

### النقل offline

**AWS Snow Family** (Snowball Edge) كانت الأجهزة اللي AWS بتبعتهالك تملاها وترجّعها. **انتبه:** Snow Family **مش متاحة لعملاء commercial جدد**، ودعم Snowball في الـ commercial Regions مقرر ينتهي **٣١ ديسمبر ٢٠٢٦**. البديل الحالي **AWS Data Transfer Terminal** (أماكن فعلية تروح لها بأجهزتك وترفع بسرعة عالية) وحلول الشركاء. الامتحان ممكن يسأل عن Snow Family بالاسم، فاعرف **فكرتها**: «داتا ضخمة + شبكة ضعيفة أو مفيش = جهاز».

### والـ hybrid الدائم؟

لو مش «نقل مرة واحدة» لكن برامج محلية لازم تفضل تكتب على AWS: **Storage Gateway** (فصل ١٨).

## 🛠️ طبّق: خطة نقل داتا «الأمانة»

الـ Lab ورقي. الشركة عندها خط **200 Mbps**.

| الداتا | الأداة | السبب |
| --- | --- | --- |
| Oracle حسابات ← Aurora PostgreSQL | **DMS Schema Conversion** ثم **DMS** (full load + CDC) | engine مختلف، والسوبر ماركت مش هيقفل |
| MySQL الموقع ← RDS MySQL | **DMS** (أو native dump/replication) | نفس الـ engine |
| ٥٠ TB صور وفواتير | **DataSync** على أكتر من أسبوع، أو **Data Transfer Terminal** لو مستعجلين | احسب: 50 TB على 200 Mbps ≈ ٢٣ يوم في أحسن الأحوال |
| ملفات أسعار من الموردين بـ SFTP | **Transfer Family** ← S3 | الموردين مش هيغيروا |
| برنامج backup قديم لازم يكمل | **Storage Gateway** (Tape) | hybrid دائم مش نقل |

**احسب بنفسك:** 50 TB = 400,000,000 Mb. على 200 Mbps = 2,000,000 ثانية ≈ **٢٣ يوم** لو الخط فاضي للنقل بس. هل الشركة تستحمل ده؟ لو لأ، حل offline.

## ⚖️ قارن: اختار من نوع الداتا وطريقتها

| | DMS | DataSync | Transfer Family | Storage Gateway | Data Transfer Terminal / Snow |
| --- | --- | --- | --- | --- | --- |
| بينقل | **databases** | **ملفات** | ملفات من شركاء | ملفات/volumes/tapes | أحجام ضخمة |
| online؟ | أيوه | أيوه | أيوه | أيوه | **offline / فعلي** |
| مرة ولا دايم؟ | الاتنين (CDC) | مرة أو مجدول | دايم | **دايم (hybrid)** | مرة |
| protocol | database engines | NFS، SMB، HDFS، S3 | SFTP، FTPS، FTP، AS2 | NFS، SMB، iSCSI | أجهزة |

<Box type="interview" title="كلمات بتحسم">

«migrate database with minimal downtime» ← **DMS**. «different database engine» ← **Schema Conversion / SCT** + DMS.
«move files online quickly from on-premises NFS/SMB» ← **DataSync**.
«SFTP into S3» ← **Transfer Family**.
«petabytes»، «limited bandwidth»، «offline» ← **Snow Family** (فكرة تاريخية) / Data Transfer Terminal.

</Box>
