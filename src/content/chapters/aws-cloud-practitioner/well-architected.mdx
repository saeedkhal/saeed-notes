## سيناريو مراجعة قبل موسم البيع

منصة e-commerce داخلة على موسم يمثل `35%` من مبيعات السنة. آخر incident استمر `42 دقيقة`، مفيش restore test من ٨ شهور، والـ compute شغالة على سعة الذروة طول الوقت. بدل سؤال «الـ architecture كويسة؟» الفريق عمل review بأدلة.

AWS Well-Architected Framework مجموعة مبادئ وأسئلة لمراجعة workload. مش شهادة جودة، ومش قالب واحد، ومش خدمة تصلح التصميم تلقائيًا.

## Timeline للمراجعة

1. **09:00:** يتحدد scope: checkout والـ database والـ deployment path.
2. **10:00:** كل ركن يتراجع بدليل: metrics، policies، incident report، restore result، وcost data.
3. **13:00:** الفريق يسجل المخاطر حسب أثرها واحتمالها، مش حسب سهولة النقاش.
4. **15:00:** أعلى ٣ إجراءات: تفعيل MFA، اختبار restore، وإضافة deployment rollback.
5. **بعد أسبوعين:** يعاد القياس؛ إغلاق finding يحتاج دليل، مش وعد.

النجاح إن المخاطر بقت معروفة ولها owner وdeadline ودليل تحقق. الفشل إن المراجعة تتحول checklist شكلية أو محاولة تعظيم ركن واحد على حساب الباقي.

## Tradeoff مش إجابة غلط

تشغيل checkout في أكتر من AZ يحسن reliability، لكنه يزيد موارد وتشغيل. ضغط صور المنتجات يقلل نقل البيانات ويحسن الأداء والتكلفة والاستدامة، لكنه يستهلك compute أثناء المعالجة.

<Hl c="o">القرار الصح هو اللي يحقق احتياج العمل بمخاطر معروفة، مش اللي يكسب ركنًا واحدًا بأقصى درجة.</Hl>

<Box type="story" icon="📋" title="أسئلة الـ review">

مين يتصرف وقت incident؟ مين يقدر يغيّر بيانات الدفع؟ آخر restore نجح إمتى؟ الـ p95 latency وقت الذروة كام؟ تكلفة كل `1,000 orders` كام؟ وإيه السعة الفاضية؟ دي أسئلة قابلة للإثبات عبر الأركان الستة.

</Box>

## أدوات تساعد، والقرار عندك

AWS Well-Architected Tool يقدر يسجل المراجعات والمخاطر وخطة التحسين. استخدامه مش معناه إن AWS صادقت على النظام، ومش بديل عن فهم سياق العمل.

## قارن بين الركن والدليل

- **Security:** policy وMFA ونتيجة فحص، مش «الوصول مقفول».
- **Reliability:** restore test وfailure test، مش مجرد وجود backup.
- **Performance Efficiency:** latency وthroughput تحت حمل معروف.
- **Cost Optimization:** تكلفة مرتبطة بوحدة عمل، مش فاتورة إجمالية بس.
- **Operational Excellence:** runbook وrollback وpost-incident actions.
- **Sustainability:** utilization وموارد أقل لكل request مع تحقيق باقي المتطلبات.
