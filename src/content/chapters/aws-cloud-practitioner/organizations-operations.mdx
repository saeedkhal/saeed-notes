## Enterprise عندها 60 account

الشركة قسمت البيئة إلى `Security`, `Infrastructure`, `Production`, و`Sandbox` OUs. قبل product launch اكتشفوا إن فريق sandbox أنشأ موارد في Region غير معتمدة، وproduction قربت من EC2 quota.

1. `AWS Organizations` جمع الحسابات والـ billing.
2. SCP على Sandbox منع Regions غير المعتمدة.
3. IAM role داخل account سمح للمطور بـ EC2، لكن الـ SCP منع action خارج النطاق.
4. `Control Tower` وفّر landing zone وcontrols وaccount provisioning.
5. `Service Quotas` كشف إن الحد 500 instance والفريق محتاج 650.
6. `Systems Manager` نفّذ patch wave على 300 node بدل SSH يدوي.
7. `AWS Health` نبّه عن maintenance لمورد محدد.

## Organizations وSCP

`Organizations` تدير accounts وOUs وسياسات وconsolidated billing. الـ `SCP` يحدد أقصى permissions المتاحة؛ **لا يمنح permission**.

مثال: IAM يسمح `s3:GetObject`، والـ SCP لا تمنعه → ممكن يسمح لو مفيش deny تاني. IAM لا يسمح، حتى لو SCP واسعة → الطلب يفشل. SCP فيها explicit deny → الطلب يفشل مهما كان IAM allow.

فصل accounts يقلل blast radius، لكن يزيد احتياج automation وcentral logging. استخدم management account للحوكمة قدر الإمكان، مش workloads يومية.

## Control Tower

`AWS Control Tower` يبني landing zone فوق Organizations وخدمات أخرى، ويقدم controls وAccount Factory. مناسب لما enterprise عايزة baseline متكرر بدل إنشاء كل account يدويًا.

هو مش بديل لـ Organizations. Control prevent أو detect يختلف تأثيره؛ اختبر قبل تطبيق control واسع عشان متقفلش deployment path حرج.

## Systems Manager

`Systems Manager` يدير fleet operations: inventory، patching، automation، Run Command، Session Manager وParameter Store.

Timeline patch:

1. 22:00 patch 10 canary nodes.
2. 22:15 راقب errors وCPU.
3. 22:30 patch 20% من fleet.
4. 23:00 كمل waves لو health checks ناجحة.
5. لو error rate عدى 2%، وقف automation وابدأ rollback.

Session Manager يقلل فتح SSH inbound، لكنه محتاج IAM وagent/connectivity مضبوطين. Systems Manager مش بديل لـ CloudWatch monitoring.

## Health وTrusted Advisor وQuotas

- `AWS Health`: events شخصية تخص مواردك؛ maintenance الساعة 02:00 مثلًا.
- `Trusted Advisor`: checks وتوصيات في cost وsecurity وperformance وfault tolerance وlimits؛ التغطية حسب support plan.
- `Service Quotas`: تشوف quota وتطلب زيادة للـ adjustable quota.

CPU 95% بسبب code → CloudWatch. AWS maintenance على RDS → Health. recommendation عن idle resource → Trusted Advisor. محتاج 650 instance والحد 500 → Service Quotas.

طلب quota increase مش فوري ولا مضمون؛ قدم قبل launch بأيام أو أسابيع، واعمل load test وخطة degraded mode.
