## 🧠 افهم: حساب واحد مبقاش كفاية

دُكّان كبر وبقى عنده فريق تطوير وفريق بيانات. وكلهم شغالين في **حساب AWS واحد**. النتيجة:

- مطور مسح database الـ production وهو فاكرها test.
- مش عارفين فاتورة التجارب قد إيه وفاتورة الـ production قد إيه.
- كل بيئة جديدة بتتعمل بالإيد في الـ console، ومحدش فاكر عمل إيه.

الحل: **حسابات منفصلة** لكل بيئة (dev، staging، prod)، و**مكان واحد** يحط عليهم قواعد ويجمع فواتيرهم، و**كود** بيبني البنية بدل الضغط بالماوس.

<Hl c="b">Organizations = شجرة حسابات بفاتورة واحدة وقواعد (SCPs). Control Tower = بيجهّز الشجرة دي بأفضل الممارسات. CloudFormation = البنية مكتوبة كود. Systems Manager = إدارة السيرفرات من مكان واحد.</Hl>

<Box type="story" icon="🏢" title="شركة بفروع">

- **Organizations** = **الشركة الأم** وتحتها فروع (حسابات). الفاتورة بتتجمع في الإدارة.
- **SCPs** = **لايحة الشركة**: «ممنوع أي فرع يفتح في بلد برّه القايمة». حتى مدير الفرع ميقدرش يكسرها.
- **Control Tower** = **مكتب الاستشارات** اللي بيفتحلك الفروع جاهزة بالأمن والكاميرات واللوايح.
- **CloudFormation** = **الرسم الهندسي** للفرع: تديه لأي مقاول يبني نفس الفرع بالظبط.
- **Systems Manager** = **إدارة الصيانة** اللي بتبعت فني لكل الفروع من غير ما المدير يروح بنفسه.

</Box>

## 🔍 من جوه: الأدوات

### AWS Organizations

- **OUs (Organizational Units):** فولدرات بتجمع حسابات.
- **SCPs (Service Control Policies):** بتحدد **أقصى** صلاحيات ممكنة في الحسابات. **مبتدّيش صلاحيات**، بتحط سقف. حتى الـ root في الحساب العضو مايقدرش يعدّيها.
- **Consolidated billing:** فاتورة واحدة، والاستخدام بيتجمع فممكن تستفيد من خصومات الحجم والـ Savings Plans بين الحسابات.

### AWS Control Tower

بيعمل **landing zone**: Organization جاهزة بحسابات أساسية (log archive وaudit)، و**controls** (guardrails) وقائية وكاشفة، و**Account Factory** لإنشاء حسابات جديدة بنفس المعايير.

### Infrastructure as Code: CloudFormation وCDK

- **AWS CloudFormation:** بتكتب البنية في **template** (YAML/JSON)، وCloudFormation بيعمل **stack** بالموارد كلها بالترتيب الصح، ولو حاجة فشلت بيرجع (rollback). تكرّر نفس البيئة في أي حساب أو Region.
- **AWS CDK:** تكتب البنية بلغة برمجة (TypeScript، Python…) وبتتحول لـ CloudFormation.

### AWS Systems Manager

مجموعة أدوات لإدارة السيرفرات (EC2 وon-prem):

- **Session Manager:** shell على السيرفر من غير SSH ولا port 22، ومتسجل.
- **Patch Manager:** patches أوتوماتيك بجدول.
- **Run Command:** نفّذ أمر على ١٠٠ سيرفر مرة واحدة.
- **Parameter Store:** إعدادات وأسرار (فصل ٣٠).

### أدوات تانية تتسأل

- **AWS Trusted Advisor:** بيفحص الحساب ويدّي توصيات في: **cost optimization، performance، security، fault tolerance، service limits، وoperational excellence**. الفحوصات الكاملة حسب خطة الدعم.
- **Service Quotas:** بيوريك حدود الخدمات (مثلًا عدد vCPUs المسموح) ويطلب زيادتها.
- **AWS Service Catalog:** كتالوج منتجات معتمدة (templates) الموظفين يطلّعوا منه بس.
- **AWS License Manager:** يتابع الـ licenses (Windows، Oracle) ويمنع تخطي العدد.
- **AWS RAM (Resource Access Manager):** تشارك موارد (subnets مثلًا) بين حسابات.

## 🛠️ طبّق: bucket من كود

⚠️ CloudFormation نفسه مجاني، بتدفع على الموارد اللي بيعملها. الـ bucket الفاضي مش بيكلف تقريبًا.

1. **اكتب template:**

<File name="dukkan-bucket.yaml">

```yaml
AWSTemplateFormatVersion: "2010-09-09"
Description: bucket صور دُكّان بإعدادات آمنة
Resources:
  ImagesBucket:
    Type: AWS::S3::Bucket
    Properties:
      VersioningConfiguration:
        Status: Enabled
      PublicAccessBlockConfiguration:
        BlockPublicAcls: true
        BlockPublicPolicy: true
        IgnorePublicAcls: true
        RestrictPublicBuckets: true
      Tags:
        - Key: Project
          Value: dukkan-lab
Outputs:
  BucketName:
    Value: !Ref ImagesBucket
```

</File>

2. **اعمل الـ stack:**

```bash
aws cloudformation deploy --template-file dukkan-bucket.yaml --stack-name dukkan-images
aws cloudformation describe-stacks --stack-name dukkan-images --query "Stacks[0].Outputs"
```

**المتوقع:** bucket باسم متولّد، فيه versioning وBlock Public Access من غير ما تضغط حاجة.

3. **جرّب التكرار:** شغّل نفس الأمر بـ `--stack-name dukkan-images-staging`. بيئة تانية بنفس الإعدادات بالظبط. ده هدف IaC.
4. **اقرا Trusted Advisor:** `Trusted Advisor` ← `Recommendations`. **المتوقع:** فحوصات أساسية زي MFA على الـ root وSecurity Groups المفتوحة.

🧹 **تنضيف:** (لازم الـ bucket يبقى فاضي)

```bash
aws cloudformation delete-stack --stack-name dukkan-images
aws cloudformation delete-stack --stack-name dukkan-images-staging
```

## ⚖️ قارن: الأدوات اللي بتتلخبط

| بيتلخبطوا | الفرق |
| --- | --- |
| SCP ↔ IAM policy | SCP = **سقف** على الحساب كله، مبيدّيش صلاحية. IAM policy = بيدّي صلاحية لهوية جوه الحساب. لازم الاتنين يسمحوا |
| Organizations ↔ Control Tower | Organizations = الأداة الأساسية. Control Tower = بيجهّز Organization بأفضل الممارسات أوتوماتيك |
| CloudFormation ↔ Elastic Beanstalk | CloudFormation = **أي** بنية من template. Beanstalk = يرفع **تطبيق** ويعمل البنية ليه |
| Trusted Advisor ↔ Security Hub | Trusted Advisor = توصيات عامة (تكلفة، أداء، أمان، limits). Security Hub = findings أمنية بالتفصيل |
| Systems Manager ↔ CloudFormation | Systems Manager = **تشغيل** السيرفرات الموجودة. CloudFormation = **بناء** البنية |
