## 🧠 افهم: الحساب اللي يقدر يعمل كل حاجة

أول ما عم حسن عمل حساب AWS بإيميله وباسورد، اتعمل معاه مستخدم اسمه **root user**. ده مش مستخدم عادي:

- يقدر يعمل **أي حاجة** في الحساب، ومفيش policy تقدر تمنعه من جوه الحساب نفسه.
- يقدر يقفل الحساب، يغيّر طريقة الدفع، ويمسح كل حاجة.
- لو حد سرق الباسورد، يقدر يشغّل سيرفرات بآلاف الدولارات باسمك.

عشان كده القاعدة: **الـ root بيتأمّن ويتشال في الدرج**، ومنستخدموش في الشغل اليومي.

<Hl c="y">Root user = صاحب الحساب بصلاحيات كاملة مش بتتقيد. بنحميه بـ MFA، وبنشتغل يوميًا بهوية تانية صلاحياتها محدودة.</Hl>

<Box type="story" icon="🔑" title="مفتاح العمارة الأصلي">

صاحب العمارة معاه **المفتاح الماستر** اللي بيفتح كل الشقق والسطح والعداد. مش بيديه للبواب، ومش بيمشي بيه في جيبه كل يوم. بيحطه في خزنة، وكل ساكن بياخد مفتاح شقته بس.

والـ MFA زي إن الخزنة محتاجة **مفتاح ورقم سري** مع بعض: لو حد لقى المفتاح بس، مش هيفتح.

</Box>

الـ **MFA (Multi-Factor Authentication)** معناه إن الدخول محتاج حاجتين من نوعين مختلفين:

- **حاجة إنت عارفها:** الباسورد.
- **حاجة معاك:** موبايل عليه app، أو security key بتتحط في الـ USB، أو passkey على جهازك.

## 🔍 من جوه: أنواع الـ MFA وإيه اللي مينفعش

### أنواع الـ MFA على AWS

| النوع | بيشتغل إزاي | مقاوم للتصيد؟ |
| --- | --- | --- |
| Passkey / FIDO security key | الجهاز بيثبت هويته للموقع الحقيقي بس | **أيوه**، الأقوى |
| Virtual authenticator app | app على الموبايل بيطلع كود من ٦ أرقام بيتغير كل ٣٠ ثانية | لأ، ممكن حد يخدعك تكتب الكود في موقع مزيّف |
| Hardware TOTP token | جهاز صغير بيطلع نفس النوع من الأكواد | لأ |

أي MFA أحسن جدًا من مفيش. ولو قدرت، استخدم **passkey أو security key** للـ root، وسجّل أكتر من جهاز عشان لو واحد ضاع.

### بلاش root access keys

الـ **access key** هي «باسورد للبرامج»: اتنين نصوص (`Access key ID` و`Secret access key`) بيخلوا كود أو CLI يكلم AWS. لو اتعملت للـ root وحد لقاها في GitHub، **مفيش MFA هيحميك**، لأن الـ API مش بيطلب MFA مع الـ access key بالشكل ده.

<Box type="warn" title="القاعدة">

**متعملش access keys للـ root أبدًا.** لو لقيت واحدة موجودة، اعطّلها وامسحها.

</Box>

### الحاجات اللي محتاجة root فعلًا

حاجات قليلة، زي تغيير إعدادات الحساب الأساسية، وقفل الحساب، وبعض إعدادات الفوترة. القايمة بتتغير، فلما تحتاج ارجع لصفحة AWS اسمها **Tasks that require root user credentials**. أي حاجة تانية: استخدم هويتك اليومية.

## 🛠️ طبّق: أمّن حساب دُكّان في ٥ خطوات

⚠️ كل الخطوات دي مجانية.

1. **ادخل بالـ root** على `console.aws.amazon.com` (اختار Root user).
2. **فعّل MFA:** من القايمة فوق على اسم الحساب ← `Security credentials` ← `Multi-factor authentication (MFA)` ← `Assign MFA device`. اختار passkey أو authenticator app، وكمّل الخطوات.
3. **اتأكد مفيش access keys:** في نفس الصفحة، قسم `Access keys` لازم يبقى فاضي.
4. **اعمل هوية للشغل اليومي:** هنعملها صح في الفصل الجاي (IAM Identity Center أو IAM user بـ MFA).
5. **اخرج من الـ root**، واكتب في مكان آمن: الإيميل، فين جهاز الـ MFA، ومين المسموح له يستخدمه.

**النتيجة المتوقعة:** في صفحة `Security credentials` هتلاقي جهاز MFA مسجّل، وقسم الـ access keys فاضي. ومن الفصل الجاي مش هتدخل بالـ root تاني إلا لو مضطر.

<Box type="tip" title="إيميل الـ root">

استخدم إيميل شركة مش إيميل شخص (زي `aws-root@dukkan.example`) يوصل لأكتر من حد موثوق. لو الموظف ساب الشغل، الحساب ميضيعش معاه.

</Box>

## ⚖️ قارن: root ولا هوية يومية؟

| | Root user | هوية يومية (IAM / Identity Center) |
| --- | --- | --- |
| بيتعمل إزاي؟ | أوتوماتيك مع الحساب | إنت بتعمله |
| الصلاحيات | كل حاجة، مش بتتقيد بـ IAM policies | اللي إنت بتديهاله بس |
| نستخدمه إمتى؟ | مهام قليلة جدًا محتاجاه | كل يوم |
| access keys؟ | **أبدًا** | للأدوات لو لازم، والأحسن credentials مؤقتة |
| MFA؟ | إجباري عمليًا | لازم برضه |

<Box type="interview" title="MFA مش بيحل كل حاجة">

MFA بيحمي من **باسورد مسروق**. مش بيحمي من: صلاحيات واسعة زيادة، access key اتسربت، أو موظف عنده صلاحية وعمل غلطة. الأمان طبقات، والطبقة الجاية هي IAM.

</Box>
