## الـ root مش حساب المدير اليومي

لما تعمل AWS account، البريد وكلمة السر بينشئوا root user. الهوية دي عندها وصول كامل وغير مقيد لموارد الحساب، وفيه مهام حساسة لا ينفذها غيرها.

ده سبب إنك **متستخدمهاش يوميًا**. بعد تجهيز وصول إداري منفصل وآمن، اقفل بيانات root وخلي استخدامها استثنائيًا.

<Box type="story" icon="🔑" title="مفتاح العمارة الرئيسي">

البواب محتاج مفتاح البوابة، مش مفتاح يفتح كل شقة والخزنة وغرفة الكهرباء. root هو المفتاح الرئيسي؛ يتحفظ للطوارئ، ويتسجل كل استخدام له.

</Box>

## أول خطوات الحماية

1. استخدم بريدًا مؤسسيًا مراقبًا، مش بريد موظف ممكن يمشي.
2. حط كلمة سر فريدة وطويلة في password manager موثوق.
3. فعّل MFA للـ root فورًا.
4. اختار MFA مقاومًا للتصيد زي passkey أو security key لما يكون مناسبًا.
5. جهّز هوية إدارية منفصلة للعمل المعتاد، وفعّل لها MFA.
6. راقب وسجّل أي استخدام للـ root.

AWS تدعم تسجيل أكتر من MFA device لبعض سيناريوهات root؛ راجع الوثائق الحالية وخطة المؤسسة عشان تقلل خطر فقد جهاز واحد من غير ما توزع الوصول بلا ضبط.

## Break-glass: للطوارئ فقط

Break-glass إجراء موثق لاستخدام صلاحية عالية لما المسار العادي يفشل. لازم يحدد:

- مين يوافق على الاستخدام ومين يحضر التنفيذ.
- فين بيانات الدخول وأجهزة MFA محفوظة بأمان.
- إمتى نعتبر الحالة طوارئ.
- إزاي نسجل السبب والخطوات، ونراجع الحدث بعدها.
- إزاي نختبر الإجراء من غير كشف الأسرار.

<Hl c="y">الطوارئ مش مبرر لهوية مشتركة مستخدمة كل يوم؛ هي مسار نادر، مراقب، ومختبر.</Hl>

## Access keys للـ root؟ لأ

Access key هي بيانات وصول برمجية. متعملش root access keys. لو لقيت واحدة موجودة، حقق في استخدامها وبعدين عطّلها واحذفها بخطة آمنة؛ متنسخش السر في ticket أو chat.

للتطبيقات والناس، استخدم roles وtemporary credentials حيثما أمكن. هنفصلهم في الفصلين الجايين.

<Box type="warn" title="الـ MFA مش عصا سحرية">

MFA يقلل خطر كلمة سر مسروقة، لكنه مش يصلح صلاحيات واسعة أو access keys مسربة أو session اتسرقت. الحماية طبقات: هوية، أقل صلاحية، logging، وتنبيه.

</Box>

## مهام root القليلة

بعض مهام الحساب والفوترة والأمان تحتاج root حسب نوع الحساب وإعداد Organizations. القائمة بتتغير، فراجع صفحة AWS الرسمية **Tasks that require root user credentials** وقت الحاجة بدل حفظ قائمة قديمة.

## 🧪 Lab آمن: تمرين طوارئ ورقي

من غير ما تدخل root، اكتب runbook من خمس خطوات لحالة فقد الوصول الإداري. حط أماكن فارغة لأسماء الموافقين، مكان جهاز MFA، وطريقة تسجيل الحدث. ممنوع تكتب كلمة سر أو recovery code في الورقة.

## قبل الفصل الجاي

حمينا الهوية الأقوى. الفصل الجاي هنبني وصول المدرسة اليومي بـ IAM users وgroups وroles وpolicies، ونشوف الصلاحية بتتعلق بمين وبأي مورد.
