## ابدأ بالسؤال مش بالخدمة

قبل ما تقول RDS أو DynamoDB، اكتب:

1. شكل الداتا والعلاقات؟
2. أهم access patterns؟
3. محتاج transaction أو joins؟
4. read/write volume والـ latency؟
5. availability وrecovery المطلوبين؟
6. مين عنده خبرة يشغّل ويصمم الحل؟

<Box type="story" icon="🧑‍🏫" title="المدرس مش بيوزع نفس الكشكول">

مسألة حساب، خريطة علاقات، كشف حضور، وتقرير سنوي مش نفس نوع الورقة. اختيار database قبل فهم السؤال زي ما توزع كشكول رسم في امتحان رياضيات عشان غلافه حلو.

</Box>

## Polyglot مش معناها زوّد خدمات

ممكن نظام واحد يستخدم أكتر من database، لكن كل خدمة جديدة تضيف تكلفة وpermissions وmonitoring وbackup ومهارة تشغيل. ابدأ بأبسط حل يحقق المتطلبات، وافصل لما القياس يثبت المشكلة.

<Hl c="y">الاختيار الصح أقل خدمة تحقق access patterns والموثوقية المطلوبة، مش أكبر رسمة معمارية.</Hl>

## أسئلة تفضح الاختيار الغلط

- لو cache وقعت، هل النظام يفقد الحقيقة؟ لو أيوه، تصميمك محتاج مراجعة.
- لو DynamoDB query محتاجة scan لكل table، هل الـ key بيدعم السؤال؟
- لو كل request تشغيلية رايحة Redshift، هل خلطت OLTP وOLAP؟
- لو graph query مجرد `get by id`، هل Neptune ضرورة؟
- لو relational schema بلا علاقات أو transactions، هل SQL اختير بالعادات بس؟

## 🧪 Lab ورقي: صمّم المدرسة

ارسم خمس صناديق: `Portal API`, `RDS`, `DynamoDB`, `ElastiCache`, `Redshift`. وصل:

- التسجيل والدرجات إلى RDS.
- sessions إلى DynamoDB.
- القراءات الساخنة إلى ElastiCache مع سهم رجوع لـ RDS.
- نسخة تحليلية دورية إلى Redshift.

دلوقتي احذف أي صندوق مش عندك requirement حقيقي له. التمرين مجاني. لو عملت prototype فعلي، استخدم داتا وهمية، حط budget، وامسح clusters/tables/backups والـ networking المدفوع بعد القياس.

<Box type="warn" title="التكلفة جزء من القرار">

قارن compute أو capacity، storage، requests، I/O، backup، data transfer، والحد الأدنى للتشغيل. راجع pricing calculator والـ docs الحالية؛ مفيش خدمة مضمونة مجانية لمجرد إنها serverless.

</Box>
