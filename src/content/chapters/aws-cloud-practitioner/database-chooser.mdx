## 🧠 افهم: السؤال مش «أنهي أحسن؟»

سارة سألت: «نستخدم PostgreSQL ولا DynamoDB؟». السؤال ده ملوش إجابة لوحده. الإجابة بتيجي من **شكل الداتا** و**شكل الأسئلة** اللي هتسألها.

نفس الفكرة زي ما بتختار مكان تخزين في البيت: التلاجة للأكل، والدولاب للهدوم، والمكتبة للكتب. محدش بيسأل «التلاجة أحسن ولا الدولاب؟».

<Box type="story" icon="🧰" title="عدّة الصنايعي">

الصنايعي الشاطر مش معاه «أحسن مفك». معاه عدّة: مفك صليبة ومفك عادة وشاكوش ومنشار. وبيبص على **المسمار** الأول وبعدين يختار. الـ databases المتخصصة هي العدّة، وأسئلة الفصل ده هي إنك تبص على المسمار.

</Box>

## 🔍 من جوه: الأربع أسئلة

### ١. الداتا شكلها إيه؟

- جداول بعلاقات ثابتة (عميل ← طلبات ← أصناف) → **relational**.
- items مستقلة بتتجاب بالمفتاح → **key-value** (DynamoDB).
- documents شكلها بيختلف (JSON) → **document** (DocumentDB أو DynamoDB).
- علاقات هي الأساس (مين يعرف مين) → **graph** (Neptune).
- قيم بوقت (حرارة كل دقيقة) → **time series** (Timestream).

### ٢. هتسألها إزاي؟

- أسئلة **معروفة مسبقًا** وبسيطة بالمفتاح → DynamoDB ممتاز.
- أسئلة **متغيرة** وjoins وfilters كتير → SQL.
- تجميع على ملايين الصفوف التاريخية (OLAP) → **data warehouse** زي Redshift، مش database التطبيق.

### ٣. السرعة والـ scale

- مللي ثواني لأي حجم → DynamoDB.
- microseconds للقراية → cache (ElastiCache أو DAX).
- ACID transactions قوية على داتا مترابطة → RDS/Aurora (وDynamoDB بيدعم transactions بحدود).

### ٤. عايز تدير قد إيه؟

| المستوى | المثال |
| --- | --- |
| كل حاجة عليك | database على EC2 |
| managed (إنت بتختار الحجم) | RDS، ElastiCache، DocumentDB |
| serverless (مفيش حجم تختاره) | DynamoDB، Aurora Serverless v2 |

<Box type="tip" title="OLTP ولا OLAP؟">

**OLTP** = عمليات التطبيق اليومية: «سجّل طلب»، «هات سلة». كتير وصغيرة وسريعة → RDS/DynamoDB.
**OLAP** = تحليل: «إجمالي المبيعات لكل محافظة في ٣ سنين». قليلة وتقيلة → **Redshift** (فصل ٣٣).

</Box>

## 🛠️ طبّق: اختار لكل جزء في دُكّان

الـ Lab ورقي. غطّي العمود التالت وحاول تجاوب لوحدك:

| الجزء | السؤال المهم | الاختيار |
| --- | --- | --- |
| الطلبات والفواتير | معاملات مالية وjoins | **Aurora PostgreSQL** (أو RDS) |
| سلة الزبون | هات بالـ customerId، ملايين المرات | **DynamoDB** + TTL |
| أكتر المنتجات مشاهدة | قراية كتير جدًا، ينفع تبقى قديمة دقيقة | **ElastiCache** |
| «اشتروا كمان…» | علاقات | **Neptune** |
| حساسات حرارة التلاجات | قيمة كل دقيقة بوقتها | **Timestream** |
| البحث «جبنة رومي» | بحث نصي | **OpenSearch Service** |
| تقرير ٣ سنين مبيعات | تجميع تاريخي ضخم | **Redshift** |
| برنامج قديم محتاج Oracle بإعدادات OS خاصة | تحكم كامل | **EC2** (أو RDS Custom) |

**تحدّي:** عم حسن قال «مش عايز ٨ databases، الفريق صغير». إيه أقل عدد يكفي البداية؟ غالبًا: **Aurora** للطلبات + **DynamoDB** للسلة، وباقي الحاجات تستنى لما تبقى مشكلة حقيقية. التعقيد ليه تمن.

## ⚖️ قارن: الجدول الكبير

| الخدمة | النوع | الكلمة المفتاحية في السؤال |
| --- | --- | --- |
| RDS | relational managed | SQL، MySQL/PostgreSQL/Oracle/SQL Server، managed |
| Aurora | relational cloud-native | MySQL/PostgreSQL compatible، high performance، ٦ نسخ |
| DynamoDB | key-value / document | serverless NoSQL، single-digit ms، any scale |
| ElastiCache | in-memory cache | caching، Redis/Valkey/Memcached، microseconds |
| MemoryDB | in-memory durable | Redis compatible + durable primary database |
| DocumentDB | document | MongoDB compatible |
| Neptune | graph | relationships، social، fraud، recommendations |
| Keyspaces | wide-column | Apache Cassandra compatible |
| Timestream | time series | IoT، metrics بوقت |
| OpenSearch Service | search & analytics | full-text search، log analytics |
| Redshift | data warehouse | OLAP، analytics، petabyte، BI |
