## وظيفة كل قطعة

- CloudFront يقرب الواجهة ويحمي origin بإعداد مناسب.
- S3 يخزن ملفات HTML وCSS والصور؛ خليه private ووصل CloudFront بصلاحية مخصصة.
- API Gateway هو باب HTTPS للـ API.
- Lambda تشغّل منطق قصير من غير إدارة servers.
- DynamoDB يخزن records بالمفاتيح اللي التصميم محتاجها.
- Cognito يدير sign-up/sign-in وtokens للمستخدمين.
- SQS تمسك شغل خلفي، وSNS تنشر خبر لعدة مشتركين.

## Request flow: فتح الدرجات

١. الطالب يطلب الموقع؛ Route 53 ممكن يحل الاسم إلى CloudFront.
٢. CloudFront ترجع ملفات الواجهة من cache أو تجيبها من S3.
٣. الطالب يسجّل الدخول عبر Cognito ويحصل على token.
٤. الواجهة تطلب `/grades` عبر API Gateway بالـ token.
٥. authorizer يتحقق، ثم Lambda تقرأ درجات الطالب المسموح بها من DynamoDB.
٦. الرد يرجع عبر API Gateway. متحطش صلاحيات الطالب في الواجهة وحدها؛ التحقق الحقيقي على الـ backend.

## Event flow: رفع واجب

١. Lambda تسجل metadata بأمان.
٢. تبعت message إلى SQS لمعالجة الملف.
٣. worker يعالج ويرجع النتيجة، مع retry وDLQ للفشل.
٤. SNS تنشر `AssignmentProcessed` للإشعارات والتحليلات.

<Hl c="g">الـ request flow مستني رد؛ الـ event flow بيفصل الشغل اللي ينفع يحصل بعدين.</Hl>

## حدود مهمة

Cognito مش database للدرجات، وCloudFront مش authorization بديل، وSQS مش broadcast لكل مستهلك لوحده. استخدم أقل IAM permissions، encryption، logs، وlimits.

<Box type="warn" title="Serverless مش معناها مجاني">

كل خدمة لها meter وحدود وFree Tier متغير. CloudFront data transfer وrequests، API calls، Lambda duration، DynamoDB capacity، والرسائل ممكن تعمل فاتورة. اعمل budget وامسح التجارب.

</Box>
