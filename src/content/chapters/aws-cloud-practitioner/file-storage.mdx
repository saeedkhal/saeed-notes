## المثال الأول: Media rendering على Linux

شركة فيديو عندها `24` EC2 worker في `3 AZs`. كل worker لازم يشوف نفس project files، ومتوسط المشروع `80 GB`. المطلوب worker جديد يعمل mount خلال دقيقة، والـ filesystem يفضل متاح لو AZ واحدة تعطلت.

١. workers تعمل mount لـ `Amazon EFS` عبر NFS.
٢. mount targets تتوزع على الـ AZs المستخدمة، وقواعد الشبكة تسمح NFS من workers فقط.
٣. الملفات النهائية تنتقل إلى S3 للتوزيع والأرشفة؛ EFS يفضل للـ shared working set.
٤. AWS Backup ينفذ policy، والفريق يعمل restore test ربع سنوي ويقيس الزمن.

## EFS ولا FSx؟

`EFS` filesystem مُدار ومرن لأحمال Linux/NFS، ويمكن مشاركته بين instances وعبر AZs داخل Region. اختاره لما التطبيق فعلًا محتاج POSIX-like shared file access، مش لمجرد إن المطورين متعودين على folders.

`FSx` عيلة متخصصة:

- `FSx for Windows File Server`: SMB وWindows وActive Directory.
- `FSx for Lustre`: throughput عالي للـ HPC والـ analytics.
- `FSx for NetApp ONTAP`: احتياجات NetApp protocols/features.
- `FSx for OpenZFS`: NFS وخصائص ZFS المُدارة.

لو pipeline تقرأ objects كاملة وتكتب نتائج مستقلة، S3 ممكن يبقى أبسط. لو legacy Windows app محتاجة SMB locks وAD، FSx for Windows أقرب من EFS.

## Hybrid: مصنع لسه on-premises

مصنع ينتج `6 TB` ملفات يوميًا، وعنده WAN `1 Gbps` مشتركة. `AWS Storage Gateway` يوفر interfaces مألوفة وlocal cache لبعض الأنماط، لكنه مش وصلة شبكة ولا backup policy وحده. `AWS DataSync` مناسب لنقل online مُدار وجدولة ومراقبة transfer بين storage systems المدعومة.

احسب قبل النقل: `6 TB` على `1 Gbps` نظريًا أكتر من `13 ساعة` قبل overhead والمنافسة. لو الـ SLA هو `4 ساعات`، لازم bandwidth أعلى أو تقليل/ضغط الداتا أو تغيير العملية.

## Backup بنتيجة قابلة للقياس

AWS Backup توحّد plans وschedules وretention لخدمات مدعومة حسب الـ Region. النجاح مش ظهور job باللون الأخضر؛ النجاح إن restore test يرجع dataset سليمة خلال الـ RTO المطلوب.

الساعة `02:00` backup يومية، الساعة `11:20` ransomware يشفر share، والـ RPO `24 ساعة` يسمح بفقد حتى آخر backup، لكن RTO `2 ساعة` يتطلب قياس restore لحجم حقيقي. لو restore استغرق `5 ساعات`، الخطة فشلت رغم وجود النسخة.

## Snow Family: caveat أكتوبر 2026

مواد قديمة تذكر `AWS Snow Family` للنقل الفيزيائي. حسب AWS Decision Guide المتاح في أكتوبر 2026، Snow Family غير متاحة لعملاء جدد، ودعم Snowball في commercial Regions مقرر ينتهي `31 ديسمبر 2026`. للتصميم الجديد راجع DataSync للنقل online وAWS Data Transfer Terminal أو partner options للنقل الفيزيائي حسب التوفر والـ docs الحالية.

<Box type="warn" title="Managed storage له تكلفة تشغيل">

احسب capacity وthroughput والـ backups والـ requests والـ transfer. امسح filesystems والنسخ التجريبية بعد الاختبار، ومتفترضش Free Tier.

</Box>

## 🧪 تمرين: Migration وrestore

شركة عندها Windows share حجمها `35 TB`، معدل تغيير `400 GB/day`، وRTO `6 ساعات`. اختار FSx أو EFS أو S3 مع السبب، ارسم initial copy ثم incremental sync، وحدد cutover window. بعدها افترض حذف `2 TB`: اكتب restore test بأوقات بداية ونهاية ومعيار نجاح واضح.
