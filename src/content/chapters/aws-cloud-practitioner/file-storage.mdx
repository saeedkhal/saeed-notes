## 🧠 افهم: ٤ سيرفرات محتاجين نفس الفولدر

دُكّان دلوقتي شغال على ٤ instances ورا Load Balancer. كل سيرفر بيحفظ ملفات الفواتير اللي بيولّدها في فولدر `/data/invoices` على الـ EBS بتاعه. النتيجة:

- الزبون طلب فاتورته، والـ Load Balancer وداه لسيرفر تاني، فملقاهاش.
- الـ EBS متركّب في سيرفر واحد بس.

محتاجين **فولدر واحد مشترك** يشوفه كل السيرفرات في نفس الوقت، كأنه هارد على الشبكة. ده اسمه **file storage**.

وفي نفس الوقت، محاسب دُكّان في المكتب عنده file server قديم بـ Windows، وعايز يكمل يشتغل عليه بس يكون الـ backup على AWS.

<Hl c="p">EFS = فولدر مشترك لسيرفرات Linux. FSx = file systems جاهزة لأنواع محددة (Windows، HPC، NetApp، ZFS). Storage Gateway = جسر بيوصّل أجهزة الـ data center بتخزين AWS.</Hl>

<Box type="story" icon="🗄️" title="دولاب الملفات في المكتب">

EBS زي **درج مكتبك**: إنت بس اللي بتفتحه.
EFS زي **دولاب الأرشيف في نص المكتب**: كل الموظفين بيفتحوه في نفس الوقت، وبيكبر لوحده كل ما تحط ملفات.
Storage Gateway زي **ساعي** قاعد في مكتبك بيستلم الملفات ويوديها مخزن الشركة الكبير (AWS)، ويحتفظ بالحاجات اللي بتستخدمها كتير قريبة منك.

</Box>

## 🔍 من جوه: الخيارات

### Amazon EFS (Elastic File System)

- File system بـ **NFS** لـ **Linux**.
- آلاف الـ instances (وcontainers وLambda) تعمله mount في نفس الوقت، من **أكتر من AZ**.
- **بيكبر ويصغر لوحده**، وبتدفع على اللي مستخدمه.
- فيه storage classes: Standard، Infrequent Access، Archive، و**lifecycle** بينقل الملفات اللي متلمستش.

### Amazon FSx: file systems متخصصة

| النوع | مناسب لـ |
| --- | --- |
| FSx for **Windows File Server** | ملفات Windows بـ **SMB** وActive Directory، برامج Windows |
| FSx for **Lustre** | **HPC** وmachine learning: أداء رهيب، وبيتربط بـ S3 |
| FSx for **NetApp ONTAP** | شركات بتستخدم NetApp وعايزة نفس المميزات على AWS |
| FSx for **OpenZFS** | نقل أحمال ZFS أو Linux محتاجة أداء عالي |

### AWS Storage Gateway

جهاز افتراضي (أو hardware) بتحطه **في الـ data center بتاعك**، بيقدّم تخزين بالـ protocols اللي برامجك فاهماها، والداتا فعليًا بتتخزن في AWS:

- **S3 File Gateway:** فولدر NFS/SMB، والملفات بتتحفظ objects في S3.
- **FSx File Gateway:** وصول محلي سريع لـ FSx for Windows.
- **Volume Gateway:** هاردات iSCSI مع backups في AWS.
- **Tape Gateway:** شرايط backup افتراضية، عشان برامج الـ backup القديمة تكمل من غير شرايط حقيقية.

### AWS Backup

مكان واحد تعمل فيه backup plans لـ EBS وEFS وFSx وRDS وDynamoDB وS3 وغيرهم: جدول، مدة احتفاظ، نسخ لـ Region أو حساب تاني.

## 🛠️ طبّق: فولدر فواتير مشترك لدُكّان

⚠️ EFS بيتحاسب على الـ GB المخزنة. ملفات صغيرة للتجربة تكلفتها قليلة جدًا، بس امسحه.

1. **اعمل EFS:** `EFS` ← `Create file system` ← الاسم `dukkan-invoices` ← نفس الـ VPC بتاعة السيرفرات. AWS بيعمل **mount target** في كل AZ.
2. **اظبط الـ Security Group:** الـ mount targets لازم تسمح بـ `NFS (2049)` من Security Group السيرفرات.
3. **اعمله mount** على instance (عن طريق Session Manager مثلًا):

```bash
sudo dnf install -y amazon-efs-utils
sudo mkdir -p /data
# fs-xxxx هو الـ ID بتاع الـ file system
sudo mount -t efs -o tls fs-0123456789abcdef0:/ /data
echo "فاتورة رقم 1001" | sudo tee /data/invoice-1001.txt
```

4. **اعمل mount من instance تانية** في AZ مختلفة واعمل `cat /data/invoice-1001.txt`.
   **المتوقع:** نفس الملف ظاهر. ده الفولدر المشترك.
5. **فكّر:** المحاسب في المكتب بـ Windows. هل هيعمل mount لـ EFS؟ (لأ، EFS لـ Linux/NFS. الأنسب FSx for Windows، أو S3 File Gateway لو الهدف backup على S3).

🧹 **تنضيف:** `umount /data`، امسح الـ file system من الـ console، وterminate للـ instances لو بتاعة التجربة.

## ⚖️ قارن: اختار التخزين من السؤال

| السؤال | الإجابة |
| --- | --- |
| هارد لـ instance واحدة | EBS |
| فولدر مشترك بين سيرفرات Linux كتير | **EFS** |
| file share لبرامج Windows بـ SMB وActive Directory | **FSx for Windows File Server** |
| HPC أو ML محتاج file system سريع جدًا | **FSx for Lustre** |
| برامج في الـ data center عايزة تخزّن على AWS بنفس الـ protocols | **Storage Gateway** |
| مكان واحد لإدارة backups كل الخدمات | **AWS Backup** |
| objects من الإنترنت أو التطبيقات | S3 |
