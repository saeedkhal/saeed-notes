## 🧠 افهم: سيرفر واحد مش هيكفي رمضان

دُكّان شغال على instance واحدة. مشكلتين:

1. **الزحمة:** بعد الفطار الطلبات ×١٠، والسيرفر الواحد بيبطّأ ويقع.
2. **العطل:** لو السيرفر ده باظ الساعة ٢ الفجر، الموقع واقف لحد ما حد يصحى.

الحل خدمتين بيشتغلوا مع بعض:

- **Elastic Load Balancing (ELB):** باب واحد للزباين، بيوزّع الطلبات على كذا سيرفر، وبيبطّل يبعت لأي سيرفر عيّان.
- **Amazon EC2 Auto Scaling:** بيزوّد السيرفرات لما الحمل يزيد، ويقللها لما يقل، ويستبدل أي سيرفر بيفشل.

<Hl c="b">الـ Load Balancer بيوزّع ويستبعد العيّان. والـ Auto Scaling group بيحافظ على العدد الصح من السيرفرات السليمة. مع بعض = scale + high availability.</Hl>

<Box type="story" icon="🏦" title="شبابيك البنك">

- **الـ Load Balancer** = الموظف اللي على الباب بيدي كل عميل رقم ويوجّهه لأفضى شباك. ولو شباك الموظف بتاعه تعبان، بيقفل الشباك ده ويوزّع على الباقي.
- **الـ Auto Scaling** = المدير اللي لما الطابور يطول بيفتح شبابيك زيادة، ولما يفضى بيقفلها، ولو موظف مشي بيجيب بداله.

</Box>

1. الزبون بيكلم **اسم الـ Load Balancer** (مش IP سيرفر معين).
2. الـ ALB بيعمل **health check** كل كام ثانية (مثلًا `GET /health`). السيرفر اللي مبيردش صح بيتشال من التوزيع.
3. الـ **Auto Scaling group** بيشوف إن في سيرفر unhealthy، فيمسحه ويطلّع بداله من الـ **launch template**.
4. لما الـ CPU يعدّي الهدف، بيطلّع سيرفرات زيادة، ويوزّعها على الـ AZs.

## 🔍 من جوه: الأجزاء والإعدادات

### أنواع الـ Load Balancers

| النوع | بيفهم إيه | مناسب لـ |
| --- | --- | --- |
| **Application LB (ALB)** | Layer 7: HTTP/HTTPS، الـ path والـ host والـ headers | مواقع وAPIs، توجيه `/api` لمكان و`/images` لمكان |
| **Network LB (NLB)** | Layer 4: TCP/UDP | أداء عالي جدًا، latency قليل، IP ثابت، ألعاب وIoT |
| **Gateway LB (GWLB)** | Layer 3 | تمرير الترافيك على أجهزة أمان (firewalls) من شركات تانية |

### Auto Scaling group: تلات أرقام

- **Minimum:** أقل عدد. حطه `2` على AZين عشان الـ availability.
- **Desired:** العدد اللي عايزه دلوقتي. الـ scaling بيغيّره.
- **Maximum:** السقف. **ده حمايتك من الفاتورة** لو حصل حمل غريب أو هجوم.

الـ **launch template** هو الوصفة: AMI، instance type، Security Group، user data، IAM role.

### طرق الـ scaling

| الطريقة | الفكرة | مثال |
| --- | --- | --- |
| Target tracking | خلّي metric عند رقم معين | «خلّي متوسط الـ CPU ٥٠٪» (الأسهل والأشهر) |
| Step scaling | خطوات حسب قد إيه الـ alarm عدّى | CPU فوق ٧٠٪ زوّد ٢، فوق ٩٠٪ زوّد ٤ |
| Scheduled | في وقت معين | كل يوم في رمضان الساعة ٧ بالليل خلّي الـ minimum ٦ |
| Predictive | بيتعلم من الأنماط اللي فاتت ويجهز بدري | الزحمة اليومية المتكررة |

<Box type="warn" title="الكود لازم يبقى stateless">

لو الـ session بتاعة الزبون (السلة مثلًا) محفوظة في ذاكرة سيرفر معين، وAuto Scaling مسحه، السلة هتضيع. احفظ الـ sessions في مكان مشترك (ElastiCache أو DynamoDB).

</Box>

## 🛠️ طبّق: دُكّان يستحمل رمضان

⚠️ الـ ALB بيتحاسب بالساعة طول ما هو موجود (مش داخل في كل خطط الـ Free Tier). خلّص في قعدة واحدة وامسح.

1. **Launch template:** `EC2` ← `Launch templates` ← `Create`. نفس إعدادات فصل ١٢ (AMI، `t3.micro`، الـ user data بتاعة nginx). الـ Security Group يسمح بـ HTTP **من Security Group الـ ALB بس** (هتعمله في الخطوة الجاية، أو ابدأ بـ Anywhere وضيّقه بعدين).
2. **Target group + ALB:** `Load Balancers` ← `Create` ← `Application Load Balancer` ← internet-facing ← اختار **AZين** ← listener `HTTP:80` ← target group جديد بـ health check path `/`.
3. **Auto Scaling group:** `Auto Scaling Groups` ← `Create` ← الـ launch template ← نفس الـ AZين ← اربطه بالـ target group ← فعّل **ELB health checks** ← `Min 2، Desired 2، Max 4` ← policy: target tracking، CPU `50%`.
4. **افتح الـ DNS name بتاع الـ ALB** في المتصفح. **المتوقع:** صفحة دُكّان.
5. **جرّب الـ self-healing:** اعمل terminate لواحدة من الـ instances يدويًا. استنى دقيقتين وبص على `Activity` في الـ ASG. **المتوقع:** instance جديدة بتطلع لوحدها، والموقع مكانش وقع.

🧹 **تنضيف بالترتيب:** امسح الـ Auto Scaling group (هيمسح الـ instances)، بعدين الـ Load Balancer، بعدين الـ target group، بعدين الـ launch template.

## ⚖️ قارن: مين بيعمل إيه؟

| | Load Balancer | Auto Scaling | Route 53 (فصل ٢٤) |
| --- | --- | --- | --- |
| بيوزّع الطلبات؟ | **أيوه**، على السيرفرات | لأ | بيوجّه على مستوى DNS (Regions مثلًا) |
| بيزوّد سيرفرات؟ | لأ | **أيوه** | لأ |
| بيكشف العيّان؟ | أيوه، ويبطّل يبعتله | أيوه، ويستبدله | health checks للـ endpoints |
| بيدّي high availability؟ | لما يوزّع على AZs | لما يحافظ على العدد في AZs | بين Regions |

| ALB | NLB |
| --- | --- |
| HTTP/HTTPS (Layer 7) | TCP/UDP (Layer 4) |
| توجيه بالـ path والـ host | أداء عالي جدًا وlatency قليل |
| مواقع وmicroservices | ألعاب، IoT، IP ثابت |
