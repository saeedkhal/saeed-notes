## 🧠 افهم: كل واحد ياخد مفتاح اللي محتاجه بس

دُكّان بقى فيه فريق: سارة المطوّرة، كريم المحاسب، وتطبيق الموقع نفسه اللي محتاج يحفظ صور. لو إدّيت الكل الـ root، كريم ممكن يمسح سيرفر بالغلط، والتطبيق لو اتخترق هياخد كل حاجة.

**IAM (Identity and Access Management)** هي الخدمة اللي بتجاوب على سؤالين في كل request لـ AWS:

1. **إنت مين؟** (authentication = إثبات الهوية)
2. **مسموحلك تعمل ده؟** (authorization = الصلاحية)

<Hl c="g">IAM بتربط هوية (user أو role) بـ policy بتقول: مسموح أو ممنوع، أنهي action، على أنهي resource.</Hl>

<Box type="story" icon="🏨" title="فندق وكروت الأوض">

- **User:** نزيل في الفندق، ليه اسم وكارت دائم.
- **Group:** «نزلاء الدور التالت»، أي حد يتضاف للجروب ياخد نفس الصلاحيات.
- **Role:** كارت **مؤقت** بيتدّى لعامل الصيانة يدخل أوضة معينة ساعة ويرجّعه. محدش «بيبقى» الـ role، الشخص أو البرنامج **بيلبسه** شوية.
- **Policy:** الورقة المكتوب فيها الكارت ده يفتح أنهي أبواب.

</Box>

قاعدة IAM لما تقرر:

1. **الأصل إن كل حاجة ممنوعة** (implicit deny). من غير policy بتسمح، مفيش حاجة.
2. لو في policy فيها `Allow` للـ action ده → مسموح.
3. لو في **أي** policy فيها `Deny` صريح → ممنوع، حتى لو في Allow. **الـ Deny بيكسب دايمًا.**

## 🔍 من جوه: المكونات الأربعة

<Grid2>
<Card title="IAM User" c={1}>

هوية دايمة لشخص أو برنامج، ليها باسورد للـ console و/أو access keys. **النهارده** الأفضل للبشر يدخلوا عن طريق IAM Identity Center بدل users كتير.

</Card>
<Card title="IAM Group" c={2}>

مجموعة users. بتحط الـ policy على الجروب مرة واحدة. group مش بيتعمله login، ومينفعش group جوه group.

</Card>
<Card title="IAM Role" c={3}>

هوية **من غير باسورد ولا access keys دايمة**. اللي بيستخدمها بياخد **credentials مؤقتة** بتنتهي لوحدها. للسيرفرات والـ Lambda والدخول من حساب تاني.

</Card>
<Card title="Policy" c={4}>

ملف JSON بيقول `Effect` (Allow/Deny) و`Action` و`Resource`. بتتحط على user أو group أو role (identity-based)، أو على المورد نفسه زي bucket (resource-based).

</Card>
</Grid2>

### شكل الـ policy

<File name="dukkan-images-read.json">

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject"],
      "Resource": "arn:aws:s3:::dukkan-images/*"
    }
  ]
}
```

</File>

اقراها كجملة: **«مسموح** تقرا وترفع objects **في** bucket اسمه dukkan-images». أي حاجة تانية ممنوعة لأنها مش مذكورة. الـ `Version` ده تاريخ ثابت لصيغة اللغة، مش تاريخ إنت كتبت فيه الـ policy.

الـ **ARN** (Amazon Resource Name) هو العنوان الكامل لأي مورد في AWS، زي `arn:aws:s3:::dukkan-images`.

### IAM Identity Center

خدمة لإدارة دخول **البشر** لحساب أو حسابات كتير من مكان واحد، مع single sign-on. الموظف بيدخل مرة، يختار الحساب والـ permission set، وياخد credentials مؤقتة. وتقدر تربطها بـ Microsoft Entra ID أو Google Workspace أو أي مزود هوية.

<Box type="tip" title="IAM نفسها global ومجانية">

IAM مش مربوطة بـ Region: الـ user اللي تعمله بيشتغل في كل الـ Regions. وIAM نفسها مش بتتحاسب، بتدفع على الموارد اللي الهويات بتستخدمها.

</Box>

## 🛠️ طبّق: صلاحيات فريق دُكّان

⚠️ IAM مجانية. الخطوات من الـ console بهوية admin (مش الـ root لو عملت واحدة).

1. **اعمل group** اسمه `Developers`: `IAM` ← `User groups` ← `Create group`.
2. **اعمل policy** بالـ JSON اللي فوق: `Policies` ← `Create policy` ← تبويب `JSON` ← الصق ← سميها `DukkanImagesReadWrite`.
3. **اربط الـ policy بالـ group.**
4. **اعمل user** لسارة وضيفها للـ group، وفعّل لها MFA.
5. **جرّب:** ادخل كسارة وحاول تفتح EC2. **المتوقع:** رسالة زي `You are not authorized to perform this operation`. ده معناه إن الـ implicit deny شغال.

نفس الفكرة بالـ CLI:

```bash
aws iam create-group --group-name Developers
aws iam create-policy --policy-name DukkanImagesReadWrite \
  --policy-document file://dukkan-images-read.json
# حط الـ ARN اللي رجع من الأمر اللي فوق
aws iam attach-group-policy --group-name Developers \
  --policy-arn arn:aws:iam::<ACCOUNT_ID>:policy/DukkanImagesReadWrite
```

🧹 **تنضيف:** امسح الـ user ثم الـ group ثم الـ policy لو كانت تجربة.

**وكريم المحاسب؟** متدّيلوش access لـ S3 خالص. AWS عندها policy جاهزة اسمها `Billing` (job function) لصلاحيات الفواتير.

## ⚖️ قارن: User ولا Group ولا Role؟

| السؤال | الإجابة |
| --- | --- |
| موظف جديد محتاج يدخل الـ console | Identity Center (أو IAM user بـ MFA في حساب صغير) |
| ١٠ مطورين محتاجين نفس الصلاحيات | **Group** وحط الـ policy عليه |
| سيرفر EC2 محتاج يقرا من S3 | **Role** (instance profile)، مش access keys على السيرفر |
| Lambda محتاجة تكتب في DynamoDB | **Role** للـ Lambda |
| حساب AWS تاني محتاج يدخل مؤقتًا | **Role** بيعمله assume |
| تحدد مين يقرا bucket من على الـ bucket نفسه | **Resource-based policy** (bucket policy) |

<Box type="interview" title="الفرق اللي بيتسأل كتير">

**User** = credentials دايمة لهوية معينة. **Role** = credentials مؤقتة لأي حد مسموح له «يلبسها». لو السؤال فيه «application» أو «EC2» أو «Lambda» أو «temporary» أو «another account»، الإجابة غالبًا **Role**.

</Box>
