## الخط الفاصل بيتحرك

AWS Shared Responsibility Model بيقسم الأمان:

- **Security of the cloud:** AWS تحمي البنية اللي تشغّل خدمات AWS: المرافق، الهاردوير، الشبكات الأساسية، وطبقة الافتراضية.
- **Security in the cloud:** العميل يحمي اللي يضعه ويضبطه: الداتا، الهويات، الإعدادات، والصلاحيات، ومسؤوليات إضافية حسب الخدمة.

<Hl c="p">AWS تؤمّن الـ Cloud، والمدرسة تؤمّن استخدامها للـ Cloud.</Hl>

## مثال EC2

مع Amazon EC2، AWS تدير data center والهاردوير والـ hypervisor. المدرسة تدير guest OS وتحديثاته، التطبيق، security groups، IAM، والتصنيف والتشفير المناسب للداتا.

لو نظام التشغيل قديم واتخترق، مينفعش نقول إن السيرفر المادي عند AWS وخلاص. الطبقة اللي اخترنا نديرها مسؤوليتنا.

## مثال خدمة مُدارة

مع خدمة database مُدارة، AWS قد تدير نظام التشغيل وطبقة قاعدة البيانات أو أجزاء أكبر من الصيانة. العميل يفضل مسؤولًا عن اختيار الإعدادات، المستخدمين والصلاحيات، network access، الداتا، والنسخ أو الاحتفاظ حسب خصائص الخدمة وإعداده.

<Box type="story" icon="🏢" title="شقة في عمارة">

صاحب العمارة مسؤول عن الأساسات والمصعد الرئيسي. الساكن مسؤول عن قفل شقته ومين يدخلها. لو استأجر شقة مفروشة، مسؤولية الأثاث تقل، لكن لسه مينفعش يسيب الباب مفتوح.

</Box>

## AWS مش مسؤولة عن كل configuration

S3 bucket خاصة بالافتراضي في سيناريوهات كثيرة، لكن العميل مسؤول عن السياسات والـ public access وإعدادات المشاركة. وجود encryption feature لا يعني إنها مفعلة أو مناسبة تلقائيًا لكل workload.

كمان العميل مسؤول عن training والإجراءات والاستجابة داخل بيئته. AWS توفر خدمات وتقارير امتثال، لكن المؤسسة تقرر إذا تصميمها يحقق متطلباتها.
