## Claims workflow في شركة تأمين

كل يوم بيوصل 12,000 claim: PDF وصور ومكالمة صوتية. المطلوب رد أولي خلال دقيقتين مع human review للقرارات الحساسة.

1. `Transcribe` يحول المكالمة من speech إلى text.
2. `Textract` يستخرج fields وtables من الفاتورة.
3. `Rekognition` يحلل صور الضرر.
4. `Comprehend` يستخرج entities وsentiment من النص.
5. تطبيق مبني على `Bedrock` يلخص الملف ويولد draft، مع Guardrails وRAG من policies.
6. reviewer يوافق أو يعدل؛ `Polly` يقدر ينطق الرد، و`Translate` يغير اللغة.

نجاح الـ workflow يتقاس بالدقة والlatency والتكلفة ونسبة الحالات اللي احتاجت مراجعة، مش بمجرد إن model رجع إجابة. Low-confidence أو high-value claim لازم يتحول لإنسان.

## Bedrock ولا SageMaker AI ولا Q؟

`Amazon Bedrock` منصة fully managed لبناء generative AI apps باستخدام foundation models، مع Knowledge Bases وGuardrails وAgents وevaluation.

`Amazon SageMaker AI`—الاسم الحالي للخدمة القديمة SageMaker قبل ديسمبر ٢٠٢٤—لبناء وتدريب وتخصيص ونشر ML models وإدارة lifecycle أعمق.

`Amazon Q` assistant جاهز للعمل؛ `Q Developer` يساعد فرق software وAWS. Q منتج للمستخدم، Bedrock منصة تبني فوقها منتج.

- chatbot من foundation model من غير training infrastructure → Bedrock.
- fraud model مخصص على labeled transactions وpipelines/endpoints → SageMaker AI.
- assistant جاهز للمطورين → Amazon Q.

## APIs متخصصة

`Rekognition` للصور والفيديو؛ `Textract` للمستندات والـ forms/tables؛ `Comprehend` لـ NLP؛ `Lex` لإدارة conversational bot؛ `Polly` text→speech؛ `Transcribe` speech→text؛ `Translate` لغة→لغة.

صورة invoice: Textract لو المطلوب amount وtable، وRekognition لو المطلوب objects داخل الصورة. ممكن تستخدم الاتنين.

## Tradeoffs إنتاجية

Foundation model أسرع في البداية، لكن لازم تختبر hallucination وprivacy وprompt injection والتكلفة per token. Custom model يدي تحكم أعلى لكنه يحتاج data وMLOps ومراقبة drift. API جاهزة تقلل الإدارة، لكنها مش مناسبة لكل domain أو قرار حساس.
