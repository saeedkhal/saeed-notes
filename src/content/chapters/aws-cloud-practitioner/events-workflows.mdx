## 🧠 افهم: نوعين من «ربط الأنظمة»

في دُكّان في نوعين من المواقف:

1. **حصل حاجة، ومين يهمه يتصرف:** «زبون جديد سجّل» ← فريق التسويق عايز يبعتله كوبون، وفريق التحليل عايز يسجله. الـ checkout **مش عارف ومش عايز يعرف** مين مهتم. ده **event-driven**.
2. **خطوات بالترتيب، وكل خطوة ليها نتيجة:** الطلب لازم: يتأكد الدفع ← يتحجز المخزون ← يتعيّن مندوب. ولو الدفع فشل، يتلغي الحجز. ده **workflow**.

<Hl c="o">EventBridge = لوحة إعلانات ذكية: الحدث بيتعلق، والقواعد بتوديه للي يهمه. Step Functions = مدير مشروع: بيمشي الخطوات بالترتيب، ويعيد المحاولة، ويتصرف لو حاجة فشلت.</Hl>

<Box type="story" icon="💍" title="فرح">

- **EventBridge** زي **جروب العيلة على واتساب**: حد كتب «العروسة وصلت القاعة!». المصور يقوم يصوّر، والـ DJ يشغّل الزفة، والمطبخ يجهز. اللي كتب مش بيكلم كل واحد، وكل واحد عارف هو مهتم بأنهي رسايل.
- **Step Functions** زي **منظم الفرح** معاه ورقة: الزفة ← الكوشة ← التورتة ← البوفيه. لو الـ DJ اتأخر، بيستنى أو بيكلّم البديل. وفي الآخر عنده سجل باللي حصل في كل خطوة.

</Box>

## 🔍 من جوه: الخدمتين

### Amazon EventBridge

- **Event:** JSON بيوصف حاجة حصلت.
- **Event bus:** المكان اللي الأحداث بتتبعتله. في **default bus** بيستقبل أحداث خدمات AWS نفسها (EC2 وقفت، ملف اترفع…)، وتقدر تعمل **custom bus** لأحداث تطبيقك، وفي أحداث من شركاء SaaS.
- **Rule:** pattern بيفلتر الأحداث («source = dukkan.checkout و total > 1000») ويبعتها لـ **targets** (Lambda، SQS، Step Functions، SNS، API خارجي…).
- **EventBridge Scheduler:** يشغّل حاجة **بجدول** (cron أو rate) أو مرة واحدة في وقت محدد. بديل الـ cron jobs على سيرفر.
- **Pipes:** يوصّل source بـ target مباشرة مع فلترة وتحويل.

### AWS Step Functions

- **State machine:** الـ workflow مكتوب كخطوات (states) باللغة اسمها **Amazon States Language** (JSON)، وبيظهر رسمة في الـ console.
- كل خطوة ممكن تكلم Lambda أو خدمات AWS كتير **مباشرة** (DynamoDB، SQS، ECS…).
- فيه **Retry** و**Catch** لكل خطوة، و**Choice** (if/else)، و**Parallel**، و**Map** (لكل عنصر في list)، و**Wait**.
- **Standard workflows:** لحد سنة، مناسبة لعمليات طويلة (موافقة بشرية مثلًا). **Express:** قصيرة وكتيرة جدًا.

<Box type="tip" title="ليه مش Lambda بتنادي Lambda؟">

ممكن تكتب كل الخطوات في function واحدة، بس هتكتب الـ retries والـ waits والـ error handling بإيدك، ومش هتعرف الطلب وقف فين. Step Functions بيديك ده جاهز ومرسوم.

</Box>

## 🛠️ طبّق: تقرير ليلي وworkflow طلب

⚠️ EventBridge Scheduler وStep Functions ليهم Free Tier شهري. التجربة صغيرة جدًا.

### ١. جدول ليلي

`EventBridge` ← `Schedules` ← `Create schedule`:

- Pattern: `Recurring` ← cron: `0 2 * * ? *` (كل يوم الساعة ٢ الفجر، واختار الـ timezone `Africa/Cairo`).
- Target: Lambda (مثلًا `dukkan-products` من فصل ١٥).

**المتوقع:** بكرة الساعة ٢ هتلاقي invocation في الـ logs. ده بديل إنك تسيب سيرفر صاحي عشان cron.

### ٢. Workflow الطلب

`Step Functions` ← `Create state machine` ← `Blank` ← تبويب `Code` والصق:

<File name="order-workflow.asl.json">

```json
{
  "Comment": "طلب دُكّان",
  "StartAt": "ChargePayment",
  "States": {
    "ChargePayment": {
      "Type": "Pass",
      "Result": { "paid": true },
      "ResultPath": "$.payment",
      "Next": "IsPaid"
    },
    "IsPaid": {
      "Type": "Choice",
      "Choices": [
        { "Variable": "$.payment.paid", "BooleanEquals": true, "Next": "ReserveStock" }
      ],
      "Default": "PaymentFailed"
    },
    "ReserveStock": { "Type": "Wait", "Seconds": 3, "Next": "AssignCourier" },
    "AssignCourier": { "Type": "Pass", "End": true },
    "PaymentFailed": { "Type": "Fail", "Error": "PaymentDeclined" }
  }
}
```

</File>

الخطوات هنا `Pass` و`Wait` للتجربة بس. في الحقيقة كل واحدة بتكلم Lambda أو خدمة. اضغط `Start execution` بأي input.

**المتوقع:** رسمة بتنوّر كل خطوة بالأخضر وهي بتعدي. غيّر `"paid": true` لـ `false` ونفّذ تاني: هتلاقي الطريق راح لـ `PaymentFailed`.

🧹 **تنضيف:** امسح الـ schedule والـ state machine.

## ⚖️ قارن: أدوات الربط كلها

| | SQS | SNS | EventBridge | Step Functions |
| --- | --- | --- | --- | --- |
| الفكرة | طابور شغل | broadcast | توجيه أحداث بقواعد | تنسيق خطوات |
| بيعرف الترتيب والحالة؟ | لأ | لأ | لأ | **أيوه** |
| فلترة | لأ | message filtering | **event patterns** قوية | Choice states |
| أحداث خدمات AWS وSaaS | لأ | محدود | **أيوه** | — |
| جدولة | لأ | لأ | **Scheduler** | Wait states |
| مثال | تصغير الصور | إشعار كل الفرق | «لو EC2 وقفت، ابعت تنبيه» | الدفع ← المخزون ← الشحن |

<Box type="interview" title="الكلمات المفتاحية">

«event bus»، «react to changes in AWS services»، «SaaS events»، «schedule (cron)» ← **EventBridge**.
«orchestrate»، «workflow»، «state machine»، «coordinate multiple Lambda functions with retries» ← **Step Functions**.

</Box>
