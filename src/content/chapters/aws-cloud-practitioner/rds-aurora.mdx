## 🧠 افهم: database على EC2 ولا مُدارة؟

طلبات دُكّان لازم تتحفظ في database فيها جداول مترابطة: `customers` و`orders` و`order_items`. ده شغل **relational database** (SQL).

ممكن تركّب PostgreSQL على EC2 بنفسك. بس ساعتها إنت اللي:

- بتعمل patches للـ OS ولـ PostgreSQL،
- بتعمل backups وتختبرها،
- بتجهّز نسخة احتياطية لو السيرفر وقع،
- بتكبّر الهارد قبل ما يتملي.

**Amazon RDS (Relational Database Service)** بيعمل كل ده ليك. إنت بتختار الـ engine والحجم، وبتدير الـ schema والـ queries والداتا.

<Hl c="g">RDS = database علائقية مُدارة: AWS بتعمل الـ patches والـ backups والـ failover. وAurora = نسخة AWS المتطورة المتوافقة مع MySQL وPostgreSQL.</Hl>

<Box type="story" icon="📒" title="الدفتر والمحاسب">

إنك تركّب database على EC2 زي إنك **تمسك دفتر الحسابات بنفسك**: تشتري الدفتر، وتصوّره كل يوم، ولو اتحرق تدور على الصورة.

RDS زي **مكتب محاسبة**: إنت بتقول القيود (الداتا)، وهما بيحفظوا الدفتر، ويصوروه كل يوم، وعندهم **نسخة تانية في فرع تاني** بتتكتب في نفس اللحظة. لو الفرع الأول قفل، الفرع التاني يكمل.

</Box>

- **Multi-AZ:** نسخة **standby** في AZ تانية، بتتكتب **مع** الـ primary. لو الـ primary وقع، RDS بيحوّل عليها أوتوماتيك (failover) في دقايق، والتطبيق بيكمل على **نفس الـ endpoint**. الهدف: **availability**.
- **Read replica:** نسخة **للقراية بس**، بتوصلها التغييرات بعد شوية (async). الهدف: **تخفيف القراية** عن الـ primary (تقارير، صفحات كتير).

## 🔍 من جوه: RDS بالتفصيل

### الـ engines

PostgreSQL، MySQL، MariaDB، Oracle، Microsoft SQL Server، IBM Db2، و**Aurora** (MySQL وPostgreSQL compatible).

### Backups

- **Automated backups:** snapshot يومي + transaction logs، لمدة لحد **٣٥ يوم**. بتقدر ترجع لأي **ثانية** في المدة دي (**point-in-time recovery**)، والـ restore بيعمل database **جديدة**.
- **Manual snapshots:** بتفضل لحد ما تمسحها بنفسك.

### Amazon Aurora

- متوافق مع MySQL أو PostgreSQL، فالتطبيق غالبًا مش محتاج يتغيّر.
- التخزين بيتنسخ **٦ نسخ على ٣ AZs**، وبيكبر لوحده.
- لحد **١٥ read replica** بـ lag قليل جدًا.
- **Aurora Serverless v2:** بيكبر ويصغر السعة أوتوماتيك حسب الحمل.
- **Aurora Global Database:** نسخ في Regions تانية للـ DR والقراية القريبة.

### حاجات بتكمّل الصورة

**RDS Proxy** بيعمل pooling للـ connections (مفيد جدًا مع Lambda). والتشفير بيتفعّل وقت الإنشاء بـ KMS.

<Box type="warn" title="الـ database مكانها private subnet">

متخليش الـ database `Publicly accessible`. خليها في private subnet (فصل ٢٢)، والـ Security Group بتاعها يسمح بس للـ Security Group بتاع التطبيق على port الـ engine.

</Box>

## 🛠️ طبّق: database طلبات دُكّان

⚠️ RDS بيتحاسب بالساعة على الـ instance والـ storage. اختار instance صغيرة (`db.t4g.micro` لو متاحة في الـ Free Tier لحسابك)، **Single-AZ** للتجربة، وامسحها في نفس القعدة.

1. **`RDS` ← `Create database`** ← `Standard create` ← `PostgreSQL` ← Template: `Free tier` أو `Dev/Test`.
2. **Settings:** الاسم `dukkan-db`، والباسورد خليه **Managed in AWS Secrets Manager** (فصل ٣٠).
3. **Connectivity:** `Public access = No`، وSecurity Group جديد.
4. **Additional configuration:** backup retention `1 day`، ولاحظ إن في checkbox اسمه `Enable deletion protection`.
5. استنى الحالة تبقى `Available` (دقايق). افتح الـ database وبص على:
   - الـ **Endpoint**: اسم DNS ثابت، ده اللي التطبيق بيكلمه مش IP.
   - تبويب `Maintenance & backups`: الـ backup window والـ maintenance window.
6. **جرّب point-in-time:** `Actions` ← `Restore to point in time`. **لاحظ** إنه هيطلب **اسم database جديدة**. ده معناه إن الـ restore مش بيكتب فوق القديمة. (متكملش عشان متدفعش على اتنين.)

🧹 **تنضيف:** `Actions` ← `Delete` ← شيل علامة `Create final snapshot` (للتجربة بس) ← أكّد. واتأكد إن مفيش manual snapshots فاضلة.

## ⚖️ قارن: الفروق اللي بتتسأل

| | Multi-AZ | Read replica |
| --- | --- | --- |
| الهدف | high availability / failover | scale للقراية |
| النسخ | synchronous | asynchronous |
| بتقرا منها؟ | لأ في الشكل الكلاسيكي (standby) | **أيوه** |
| لو الـ primary وقع | failover أوتوماتيك | ممكن تعملها promote يدوي |
| ممكن في Region تانية؟ | لأ (نفس الـ Region) | أيوه (cross-Region) |

| | Database على EC2 | Amazon RDS | Amazon Aurora |
| --- | --- | --- | --- |
| Patches للـ OS والـ engine | إنت | AWS | AWS |
| Backups وPITR | إنت | أوتوماتيك | أوتوماتيك |
| Failover | إنت تبنيه | Multi-AZ | مدمج، أسرع |
| أي engine؟ | أي حاجة | ٦ engines + Aurora | MySQL/PostgreSQL compatible |
| مناسب لـ | engine مش مدعوم، تحكم كامل في الـ OS | معظم التطبيقات | أداء وتوافر أعلى وscale أكبر |
