## Payment API من أول request لحد الـ backup

Fintech عندها `CloudFront → ALB → ECS → RDS`، وبتحفظ settlement files في S3.

1. العميل يبعت card token عبر `HTTPS/TLS`: ده <En>encryption in transit</En>.
2. ALB يفك TLS ويبعت للـ target على connection محمية حسب التصميم.
3. ECS task تجيب database credential وقت التشغيل من `Secrets Manager` باستخدام IAM role.
4. RDS وS3 يشفروا البيانات <En>at rest</En> بمفاتيح تحت إدارة `KMS`.
5. CloudTrail يسجل استخدام الـ KMS API وتغييرات policies.
6. بعد 30 يوم، Secrets Manager يعمل rotation للـ credential من غير ما يتحط في Git أو image.

لو S3 encrypted لكن التطبيق بيبعت HTTP، الحماية فشلت أثناء النقل. ولو HTTPS شغال لكن backup غير مشفر، الحماية فشلت أثناء التخزين. الاتنين مطلوبين.

## KMS: key مش secret value

`AWS KMS` ينشئ ويدير encryption keys، permissions، rotation options، وcryptographic operations. في <En>envelope encryption</En>:

1. التطبيق يشفّر 20 GB file بـ data key محليًا.
2. KMS key تشفّر الـ data key الصغير.
3. الملف المشفر والـ encrypted data key يتخزنوا مع بعض.
4. عند القراءة، principal مصرح له يطلب من KMS فك data key ثم يفك الملف.

ده أسرع وأنسب من إرسال كل 20 GB لـ KMS. النجاح محتاج IAM policy وkey policy يسمحوا بالمسار المطلوب؛ encryption من غير access control مضبوط مش كفاية.

## Secrets Manager: credential بيتغير

`Secrets Manager` يخزن passwords وAPI keys وtokens، يدير versions، ويدعم rotation. التطبيق يطلب القيمة بهوية IAM بدل hard-coded secret.

لو rotation غيّر password في Secrets Manager بس معملش update للـ database، التطبيق هيفشل. rotation workflow لازم يغيّر الطرفين ويختبر login قبل ما يفعّل النسخة الجديدة.

## ACM: هوية endpoint وTLS

`AWS Certificate Manager (ACM)` يوفر ويدير شهادات SSL/TLS للاستخدام مع خدمات متكاملة زي CloudFront وALB وAPI Gateway. الشهادة تثبت هوية الـ endpoint وتدعم HTTPS؛ مش database password ومش KMS key.

الشهادات العامة المُدارة تتجدد تلقائيًا لو validation وشروط التجديد لسه سليمة. شهادة CloudFront العامة لها متطلبات Region مخصوصة؛ راجع الـ docs الحالية.

## إزاي تختار؟

- data على disk أو backup: encryption at rest، غالبًا بتكامل الخدمة مع KMS.
- traffic بين client وendpoint: TLS وشهادة من ACM عند الخدمة المدعومة.
- application credential محتاج rotation: Secrets Manager.
- configuration غير حساس أو secret أبسط حسب المتطلبات: قارن Parameter Store، لكن متفترضش إن كل parameter secret.
- hardware key control خاص: راجع KMS custom key stores أو CloudHSM حسب المتطلب؛ التعقيد والتكلفة أعلى.
