## At rest وIn transit

- <En>Encryption at rest</En>: البيانات وهي متخزنة على disk أو database أو backup.
- <En>Encryption in transit</En>: البيانات وهي ماشية على الشبكة، غالبًا باستخدام TLS/HTTPS.

محتاج الاتنين. تشفير القرص مش بيحمي request ماشية plaintext، وHTTPS مش بيشفر backup متروك من غير إعداد مناسب.

<Box type="story" icon="📦" title="جواب في خزنة">

At rest يعني الجواب مقفول في خزنة وهو ساكن. In transit يعني راكب عربية مصفحة وهو بيتنقل. حماية مرحلة واحدة متكفيش.

</Box>

## AWS KMS: إدارة المفاتيح

<En>AWS Key Management Service</En> ينشئ ويدير keys تشفير ويطبّق permissions ويسجل استخدامها عبر CloudTrail. خدمات AWS كثيرة تتكامل معاه لتشفير البيانات.

KMS key مش مكان تحط فيه password كنص. هو مفتاح وعمليات cryptographic وإدارة دورة حياة.

في <En>envelope encryption</En>، data key تشفر البيانات، وKMS key تحمي الـ data key. ده أنسب للبيانات الكبيرة من إرسال كل الملف إلى KMS.

## Secrets Manager: السر وقيمته

<En>AWS Secrets Manager</En> يخزن credentials وAPI keys وtokens بشكل مُدار، يتحكم في الوصول، ويدعم rotation خصوصًا مع تكاملات databases.

التطبيق يطلب السر وقت التشغيل بهوية IAM؛ متحطش password في source code أو AMI أو ملف متسجل في Git.

## AWS Certificate Manager

<En>AWS Certificate Manager (ACM)</En> يوفّر ويدير شهادات SSL/TLS العامة والخاصة للاستخدام مع خدمات AWS متكاملة زي CloudFront وload balancers وAPI Gateway.

الشهادة تثبت الهوية وتدعم HTTPS. هي مش password database، وKMS مش بديل مباشر للشهادة.

الشهادات العامة المُدارة من ACM بتتجدد تلقائيًا لو شروط التجديد والتحقق ما زالت صحيحة. راجع Region ومتطلبات الخدمة؛ شهادة CloudFront العامة لها متطلبات Region مخصوصة في الإعداد.

## بوابة المدرسة

CloudFront وAPI Gateway يستخدموا TLS للطلب. S3 وDynamoDB يفعّلوا encryption at rest. Lambda تقرأ database secret من Secrets Manager. KMS keys تتحكم في التشفير، وIAM يحدد مين يستخدمها.

<Hl c="p">التشفير من غير permissions صح ممكن يدي شخص صلاحية يفك التشفير؛ الاتنين لازم يتصمموا مع بعض.</Hl>
