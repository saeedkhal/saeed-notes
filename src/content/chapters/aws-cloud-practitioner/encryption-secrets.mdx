## 🧠 افهم: تلات أماكن الداتا ممكن تتسرق منها

داتا زباين دُكّان (أسماء، تليفونات، عناوين) ممكن تتسرق في تلات أماكن:

1. **وهي ماشية على الشبكة:** حد بيتنصت على الواي فاي ← **encryption in transit** (HTTPS/TLS).
2. **وهي متخزنة:** هارد اتسرق أو backup اتسرب ← **encryption at rest**.
3. **الباسورد اللي بيفتح الداتا نفسها:** باسورد الـ database مكتوب في الكود ومرفوع على GitHub ← **secrets management**.

التشفير مالوش لازمة لو المفتاح مرمي جنب الداتا. عشان كده AWS عندها خدمات بتحمي **المفاتيح** و**الأسرار** نفسها.

<Hl c="g">KMS بيدير مفاتيح التشفير ومحدش بيشوف المفتاح نفسه. Secrets Manager بيخزن الباسوردات ويغيّرها لوحده. ACM بيدّيك شهادات HTTPS مجانية للخدمات المتكاملة.</Hl>

<Box type="story" icon="🔐" title="الخزنة ومفتاحها">

- **Encryption at rest** = الفلوس في **خزنة** مش على الترابيزة.
- **Encryption in transit** = الفلوس بتتنقل في **عربية مصفّحة** مش في شنطة.
- **KMS** = **بنك** ماسك مفاتيح الخزن. إنت مش بتشيل المفتاح، بتطلب من البنك «افتح الخزنة دي» والبنك بيتأكد إنك مسموحلك ويسجّل الطلب.
- **Secrets Manager** = **خزنة صغيرة للأرقام السرية** بتغيّر الرقم كل شهر لوحدها وتبلّغ اللي محتاجه.

</Box>

1. الزبون بيتصل بـ **HTTPS** بشهادة من **ACM** ← in transit.

## 🔍 من جوه: الخدمات

### AWS KMS (Key Management Service)

- بيعمل ويخزن مفاتيح التشفير في **HSMs**، و**المفتاح الأساسي عمره ما بيخرج من KMS** بشكل مكشوف.
- أنواع المفاتيح:
  - **AWS managed keys:** الخدمة بتعملها ليك (زي `aws/s3`). سهل ومفيش تحكم كتير.
  - **Customer managed keys:** إنت بتعملها وتتحكم في الـ **key policy** (مين يستخدمها)، والـ rotation، وتقدر تعطّلها.
- كل استخدام للمفتاح بيتسجل في **CloudTrail**.
- معظم الخدمات (S3، EBS، RDS، DynamoDB…) بتشفّر بـ KMS بضغطة.

### AWS CloudHSM

**HSM مخصص ليك لوحدك** (single-tenant). إنت اللي بتدير المفاتيح والمستخدمين بالكامل، وAWS مش بتقدر توصل للمفاتيح. للشركات اللي عندها متطلبات compliance صارمة (FIPS 140-3 Level 3 مثلًا، راجع الـ docs).

### AWS Secrets Manager

- بيخزن **أسرار**: باسوردات databases، API keys، tokens. مشفّرة بـ KMS.
- **Automatic rotation:** بيغير الباسورد كل فترة لوحده (متكامل مع RDS وغيره).
- التطبيق بيطلب السر وقت التشغيل بصلاحية IAM.

### SSM Parameter Store

جزء من Systems Manager. بيخزن إعدادات (`/dukkan/prod/feature-x=on`) وممكن أسرار (`SecureString` مشفّر بـ KMS). أرخص (فيه tier مجاني)، بس **مفيش rotation أوتوماتيك مدمج** زي Secrets Manager.

### AWS Certificate Manager (ACM)

بيدّيك **شهادات TLS/SSL** public **مجانية** للاستخدام مع ALB وCloudFront وAPI Gateway، و**بيجددها لوحده**. مش هتعرف تنزّل الـ private key بتاعتها لسيرفر عادي (في exportable certificates بشروط، راجع الـ docs).

## 🛠️ طبّق: طلّع باسورد دُكّان من الكود

⚠️ Secrets Manager بيتحاسب لكل secret في الشهر + الـ API calls (وفي فترة تجربة للـ secret الجديد). KMS customer managed key بيتحاسب شهريًا. امسحهم بعد الـ Lab.

**قبل:** في كود دُكّان:

```js
// @diff -
const db = connect({ user: "admin", password: "Dukkan@2026" });
```

1. **خزّن السر:**

```bash
aws secretsmanager create-secret --name dukkan/dev/db \
  --secret-string '{"username":"admin","password":"غيّرها-لحاجة-عشوائية"}'
```

2. **اقراه** (ده اللي التطبيق هيعمله بالـ SDK):

```bash
aws secretsmanager get-secret-value --secret-id dukkan/dev/db --query SecretString --output text
```

3. **بعد:** الكود بيقرا وقت التشغيل:

<File name="db.mjs">

```js
import { SecretsManagerClient, GetSecretValueCommand } from "@aws-sdk/client-secrets-manager";

const sm = new SecretsManagerClient({});
// الصلاحية جاية من الـ IAM role بتاع التطبيق، مش من keys في الكود
const { SecretString } = await sm.send(
  new GetSecretValueCommand({ SecretId: "dukkan/dev/db" })
);
const { username, password } = JSON.parse(SecretString);
// @diff +
const db = connect({ user: username, password });
```

</File>

4. **شوف التسجيل:** `CloudTrail` ← `Event history` ← `GetSecretValue`. **المتوقع:** كل قراية للسر متسجلة بمين قراها.
5. **فكّر:** الباسورد القديم `Dukkan@2026` كان في Git. نقله لـ Secrets Manager كفاية؟ **لأ**، لازم **تغيّره** لأنه اتسرب في الـ history.

🧹 **تنضيف:**

```bash
aws secretsmanager delete-secret --secret-id dukkan/dev/db --force-delete-without-recovery
```

## ⚖️ قارن: أنهي خدمة لأنهي سر؟

| | KMS | CloudHSM | Secrets Manager | Parameter Store | ACM |
| --- | --- | --- | --- | --- | --- |
| بيخزن | مفاتيح تشفير | مفاتيح في HSM ليك لوحدك | أسرار | إعدادات وأسرار | شهادات TLS |
| مين بيدير | AWS (وإنت بتتحكم في الصلاحيات) | **إنت بالكامل** | AWS | AWS | AWS |
| Rotation | للمفاتيح (اختياري) | إنت | **أوتوماتيك للأسرار** | لأ مدمج | **تجديد أوتوماتيك** |
| مثال | تشفير S3 وEBS | compliance صارم | باسورد RDS | `feature-flag`، URL | HTTPS على ALB |

| At rest | In transit |
| --- | --- |
| الداتا وهي متخزنة على الهارد أو في backup | الداتا وهي ماشية على الشبكة |
| KMS مع S3/EBS/RDS/DynamoDB | TLS/HTTPS، شهادات ACM |

<Box type="interview" title="الكلمات المفتاحية">

«create and manage encryption keys» ← **KMS**. «dedicated HSM»، «full control of keys»، «single-tenant» ← **CloudHSM**.
«rotate database credentials automatically» ← **Secrets Manager**. «store configuration values» ← **Parameter Store**.
«SSL/TLS certificates»، «HTTPS» ← **ACM**.

</Box>
