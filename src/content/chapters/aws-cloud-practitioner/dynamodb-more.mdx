## 🧠 افهم: مش كل داتا شكلها جدول بعلاقات

دُكّان عنده داتا شكلها مختلف:

- **سلة الزبون:** «هات سلة الزبون رقم 42». سؤال واحد بالمفتاح، ملايين المرات في اليوم، ولازم يرد في أجزاء من الثانية.
- **أكتر المنتجات مشاهدة:** بتتقري كل ثانية، ومش مشكلة لو قديمة دقيقة.
- **«الناس اللي اشتروا ده اشتروا كمان…»:** علاقات بين منتجات وزباين.

الـ relational database تقدر تعمل كل ده، بس مش دايمًا أحسن ولا أرخص اختيار. AWS عندها databases **متخصصة** (purpose-built) كل واحدة ممتازة في شكل معين.

<Hl c="b">DynamoDB = NoSQL key-value serverless: بتجيب العنصر بمفتاحه في مللي ثواني مهما كبر الجدول. وباقي الـ databases المتخصصة كل واحدة لشكل داتا: cache، documents، graph، time series.</Hl>

<Box type="story" icon="🧥" title="الأمانات في الفرح">

DynamoDB زي **شباك الأمانات في قاعة فرح**: بتدي الجاكت وتاخد رقم. لما ترجع بالرقم، الجاكت بيطلع في ثانية، سواء القاعة فيها ١٠٠ جاكت ولا مليون. بس لو سألت «هات كل الجواكت الزرقا»، الموظف هيلف على كله. يعني **السرعة جاية من إنك تسأل بالرقم**.

</Box>

## 🔍 من جوه: DynamoDB والباقيين

### DynamoDB بالتفصيل

- **Primary key:** يا إما **partition key** بس، يا إما **partition key + sort key** (زي `customerId` + `orderDate` عشان تجيب طلبات زبون مترتبة).
- **Serverless:** مفيش سيرفرات ولا versions ولا patches.
- **Capacity modes:** **On-demand** (بتدفع على كل read/write، مناسب لحمل مش معروف) أو **Provisioned** (بتحدد السعة، أرخص لحمل ثابت، وممكن مع auto scaling).
- **Global tables:** الجدول بيتنسخ على أكتر من Region وتكتب في أي واحدة.
- **DAX:** cache في الذاكرة قدام DynamoDB، يوصّل القراية لـ microseconds.
- **TTL:** بتمسح الـ items أوتوماتيك بعد وقت (السلة القديمة مثلًا).
- **Streams:** كل تغيير بيطلع event تقدر تشغّل بيه Lambda.

### الـ databases المتخصصة التانية

| الخدمة | شكل الداتا | مثال في دُكّان |
| --- | --- | --- |
| **ElastiCache** (Valkey، Redis OSS، Memcached) | cache في الذاكرة | أكتر المنتجات مشاهدة، الـ sessions |
| **MemoryDB** | in-memory database بتحفظ الداتا بشكل دائم | leaderboard لازم ميضيعش |
| **DocumentDB** | documents (متوافق مع MongoDB API) | كتالوج منتجات بخصائص مختلفة |
| **Neptune** | graph: عُقد وعلاقات | «اللي اشتروا ده اشتروا كمان» |
| **Keyspaces** | wide-column (متوافق مع Cassandra) | تطبيقات Cassandra موجودة |
| **Timestream** | time series | قراءات حساسات تلاجات المحل كل دقيقة |
| **OpenSearch Service** | بحث نصي وlogs | البحث في المنتجات بالاسم |

## 🛠️ طبّق: سلة دُكّان في DynamoDB

⚠️ DynamoDB on-demand بيتحاسب على كل read/write والتخزين. كام عملية للتجربة تكلفتها شبه صفر، وفي Free Tier للتخزين والسعة حسب حسابك.

1. **اعمل الجدول:**

```bash
aws dynamodb create-table --table-name dukkan-carts \
  --attribute-definitions AttributeName=customerId,AttributeType=S \
  --key-schema AttributeName=customerId,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST
```

2. **حط item:**

```bash
aws dynamodb put-item --table-name dukkan-carts --item '{
  "customerId": {"S": "42"},
  "items": {"L": [{"M": {"productId": {"S": "bread"}, "qty": {"N": "3"}}}]}
}'
```

3. **هاته بالمفتاح:**

```bash
aws dynamodb get-item --table-name dukkan-carts --key '{"customerId": {"S": "42"}}'
```

**المتوقع:** نفس الـ item راجع. ده الطريق السريع.

4. **فعّل TTL** على attribute اسمه `expiresAt` من تبويب `Additional settings`. أي سلة فيها `expiresAt` فات وقته هتتمسح لوحدها خلال وقت قصير.
5. **فكّر:** لو عايز «كل السلال اللي فيها جبنة»، هتعمل `Scan` على الجدول كله. ده بطيء ومكلف على جدول كبير. لو السؤال ده مهم، صمّم مفتاح أو **Global Secondary Index** ليه.

🧹 **تنضيف:**

```bash
aws dynamodb delete-table --table-name dukkan-carts
```

## ⚖️ قارن: اختار الـ database من شكل السؤال

| | RDS / Aurora | DynamoDB | ElastiCache |
| --- | --- | --- | --- |
| النوع | relational (SQL) | NoSQL key-value/document | cache في الذاكرة |
| Schema | ثابتة وجداول وعلاقات | مرنة، المفتاح بس ثابت | key-value |
| Joins وqueries مرنة | **ممتاز** | محدود، صمّم للأسئلة المعروفة | لأ |
| Scale | vertical + read replicas | أفقي تقريبًا من غير حد | بالـ nodes/shards |
| إدارة | مُدار بس فيه instances | serverless | مُدار (وفي serverless) |
| مناسب لـ | طلبات وحسابات ومعاملات | sessions، سلة، IoT، gaming | تسريع القراية |

<Box type="interview" title="كلمات بتشاور على الإجابة">

«key-value»، «serverless NoSQL»، «single-digit millisecond at any scale» ← **DynamoDB**.
«microsecond latency for DynamoDB» ← **DAX**.
«MongoDB compatible» ← **DocumentDB**. «graph»، «relationships»، «social network»، «fraud» ← **Neptune**.
«Cassandra» ← **Keyspaces**. «time series»، «IoT measurements» ← **Timestream**.
«caching»، «Redis»، «Memcached» ← **ElastiCache**.

</Box>
