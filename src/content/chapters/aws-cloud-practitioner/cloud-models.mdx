## سيناريو: شركة SaaS بتفصل بين ٣ احتياجات

شركة بتقدم نظام فواتير عندها deadline في ٦ أسابيع. عندها تطبيق قديم محتاج package على Linux، API جديدة الفريق عايز ينشرها بسرعة، وبريد مؤسسي لا يميز منتجها.

المطلوب مش اختيار اختصار واحد لكل الشركة. المطلوب تحديد مقدار التحكم ومسؤولية التشغيل لكل workload.

## Request flow: القرار خلال أسبوع

1. **اليوم ١:** التطبيق القديم يحتاج تحكم في الـ OS ونسخة package محددة؛ اختار الفريق `EC2` كنموذج قريب من IaaS.
2. **اليوم ٢:** الـ API الجديدة كود ويب عادي والفريق لا يريد إدارة provisioning يدويًا؛ اختار `Elastic Beanstalk` كنموذج platform مُدارة.
3. **اليوم ٣:** البريد وظيفة مكتملة؛ اشترت الشركة SaaS بدل بنائه.
4. **اليوم ٤:** راجع الأمن مين يعمل patch ومين يدير users والداتا في كل اختيار.
5. **اليوم ٥:** اتسجلت حدود كل خدمة وخطة الخروج منها قبل production.

النجاح إن كل فريق عارف الطبقات اللي يملك قرارها والطبقات اللي يديرها المزود. الفشل إن الفريق يختار «managed» ويفترض إن الأمان والبيانات بقوا مسؤولية غيره.

## سيناريو الاستضافة: fintech عليها شرط بيانات

شركة fintech عندها transaction system في data center قائم، وanalytics workload جديدة على AWS. الجهة الرقابية تشترط بقاء مجموعة بيانات في نطاق معين، والفريق محتاج ينقل النتائج المجمعة للـ Cloud كل ١٥ دقيقة.

<Grid2>
<Card title="Public Cloud" c={1}>

موارد من مزود عام زي AWS بعزل منطقي بين العملاء. كلمة public بتوصف نموذج المزود، مش إن بياناتك عامة.

</Card>
<Card title="Private Cloud" c={2}>

بيئة Cloud مخصصة لمؤسسة واحدة، غالبًا بتحكم وتشغيل ومسؤولية أكبر.

</Card>
<Card title="Hybrid Cloud" c={3}>

ربط data center أو private environment بخدمات Public Cloud وتوزيع الـ workloads والداتا بينهم.

</Card>
<Card title="Multicloud" c={4}>

استخدام خدمات من أكتر من cloud provider. ممكن يكون مقصودًا أو نتيجة فرق واحتياجات مختلفة.

</Card>
</Grid2>

في السيناريو، ربط الـ data center بـ AWS هو `hybrid`. لو الشركة استخدمت AWS ومزود Cloud تاني من غير بيئة محلية، ده `multicloud`. الاتنين ممكن يجتمعوا، لكنهم مش مترادفين.

## مقارنة قريبة

- **Service model** يجاوب: مين يدير أي طبقة؟
- **Deployment model** يجاوب: الموارد مستضافة فين وتحت أي نموذج؟
- **Hybrid** يربط on-premises/private مع public cloud.
- **Multicloud** يستخدم أكتر من cloud provider؛ مش شرط يكون فيه on-premises.

## 🧪 تمرين اختيار

شركة media عندها: بريد جاهز، API خاصة محتاجة نشر سريع، transcoder قديم محتاج OS محدد، وأرشيف لازم يفضل on-premises مؤقتًا. اختار لكل واحدة service model وdeployment model، واكتب مسؤوليتين على الشركة وعلامة نجاح بعد شهر.

<Box type="tip" title="سؤال الامتحان">

دور على مقدار التحكم ومين مسؤول عن التشغيل. لو المؤسسة عايزة تتحكم في OS، فكّر في IaaS. لو عايزة تستخدم برنامج مكتمل، فكّر في SaaS.

</Box>
