## 🧠 افهم: فين نحط ١٠٠ ألف صورة منتج؟

دُكّان عنده صور منتجات، وفواتير PDF، وbackups. لو حطيتهم على هارد EBS:

- الهارد ليه حجم، ولازم تكبّره كل شوية.
- مربوط بسيرفر واحد في AZ واحدة.
- عشان الزبون يشوف الصورة لازم السيرفر يقدّمها.

**Amazon S3 (Simple Storage Service)** حاجة مختلفة: مخزن **objects** (ملفات) من غير حد للحجم الكلي، بتوصله بـ HTTP من أي مكان بالصلاحيات، والداتا بتتنسخ أوتوماتيك على أكتر من AZ. بتدفع على اللي خزّنته فعلًا، وعلى الطلبات، وعلى الداتا اللي بتخرج.

<Hl c="y">S3 = buckets جواها objects. كل object ليه key (اسمه الكامل) وداتا وmetadata. مصمم لمتانة عالية جدًا (11 nines)، والأصل إن كل حاجة فيه private.</Hl>

<Box type="story" icon="📦" title="مخزن الأمانات">

S3 زي **مخزن أمانات** ضخم. بتسلّم الشنطة (object) وتاخد إيصال عليه رقم (key)، وتحطها في دولاب باسمك (bucket). مش بتفتح الشنطة وتعدّل حاجة جواها، لو عايز تغير بتسلم شنطة جديدة بنفس الرقم.

والدواليب أنواع: دولاب قريب على الباب للحاجات اللي بتطلبها كل يوم (غالي شوية)، ومخزن في البدروم للحاجات اللي بتطلبها مرة في السنة (رخيص، بس بياخد وقت عشان يطلّعها).

</Box>

## 🔍 من جوه: الحاجات اللي لازم تعرفها

### Bucket وobject وkey

- **Bucket:** اسمه **unique على مستوى العالم كله** (مش حسابك بس)، وبيتعمل في Region.
- **Object:** ملف لحد **5 TB**. فوق ١٠٠ ميجا استخدم multipart upload.
- **Key:** الاسم الكامل زي `products/2026/42.jpg`. الـ `/` بتبان كـ folders في الـ console، بس فعليًا هي جزء من الاسم.

### Storage classes

| الـ class | مناسب لـ | ملاحظة |
| --- | --- | --- |
| S3 Standard | داتا بتتقري كتير | الافتراضي |
| S3 Intelligent-Tiering | مش عارف الـ pattern | بينقل الـ objects بين tiers لوحده حسب الاستخدام |
| S3 Standard-IA | بتتقري قليل بس محتاجها فورًا | تخزين أرخص، والقراية عليها رسوم |
| S3 One Zone-IA | زي IA بس في AZ واحدة | أرخص، لداتا تقدر تعيد عملها |
| S3 Express One Zone | أسرع أداء ممكن | AZ واحدة، لأحمال محتاجة latency قليل جدًا |
| S3 Glacier Instant Retrieval | أرشيف بتحتاجه فورًا نادرًا | مللي ثواني |
| S3 Glacier Flexible Retrieval | أرشيف | الاسترجاع من دقايق لساعات |
| S3 Glacier Deep Archive | أرشيف طويل جدًا | أرخص حاجة، الاسترجاع ساعات |

**Lifecycle rules** بتنقل الـ objects بين الـ classes أو تمسحها أوتوماتيك بعد مدة.

### الحماية

- **Block Public Access:** مفعّل افتراضيًا على الـ buckets الجديدة. سيبه مفعّل إلا لو عندك سبب واضح جدًا.
- **Bucket policy:** resource-based policy على الـ bucket نفسه بتحدد مين يعمل إيه.
- **Encryption:** كل الـ objects الجديدة بتتشفّر افتراضيًا (SSE-S3)، وتقدر تستخدم مفاتيح KMS.
- **Versioning:** بيحتفظ بكل نسخة من الـ object. لو حد مسح أو كتب فوق ملف بالغلط، ترجع للنسخة القديمة.
- **Presigned URL:** لينك مؤقت بيسمح لحد يرفع أو ينزّل object معين لمدة محددة من غير ما يبقى عنده صلاحيات AWS.

### حاجات تانية مفيدة

**Static website hosting** (موقع HTML/CSS/JS من غير سيرفر)، **Replication** لـ bucket في Region تانية، **S3 Transfer Acceleration** لرفع أسرع من مسافات بعيدة، و**S3 Object Lock** لملفات ممنوع تتمسح لمدة (compliance).

## 🛠️ طبّق: bucket لصور دُكّان

⚠️ S3 بيتحاسب على التخزين والطلبات. ملفات صغيرة للتجربة تكلفتها شبه صفر، بس امسحها.

1. **اعمل bucket** (الاسم لازم يبقى unique، ضيف رقم):

```bash
aws s3 mb s3://dukkan-images-<رقم-عشوائي> --region eu-central-1
```

2. **ارفع صورة** وجرب تفتحها من لينكها المباشر:

```bash
aws s3 cp ./bread.jpg s3://dukkan-images-<رقم>/products/bread.jpg
```

افتح `Object URL` من الـ console. **المتوقع:** `AccessDenied`. ده كويس: الـ bucket private.

3. **اعمل لينك مؤقت** لمدة ٥ دقايق:

```bash
aws s3 presign s3://dukkan-images-<رقم>/products/bread.jpg --expires-in 300
```

افتح اللينك. **المتوقع:** الصورة تفتح. استنى ٥ دقايق وافتحه تاني: هيرفض.

4. **فعّل versioning** وارفع نفس الملف تاني بصورة مختلفة. من `Show versions` هتلاقي النسختين.
5. **اعمل lifecycle rule:** `Management` ← `Create lifecycle rule` ← prefix `invoices/` ← انقل لـ `Standard-IA` بعد ٣٠ يوم، و`Glacier Flexible Retrieval` بعد ١٨٠ يوم.

🧹 **تنضيف:** فضّي الـ bucket (بكل الـ versions) وامسحه:

```bash
aws s3 rb s3://dukkan-images-<رقم> --force
```

لو الـ versioning مفعّل، `--force` ممكن مايمسحش الـ versions القديمة. امسحها من الـ console بـ `Empty`.

## ⚖️ قارن: S3 ضد باقي التخزين

| | S3 | EBS | EFS |
| --- | --- | --- | --- |
| النوع | object | block | file |
| بتوصله إزاي | HTTP API | متركّب كهارد في instance | متركّب كفولدر في سيرفرات كتير |
| الحجم | مفيش حد كلي | بتحجز حجم | بيكبر لوحده |
| مناسب لـ | صور، فيديو، backups، data lake، static sites | OS وdatabase على EC2 | ملفات مشتركة |
| بتعدّل جزء من الملف؟ | لأ، بترفع object كامل | أيوه | أيوه |

<Box type="interview" title="أسئلة الـ storage classes">

«access patterns unknown or changing» ← **Intelligent-Tiering**.
«infrequently accessed but needs millisecond access» ← **Standard-IA** (أو Glacier Instant Retrieval لو أرشيف).
«lowest cost, retrieval within hours is fine» ← **Glacier Deep Archive**.
«can be recreated, single AZ is fine» ← **One Zone-IA**.

</Box>
