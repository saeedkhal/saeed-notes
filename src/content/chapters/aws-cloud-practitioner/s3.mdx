## المثال الأول: صور منتجات متجر

متجر عنده `8 مليون` صورة، ويضيف `120 GB` يوميًا. صور آخر `30 يوم` عليها traffic عالي، وبعد `180 يوم` نادرًا ما تُطلب، لكن فريق compliance محتاج يحتفظ بالأصل `7 سنين`.

١. التطبيق يرفع الأصل إلى bucket خاصة تحت key زي `products/tenant-42/2026/11/id.jpg`.
٢. S3 event يبدأ thumbnail pipeline؛ الناتج يتكتب في prefix مختلف.
٣. CloudFront يقدّم النسخ العامة، والـ bucket نفسها تفضل مع Block Public Access وسياسة origin مناسبة.
٤. Lifecycle تنقل objects حسب العمر، وretention policy المعتمدة تمنع الحذف المبكر لو المتطلب قانوني.
٥. Versioning وreplication يتصمموا للفشل المطلوب، مش يتفعلوا كبديل تلقائي للـ backup.

## نموذج الداتا

S3 <En>object storage</En>: الـ object عبارة عن bytes وmetadata داخل bucket وتحت key فريد. `assets/2026/logo.png` key واحدة؛ الـ slash مش folder حقيقية. S3 إقليمي، واسم bucket فريد عالميًا داخل AWS partition.

تعديل جزء صغير من object مش زي block storage؛ غالبًا تكتب object جديدة. عشان كده S3 ممتاز للصور، logs، backups، static assets وdata lakes، لكنه مش disk لنظام تشغيل.

## Versioning وقت incident

الساعة `10:00` deployment غلط overwrite لـ `50,000` object. مع Versioning، كل overwrite يعمل version جديدة. الساعة `10:08` الفريق يوقف الكاتب، يحدد version IDs السابقة، ويبدأ restore منظم. Delete عادي على bucket versioned يضيف delete marker بدل إزالة كل versions.

النجاح: تقدر ترجع نسخة سابقة. المقابل: كل version تستهلك storage، وحذف bucket يتطلب تنظيف versions وdelete markers. Lifecycle للـ noncurrent versions لازم يطابق retention المطلوب.

## Storage class قرار اقتصادي

- `S3 Standard`: access متكرر وresilience عبر عدة AZs.
- `S3 Intelligent-Tiering`: نمط غير متوقع؛ automation مع رسوم/شروط راجعها.
- `Standard-IA`: access قليل مع retrieval سريع، لكن minimum duration/size ورسوم retrieval ممكن تأثر.
- `One Zone-IA`: AZ واحدة؛ مناسب فقط لداتا قابلة لإعادة الإنشاء.
- فئات `S3 Glacier`: archive من instant retrieval لمدد أبطأ في Flexible Retrieval وDeep Archive.

لو `10 TB` تُسترجع بالكامل كل شهر، سعر التخزين الأقل ممكن يخسر قدام retrieval. احسب storage + requests + retrieval + transfer، وراجع أسعار أكتوبر 2026 للـ Region.

## Lifecycle مش Replication

`Lifecycle` تغيّر class أو تنهي objects حسب قواعد زمنية. `SRR` تنسخ داخل Region، و`CRR` إلى Region أخرى. Replication تحتاج Versioning على المصدر والوجهة وصلاحيات مناسبة، وقد يكون لها lag وتكلفة.

## 🧪 تمرين: retention وتكلفة وفشل

صمم bucket لفيديوهات حجمها `40 TB`: `15%` عليها مشاهدة يومية، `70%` لا تُطلب بعد شهر، و`15%` لازم تفضل قابلة للاسترجاع خلال ساعات لمدة `5 سنين`. اكتب lifecycle، أثر versioning، وهل تحتاج CRR. بعدها افترض إن operator حذف prefix الساعة `09:30`: اكتب timeline للاستعادة ونقطة تمنع تكرار الحذف.
