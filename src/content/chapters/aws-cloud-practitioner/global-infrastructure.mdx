## سيناريو Production: منصة فيديو في ٣ أسواق

منصة media مستخدميها في القاهرة والرياض وفرانكفورت. الـ API والداتا الأساسية لازم تشتغل في Region واحدة كبداية، الفيديوهات لازم توصل بسرعة عالميًا، والخدمة لازم تكمل لو موقع تشغيل واحد تعطل.

الفريق قارن `eu-central-1` و`me-south-1` حسب latency مقاس، إقامة البيانات، توفر transcoding feature، والتكلفة. القرار مش «أقرب نقطة على الخريطة»؛ القرار مجموعة متطلبات موثقة.

## Timeline: طلب فيديو واحد

1. **00 ms:** المستخدم يطلب صورة الغلاف؛ DNS يوجهه للعنوان المناسب.
2. **25 ms:** CloudFront edge location قريبة تلاقي الصورة في الـ cache وترجعها من غير زيارة الـ origin.
3. **طلب API:** يروح للـ Region المختارة لأن التطبيق الإقليمي شغال هناك.
4. **داخل الـ Region:** load balancer يوجه الطلب لنسخة سليمة في `AZ-b` بعد ما health check اكتشف مشكلة في `AZ-a`.
5. **بعد 90 ثانية:** Auto Scaling يعوض السعة الناقصة حسب التصميم.

النجاح إن عطل AZ ما يوقفش الخدمة، وإن الـ latency والداتا يحققوا المتطلبات. الفشل إن كل الطبقات تعتمد على AZ واحدة أو إن الفريق يفترض إن خدمة ما Multi-AZ من غير توثيق.

## Region: نطاق القرار الجغرافي

الـ Region منطقة جغرافية مستقلة نسبيًا فيها عدة Availability Zones. أسماء زي `eu-west-1` و`me-south-1` بتحدد مكان تشغيل موارد إقليمية كتير. الخدمات والمزايا والأسعار مش متطابقة في كل Region.

## Availability Zone: عزل قريب

كل Region فيها عدة AZs؛ الـ AZ موقع أو مجموعة data centers معزولة ماديًا عن AZs التانية ومتوصلة بزمن وصول منخفض. توزيع طبقات التطبيق على أكتر من AZ يقلل نقطة الفشل الواحدة.

مش كل خدمة بتطلب منك تختار AZ. خدمات مُدارة كتير تخفي التفاصيل أو توزع مكوناتها حسب إعدادك. لازم تقرأ سلوك الخدمة بدل ما تفترض إنها Multi-AZ.

<Hl c="g">Region يديك نطاق جغرافي، وAZ تديك عزل أعطال جوه النطاق ده.</Hl>

## Edge location مش AZ

Edge locations نقاط قريبة من المستخدمين بتخدم شبكات زي Amazon CloudFront وRoute 53. هدفها توصيل المحتوى أو استقبال الطلبات من مكان أقرب؛ مش هي المكان المعتاد اللي تشغّل فيه EC2.

الـ API ممكن تكون في Region واحدة، بينما الصور والفيديوهات الثابتة تتخزن مؤقتًا عند edge locations أقرب للمشاهدين.

## Local Zone للحساسية الشديدة للـ latency

AWS Local Zones امتداد لRegion بيحط خدمات مختارة قرب تجمع سكاني أو صناعي. بتستخدمها لما workload محتاج latency منخفض جدًا ومفيش Region قريبة كفاية.

هي امتداد للـ Region الأم وليست بديلًا عامًا عنها، والخدمات المتاحة فيها محدودة. تستخدمها workload مثل rendering تفاعلي أو media production محتاج latency شديد الانخفاض بعد قياس فعلي.

## مقارنة المفاهيم

- **Region:** نطاق جغرافي لتشغيل موارد إقليمية واتخاذ قرار data residency.
- **Availability Zone:** نطاق عزل أعطال داخل Region مع اتصال منخفض الـ latency.
- **Edge location:** نقطة قريبة لتوصيل المحتوى أو خدمات edge؛ مش مكان EC2 المعتاد.
- **Local Zone:** امتداد بخدمات مختارة قرب تجمع معين لاحتياج latency خاص.
- **Multi-Region:** تصميم لاستمرارية أو وصول عالمي أوسع؛ أعلى تكلفة وتعقيدًا من Multi-AZ غالبًا.
