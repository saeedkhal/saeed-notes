## السؤال الأول: الداتا واقفة ولا ماشية؟

قبل اسم الخدمة، اسأل: الداتا ملفات في `S3`؟ ولا أحداث جاية دلوقتي؟ ولا جداول تحليلية كبيرة؟ ولا المطلوب شاشة للإدارة؟

<Box type="story" title="بوابة المدرسة">

أرشيف حضور السنة في مخزن، لكن دخول الطلبة من البوابة stream لحظي. أمين المخزن، عامل النظافة، والمراقب اللي قدام البوابة كل واحد شغلته مختلفة؛ خدمات الـ analytics كده برضه.

</Box>

<Hl c="g">اختار من نوع الشغل: query، prepare، process، stream، warehouse، visualize، أو search.</Hl>

## Athena: SQL من غير سيرفر

`Amazon Athena` بيعمل queries بـ SQL مباشرة على بيانات في `S3` ومصادر مدعومة. هو `serverless`، والدفع غالبًا حسب حجم الداتا اللي اتعملها scan.

- سؤال سريع أو ad-hoc على logs وملفات: Athena.
- `Parquet` وpartitioning يقللوا الداتا المقروءة والتكلفة.
- هو مش database تشغيلية للتطبيق، ومش أداة ETL أساسية.

## Glue: الفهرس ومطبخ التجهيز

`AWS Glue` خدمة data integration و`ETL`: تكتشف schema بـ crawlers، تحفظ metadata في `Glue Data Catalog`، وتنضف وتحول الداتا.

Athena وEMR وRedshift Spectrum يقدروا يستفيدوا من الـ Catalog. لو السؤال فيه **discover schema** أو **catalog** أو **transform data**، فكّر في Glue.

## EMR: مصنع الـ Big Data

`Amazon EMR` يشغّل frameworks مفتوحة زي Spark وHive وFlink لمعالجة أحجام ضخمة. عندك اختيارات managed clusters و`EMR Serverless` حسب الـ workload.

<Box type="idea" title="Glue ولا EMR؟">

Glue مناسب لـ ETL مُدار وتجهيز الداتا بأقل إدارة. EMR مناسب لما الفريق محتاج ecosystem وأدوات open source وتحكم أوسع في معالجة Big Data.

</Box>

## Kinesis: الأحداث وهي داخلة

`Amazon Kinesis` عيلة للـ real-time streaming:

- `Kinesis Data Streams`: تستقبل stream وتسيب consumers يعالجوه.
- `Amazon Data Firehose`: توصل streams لوجهات زي S3 وRedshift وOpenSearch بإدارة أقل.
- `Kinesis Video Streams`: فيديو وبيانات مرتبطة بيه.
- `Managed Service for Apache Flink`: معالجة stream بكود Flink.

مثال: عدد الطلبة اللي عدّوا من البوابة آخر دقيقة، مش تقرير آخر السنة.

## Redshift: مخزن التحليلات

`Amazon Redshift` data warehouse للـ SQL analytics المعقدة على بيانات كبيرة. ينفع provisioned أو serverless، ومصمم لتحليل مجموعات بيانات، مش لتسجيل كل click كـ transaction صغير.

لو الإدارة بتجمع بيانات الحضور والمصروفات والنتائج وعايزة تقارير متكررة ومعقدة: Redshift أقرب من Athena.

## QuickSight: الرسمة مش المخزن

`Amazon QuickSight` خدمة BI للـ dashboards والـ visualizations، وتوصل لمصادر زي Athena وRedshift وRDS. هي تعرض insight؛ مش مكان تخزين الداتا ولا محرك ETL.

<Box type="warn" title="الاسم بيتغير">

في صفحات AWS الحديثة ممكن تقابل اسم `Amazon Quick` ضمن تجربة أعمال أوسع، بينما مواد CLF-C02 وأسئلة كتير ما زالت تقول `Amazon QuickSight`. راجع دليل الامتحان والـ docs وقت الحجز.

</Box>

## OpenSearch: دور وابحث في logs

`Amazon OpenSearch Service` خدمة مُدارة للبحث النصي، log analytics، monitoring، وclickstream analytics شبه اللحظي. لو المطلوب search box في portal أو استكشاف logs بسرعة، دي إشارة قوية.

هو مش بديل عام لـ Redshift: البحث في documents والـ logs غير SQL warehouse للتقارير المؤسسية.
