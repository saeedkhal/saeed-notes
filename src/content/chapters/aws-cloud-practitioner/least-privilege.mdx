## 🧠 افهم: الضرر على قد الصلاحية

سارة كانت مستعجلة، فإدّت تطبيق دُكّان policy فيها `"Action": "*"` و`"Resource": "*"`. الموقع اشتغل. بعد شهر حد لقى ثغرة في مكتبة رفع الصور ووصل للتطبيق. ولأن التطبيق عنده كل الصلاحيات، المهاجم:

- مسح الـ database،
- وشغّل سيرفرات تعدين عملات بـ ٤ آلاف دولار في يومين.

لو التطبيق كان مسموحله **بس** يرفع صور في bucket واحد، أقصى ضرر كان صور زيادة في الـ bucket.

<Hl c="p">Least privilege = كل هوية تاخد أقل صلاحيات تكفي شغلها، على أقل موارد، لأقل وقت. الاختراق هيحصل، المهم الضرر يبقى صغير.</Hl>

<Box type="story" icon="🧹" title="مفتاح عامل النظافة">

عامل النظافة في الشركة محتاج يدخل المكاتب بعد الساعة ٥. مش محتاج مفتاح الخزنة، ولا يدخل الساعة ٢ الفجر، ولا ياخد المفتاح معاه البيت. لو كارته ضاع، أقصى حاجة حد يدخل مكتب فاضي بالليل.

**أقل أبواب، أقل ساعات، والكارت بيترجع.** ده بالظبط least privilege + temporary credentials.

</Box>

## 🔍 من جوه: إزاي تضيّق الصلاحية؟

### خمس أسئلة لكل policy

1. **مين؟** هوية واحدة محددة، مش «الكل».
2. **إيه الـ actions؟** `s3:PutObject` بس، مش `s3:*`.
3. **على إيه؟** `arn:aws:s3:::dukkan-images/*`، مش `*`.
4. **بشروط إيه؟** `Condition` زي إن الطلب لازم يكون من شبكة معينة أو عليه MFA.
5. **لحد إمتى؟** credentials مؤقتة بدل دايمة.

### مثال: ضيّق الـ policy

<File name="before-vs-after.json">

```jsonc
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      // @diff -
      "Action": "*",
      // @diff +
      "Action": ["s3:PutObject"],
      // @diff -
      "Resource": "*"
      // @diff +
      "Resource": "arn:aws:s3:::dukkan-images/uploads/*"
    }
  ]
}
```

## 🛠️ طبّق: نضّف صلاحيات دُكّان

⚠️ كل الأدوات دي مجانية (Access Analyzer للـ external access مجاني، وبعض أنواع التحليل المتقدمة ليها سعر، راجع الـ docs).

1. **طلّع credential report:**

```bash
aws iam generate-credential-report
aws iam get-credential-report --query Content --output text | base64 -d > report.csv
```

افتح الملف ودوّر على: users من غير MFA، أو access keys عمرها أكبر من ٩٠ يوم.

2. **افحص Last accessed** للـ role بتاع التطبيق. لو ظاهر إنه بيستخدم `S3` بس، امسح أي صلاحية تانية.
3. **فعّل IAM Access Analyzer** في الـ Region: `IAM` ← `Access analyzer` ← `Create analyzer` ← zone of trust = حسابك. **المتوقع:** قايمة findings لو في bucket أو role متاح من برّه.
4. **حوّل التطبيق لـ role:** لو في access keys محطوطة في ملف `.env` على السيرفر، استبدلها بـ instance role (فصل ١٢)، وبعدين عطّل الـ keys القديمة.

🧹 لو عملت analyzer للتجربة بس، امسحه.

## ⚖️ قارن: مين بيعمل إيه؟

| الأداة | بتجاوب على | مثال |
| --- | --- | --- |
| IAM policies | مسموح ولا لأ؟ | Allow `s3:PutObject` |
| AWS STS | إزاي آخد credentials مؤقتة؟ | `AssumeRole` |
| IAM Access Analyzer | مين برّه يقدر يوصل؟ وإيه الصلاحيات اللي مش مستخدمة؟ | bucket متشارك مع حساب غريب |
| Last accessed | الهوية دي استخدمت الخدمة دي إمتى؟ | آخر استخدام لـ EC2 من ٢٠٠ يوم |
| Credential report | حالة كل الـ users | مين من غير MFA |
| CloudTrail (فصل ٢٩) | مين عمل إيه وإمتى فعلًا؟ | سارة مسحت bucket الساعة ٣ |
