## CloudWatch: نبض التشغيل

الـ <En>metric</En> رقم عبر الزمن، زي Lambda errors أو API latency. الـ log تفاصيل أحداث التطبيق. الـ alarm يراقب metric أو expression ويغيّر حالته وقد يشغّل action.

الـ alarm مش ضمان إن السبب معروف؛ هو إشارة للتحقيق. اختار threshold ومدة يقللوا الضوضاء.

## CloudTrail: كاميرا الـ API

CloudTrail يسجل نشاط API من Console وCLI وSDK وخدمات AWS: principal، وقت، source IP، request وغيرها. مناسب لسؤال "مين حذف الـ bucket policy؟".

مش بديل للـ application logs، ومش هو أداة CPU monitoring.

## Config: صورة الإعداد عبر الزمن

AWS Config يسجل تكوين الموارد المدعومة وتغيّراته. Config Rules تقيّم compliance، مثل "هل الـ bucket يمنع public access؟".

Config يقول إن الحالة غير compliant؛ مش معناه إنه يمنع التغيير تلقائيًا أو يصلحه إلا لو ربطت remediation مناسبة.

## X-Ray: رحلة الطلب

X-Ray يجمع traces من تطبيق instrumented عشان يوضح أجزاء الطلب، latency والأخطاء بين services. لو API بطيئة بسبب call معين، trace تساعدك تحدده.

<Box type="story" icon="🏥" title="مستشفى المدرسة">

CloudWatch جهاز النبض، CloudTrail دفتر مين فتح باب غرفة الأدوية، Config صورة ترتيب الغرفة ومخالفتها للقواعد، وX-Ray أشعة تتبع المشكلة جوه الرحلة.

</Box>

## 🧪 تمرين ورقي آمن

صنّف الأسئلة: "CPU عالية"، "مين غيّر SG"، "هل bucket خالف rule"، "أنهي service أخّرت request". اكتب CloudWatch، CloudTrail، Config، X-Ray بالترتيب.

لو فعّلت trails أو Config recorders أو خزنت logs، قد تظهر تكاليف تخزين وتحليل وتسجيل. راجع Pricing وامسح التجارب؛ متوقفش audit production عشان التوفير.
