## 🧠 افهم: الطلب مستني كل حاجة تخلص

لما زبون يضغط «اطلب» في دُكّان، الكود بيعمل بالترتيب:

1. يحفظ الطلب.
2. يبعت إيميل تأكيد.
3. يبلّغ المخزن.
4. يبعت SMS للمندوب.

لو خدمة الإيميل بطيئة ٨ ثواني، **الزبون مستني ٨ ثواني**. ولو خدمة الـ SMS وقعت، **الطلب كله فشل**، رغم إن الطلب نفسه اتحفظ تمام. ده اسمه **tight coupling**: كل جزء مربوط بالتاني.

الحل: الكود يحفظ الطلب ويرمي **رسالة**: «في طلب جديد رقم 1001»، ويرد على الزبون فورًا. وكل خدمة تانية تاخد الرسالة وتشتغل على مهلها. ده **decoupling**.

<Hl c="b">SQS = طابور: الرسالة بتستنى لحد ما مستهلك يسحبها ويخلصها. SNS = ميكروفون: الرسالة بتتبعت فورًا لكل المشتركين. ومع بعض = fan-out.</Hl>

<Box type="story" icon="🧾" title="المطعم والمطبخ">

- **SQS** زي **حامل الأوردرات** في المطبخ: الجرسون بيعلّق الورقة ويرجع للزباين. الطباخ بياخد ورقة لما يفضى. لو الطباخ تعبان، الأوراق مستنية مش بتضيع. ولو جه طباخ تاني، بيسحبوا من نفس الحامل.
- **SNS** زي **ميكروفون المطعم**: «أوردر ترابيزة ٥ جاهز!». كل اللي بيسمع (الجرسون، الكاشير، المدير) بيعرف في نفس اللحظة. بس لو حد مش موجود، مش هيسمع.

</Box>

1. الـ API بيحفظ الطلب ويعمل **publish** لرسالة واحدة على **SNS topic**.
2. الـ topic بيبعت نسخة لكل **SQS queue** مشتركة فيه.
3. كل خدمة بتسحب من الطابور بتاعها **بسرعتها**. لو خدمة المخزن واقفة ساعة، رسايلها مستنية في الطابور.
4. رسالة فشلت ٥ مرات؟ بتتنقل لـ **dead-letter queue** عشان حد يبص عليها، بدل ما تفضل تلف.

## 🔍 من جوه: SQS وSNS بالتفصيل

### Amazon SQS

| | Standard | FIFO |
| --- | --- | --- |
| الترتيب | best-effort، ممكن يختلف | **بالظبط بالترتيب** (جوه message group) |
| التكرار | **at-least-once**: ممكن الرسالة توصل مرتين | **exactly-once processing** |
| الـ throughput | تقريبًا مفيش حد | أقل (وفي high-throughput mode) |
| مثال | إيميلات، تصغير صور | خصم من رصيد، خطوات لازم بالترتيب |

مفاهيم مهمة:

- **Polling:** المستهلك هو اللي **بيسحب** الرسايل. (Long polling بيقلل الطلبات الفاضية.)
- **Visibility timeout:** لما مستهلك ياخد رسالة، بتستخبى عن الباقيين فترة. لو خلص يمسحها. لو وقع قبل ما يخلص، بتظهر تاني لحد تاني.
- **Retention:** الرسالة بتستنى لحد **١٤ يوم** (الافتراضي ٤ أيام).
- **Dead-letter queue (DLQ):** طابور للرسايل اللي فشلت أكتر من عدد معين.
- علشان Standard ممكن يكرر، خلّي المستهلك **idempotent**: لو عالج نفس الطلب مرتين، النتيجة متتكررش.

### Amazon SNS

- **Pub/sub:** بتعمل **publish** على **topic**، وكل **subscribers** بيستلموا (**push**).
- أنواع المشتركين: SQS، Lambda، HTTP/S، email، SMS، mobile push.
- **Message filtering:** كل مشترك ياخد الرسايل اللي تهمه بس (مثلًا طلبات القاهرة بس).
- الرسالة **مش بتتخزن** لو المشترك مش متاح (SNS بيعمل retries، بس هو مش طابور). عشان كده بنحط SQS ورا SNS.

### Amazon MQ

broker مُدار لـ **ActiveMQ** و**RabbitMQ**. مناسب لو عندك تطبيقات قديمة بتستخدم protocols زي AMQP أو MQTT أو JMS ومش عايز تغيّر الكود. لتطبيقات جديدة على AWS، SQS/SNS غالبًا أبسط.

## 🛠️ طبّق: fan-out لطلبات دُكّان

⚠️ SQS وSNS ليهم Free Tier شهري كبير. التجربة دي هتستهلك كام request.

1. **اعمل topic وqueue:**

```bash
aws sns create-topic --name dukkan-order-created
aws sqs create-queue --queue-name dukkan-emails
```

2. **اشترك الـ queue في الـ topic:** أسهل من الـ console: افتح الـ queue ← `Subscribe to Amazon SNS topic` ← اختار الـ topic. (الـ console بيظبط الـ queue policy اللي بتسمح لـ SNS يكتب.)
3. **اعمل publish:**

```bash
aws sns publish --topic-arn arn:aws:sns:eu-central-1:<ACCOUNT_ID>:dukkan-order-created \
  --message '{"orderId":"1001","total":350}'
```

4. **اسحب من الطابور:**

```bash
aws sqs receive-message --queue-url <QUEUE_URL> --wait-time-seconds 10
```

**المتوقع:** الرسالة ظاهرة (جوه envelope بتاع SNS). لاحظ الـ `ReceiptHandle`.

5. **جرّب الـ visibility timeout:** شغّل `receive-message` تاني فورًا. مش هتلاقيها (مستخبية). استنى ٣٠ ثانية وجرب: هتظهر تاني، لأنك مسحتهاش. امسحها:

```bash
aws sqs delete-message --queue-url <QUEUE_URL> --receipt-handle <RECEIPT_HANDLE>
```

6. **(اختياري)** اعمل queue تانية `dukkan-warehouse` واشتركها. اعمل publish واحد ولاحظ إن الرسالة وصلت للطابورين.

🧹 **تنضيف:**

```bash
aws sqs delete-queue --queue-url <QUEUE_URL>
aws sns delete-topic --topic-arn <TOPIC_ARN>
```

## ⚖️ قارن: SQS ولا SNS ولا MQ؟

| | SQS | SNS | Amazon MQ |
| --- | --- | --- | --- |
| النموذج | queue (طابور) | pub/sub (topic) | message broker |
| الرسالة بتروح لـ | **مستهلك واحد** يعالجها | **كل** المشتركين | حسب الإعداد |
| مين بيتحرك | المستهلك **بيسحب** (pull) | SNS **بيزق** (push) | الاتنين |
| بيخزن الرسايل؟ | **أيوه**، لحد ١٤ يوم | لأ | أيوه |
| مناسب لـ | buffering، توزيع شغل، decoupling | إشعارات، fan-out | نقل تطبيقات بـ AMQP/MQTT/JMS |

<Box type="interview" title="الكلمات المفتاحية">

«decouple»، «buffer»، «queue»، «process asynchronously» ← **SQS**.
«notify multiple subscribers»، «pub/sub»، «fan-out»، «SMS/email notifications» ← **SNS**.
«existing app uses RabbitMQ / ActiveMQ / AMQP / MQTT» ← **Amazon MQ**.
«order matters»، «no duplicates» ← **SQS FIFO**.

</Box>
