## Amazon SQS: طابور شغل

<En>Amazon Simple Queue Service</En> طابور مُدار. المنتج يبعت message، والمستهلك يعمل poll ويعالجها ثم يحذفها بعد النجاح.

- الرسالة بتفضل لحد ما تتعالج أو تنتهي retention.
- كل message غالبًا تتسلم لمستهلك واحد من مجموعة العمال.
- Standard queue scalable جدًا وتسليمها at-least-once؛ صمّم المعالجة idempotent.
- FIFO queue تضيف ordering وخصائص إزالة التكرار ضمن حدودها.

الـ <En>visibility timeout</En> يخفي الرسالة مؤقتًا أثناء المعالجة. لو العامل فشل وممسحهاش، تظهر تاني.

## DLQ: أوضة الحالات الصعبة

<En>Dead-letter queue</En> تستقبل الرسائل اللي فشلت عدد مرات محدد. هي مش زر إصلاح؛ راقبها، افهم السبب، وصلّح، وبعدها قرر إعادة المعالجة.

## Amazon SNS: ميكروفون

<En>Amazon Simple Notification Service</En> خدمة publish/subscribe. الـ publisher ينشر على topic، وSNS تدفع نسخة لكل subscription مناسبة: SQS أو Lambda أو HTTP/S أو email وغيرها.

ده <En>fanout</En>: حدث "النتيجة ظهرت" يروح لطابور الإيميل وطابور التحليلات وخدمة إشعار ولي الأمر.

## الاتنين مع بعض

SNS topic تبعت لكل فريق SQS queue خاصة به. كده كل مستهلك ياخد نسخة ويعالج بسرعته، ولو واحد وقع الباقيين يكملوا.

التسليم قد يتكرر، فاستعمل message ID أو business key يمنع تسجيل نفس المصروف مرتين.
