## Route 53: دليل التليفونات

<En>Amazon Route 53</En> خدمة DNS بتترجم `portal.school.example` لوجهة يفهمها الجهاز. تقدر تسجل domain، تدير records، تعمل health checks، وتستخدم routing policies.

<Box type="story" icon="📒" title="دليل المدرسة">

Route 53 يقول للطالب عنوان البوابة، لكنه مش البوابة ولا بيخزن صفحة الموقع. زي دليل تليفونات يديك الرقم، مش هو اللي يرد على المكالمة.

</Box>

سياسات مشهورة في مستوى الامتحان:

- Simple: وجهة عادية.
- Weighted: توزّع بنسبة، مفيدة لتجربة إصدار.
- Latency-based: تبعت المستخدم للـ Region الأقل latency.
- Failover: primary وsecondary مع health check.
- Geolocation: قرار حسب مكان المستخدم.

## CloudFront: نسخة قريبة

<En>Amazon CloudFront</En> شبكة توصيل محتوى <En>CDN</En>. بتجيب المحتوى من origin زي S3 أو load balancer أو API، وتخزن المناسب في edge locations قريبة من المستخدمين.

لو cache hit، الرد يطلع من الـ edge. لو miss، CloudFront تروح للـ origin وترجع الرد حسب cache policy.

Edge location مش Region جديدة تشغّل فيها كل خدماتك؛ هي نقطة حضور لخدمات edge.

## Global Accelerator: طريق أسرع للتطبيق

<En>AWS Global Accelerator</En> يدي static anycast IPs ويدخل TCP/UDP traffic على شبكة AWS العالمية ويوجهه لـ healthy regional endpoints.

<Grid2>
<Card title="CloudFront" c={4}>

CDN وcache على مستوى HTTP/HTTPS، مناسب للصور والملفات والويب والـ APIs القابلة للتسريع.

</Card>
<Card title="Global Accelerator" c={5}>

توجيه شبكة لـ TCP/UDP، static IPs، وhealth-based regional routing. مش cache للمحتوى.

</Card>
</Grid2>

<Hl c="y">Route 53 يحل الاسم، CloudFront يقرّب نسخة محتوى، Global Accelerator يحسّن طريق الاتصال.</Hl>

ممكن تستخدم Route 53 قدام CloudFront أو Global Accelerator؛ الخدمات مش دايمًا بدائل مباشرة.

## سيناريو بوابة المدرسة

ملفات CSS وصور الكتب على S3 وCloudFront. Route 53 يربط اسم البوابة بتوزيعة CloudFront. لو عندنا لعبة امتحان realtime على TCP في Regions متعددة، Global Accelerator مرشح أقوى.
