## السؤال قبل اسم الخدمة

كل خدمة هنا بتشغّل كود، بس الفرق هو: <Hl c="y">مين شايل مسؤولية السيرفر، وإنت محتاج تحكّم قد إيه؟</Hl>

بوابة المدرسة ممكن تبدأ موقع صغير، وبعدها تكبر ويبقى فيها تسجيل وحضور ورفع واجبات. مفيش اختيار واحد صح لكل مرحلة.

<Box type="story" icon="🏫" title="أربع طرق تفتح بيها مقصف المدرسة">

`EC2` زي ما تستأجر المحل فاضي وتجيب معداته. `Lightsail` زي كشك جاهز بباقة بسيطة. `Elastic Beanstalk` ياخد وصفة الأكل ويجهّز التشغيل حواليها. `Lambda` زي عامل بيتنادى وقت الطلب ويمشي بعده.

</Box>

## الخريطة السريعة

<Grid2>
<Card title="EC2: تحكّم كامل" c={1}>

اختاره لما تحتاج نظام تشغيل، إعدادات شبكة، software مخصوص، أو workload شغّالة باستمرار. إنت مسؤول عن الـ OS والـ patching والـ scaling اللي ما عملتلوش automation.

</Card>
<Card title="Lightsail: بداية أبسط" c={2}>

مناسب لموقع بسيط أو prototype بواجهة موحّدة وباقات شهرية متوقعة نسبيًا. مرونته وتكاملاته أقل من تصميم AWS متقدم.

</Card>
</Grid2>

<Grid2>
<Card title="Elastic Beanstalk: ارفع التطبيق" c={3}>

لـ web app تقليدية: ترفع الكود، والخدمة تنشئ وتدير موارد زي EC2 والـ load balancing والـ scaling. لسه بتدفع ثمن الموارد اللي تحتها.

</Card>
<Card title="Lambda: شغّل عند الحدث" c={4}>

لكود قصير يبدأ بسبب request أو ملف أو message، من غير ما تدير server. الدفع حسب الاستخدام، لكن فيه quotas وحد أقصى للتنفيذ.

</Card>
</Grid2>

دي نقطة بداية، مش قانون. مثلًا Beanstalk نفسه بيستخدم موارد AWS تحت الغطا، وLambda ممكن تقف قدام API عن طريق API Gateway.

## طبّقها على بوابة المدرسة

- صفحة تعريف صغيرة وتجربة سريعة: `Lightsail` ممكن يقلل التعقيد.
- تطبيق المدرسة القديم محتاج package على Linux: `EC2` يدي تحكّم.
- Web app عادية والفريق مش عايز يجهّز البنية يدويًا: `Elastic Beanstalk`.
- تصغير صورة الواجب بعد رفعها: `Lambda` مناسبة لحدث قصير.

<Box type="warn" title="Managed مش معناها مجاني">

راجع صفحة التسعير والـ Region قبل أي تجربة. Beanstalk ملوش رسم خدمة منفصل عادةً، لكن EC2 والـ load balancer وباقي موارده بتتحاسب. Lightsail له bundles، وLambda لها حساب طلبات ومدة وموارد. مفيش هنا وعد بـ Free Tier.

</Box>

## 🧪 تمرين ورقة: أربع كروت

اكتب أربع حالات: «موقع ثابت بسيط»، «برنامج قديم محتاج root»، «API ويب عادية»، «معالجة ملف عند الرفع». قدام كل واحدة اختار خدمة، واكتب سبب من كلمتين: **تحكّم**، **بساطة**، **منصة**، أو **حدث**.

التمرين مفيهوش موارد ولا تكلفة. لو جرّبت من الـ Console بعدين، امسح كل resource أنشأتها وتأكد إن مفيش instance أو environment شغّال.

## قرار الامتحان

لو السؤال شدّد على full control فالمرشح `EC2`. لو قال simple bundled experience فكر في `Lightsail`. لو قال deploy web code مع إدارة البنية فكر في `Elastic Beanstalk`. لو قال event-driven ومن غير servers فكر في `Lambda`.

في الفصل الجاي هنفتح اختيار `EC2` ونفهم الـ AMI والـ instance من جوّه.
