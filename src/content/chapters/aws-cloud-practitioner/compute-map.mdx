## 🧠 افهم: «فين الكود هيشتغل؟»

كود دُكّان لازم يشتغل على حاجة. بس دُكّان فيه أنواع شغل مختلفة:

- **الموقع:** شغال ٢٤ ساعة ومستني زباين.
- **تصغير الصور:** بيحصل بس لما حد يرفع صورة، ثواني وخلاص.
- **تقرير المبيعات:** مرة في الليلة، بياخد ساعة.

لو حطيتهم كلهم على سيرفر شغال ٢٤ ساعة، هتدفع على وقت فاضي كتير. AWS عندها أكتر من طريقة لتشغيل الكود، والفرق بينها هو **إنت بتدير قد إيه** و**بتدفع إمتى**.

<Hl c="y">الـ compute على AWS ٣ عائلات: سيرفرات (EC2)، containers (ECS/EKS/Fargate)، وserverless (Lambda). كل ما تطلع لفوق بتدير أقل وتتحكم أقل.</Hl>

<Box type="story" icon="🍳" title="تعمل أكل إزاي؟">

- **EC2** = تأجر مطبخ فاضي. تجيب حلل وتوابل وتطبخ اللي إنت عايزه، وإنت اللي بتنضف.
- **Containers** = علب أكل جاهزة للتسخين. أي مطبخ فيه ميكروويف يسخّنها بنفس الطعم. **ECS/EKS** هما المسؤول عن ترتيب المطابخ، و**Fargate** إن المطبخ نفسه مش شغلتك.
- **Lambda** = دليفري. بتطلب الوجبة لما تجوع، وتدفع على الوجبة، ومفيش مطبخ خالص.

</Box>

## 🔍 من جوه: كل خدمة في سطرين

<Grid2>
<Card title="Amazon EC2" c={1}>

سيرفر افتراضي. تحكم كامل في الـ OS والـ software. إنت مسؤول عن الـ patches والـ scaling. **فصل ١٢.**

</Card>
<Card title="AWS Lambda" c={4}>

بترفع function، وبتشتغل لما حدث يحصل (request، ملف اترفع، رسالة). أقصى مدة للتشغيل الواحد **١٥ دقيقة**. بتدفع على عدد المرات والوقت. **فصل ١٥.**

</Card>
<Card title="ECS / EKS" c={2}>

بيشغّلوا ويرتبوا containers. **ECS** بتاع AWS وأبسط. **EKS** هو Kubernetes مُدار، لو فريقك بيستخدم Kubernetes أصلًا. **فصل ١٦.**

</Card>
<Card title="AWS Fargate" c={3}>

مكان تشغيل الـ containers **من غير ما تدير سيرفرات**، بيشتغل مع ECS أو EKS. بتدفع على CPU وmemory الـ container.

</Card>
<Card title="Elastic Beanstalk" c={5}>

PaaS: ترفع الكود (Node، Python، Java…) وهو بيعمل السيرفرات والـ load balancer والـ scaling ليك. وإنت لسه شايفهم وتقدر تعدّلهم.

</Card>
<Card title="Amazon Lightsail" c={1}>

سيرفر بسيط بسعر شهري ثابت ومعاه حاجات جاهزة (WordPress مثلًا). للمواقع الصغيرة والناس اللي عايزة بداية سهلة.

</Card>
</Grid2>

وفي كمان **AWS Batch** للشغل الـ batch الكبير (آلاف الـ jobs)، بيرتّب التشغيل على EC2 أو Fargate لوحده.

### سؤالين بيحسموا

1. **الشغل شكله إيه؟** شغال دايمًا؟ ولا بيحصل مع حدث وبيخلص بسرعة؟ ولا batch كبير؟
2. **الفريق عايز يدير قد إيه؟** محتاج OS معين؟ عندكم Kubernetes؟ ولا عايزين ترفعوا الكود وخلاص؟

## 🛠️ طبّق: وزّع شغل دُكّان

الـ Lab ورقي. اختار الخدمة لكل حالة، واكتب **ليه مش البديل**:

| الشغل | الاختيار | ليه مش البديل؟ |
| --- | --- | --- |
| الموقع (Node.js، ٢٤ ساعة) | Fargate (ECS) | Lambda ممكن، بس الموقع شغال دايمًا فمش هتوفر كتير، والفريق عنده Docker |
| تصغير صورة بعد الرفع | Lambda | سيرفر ٢٤ ساعة عشان شغل ٣ ثواني = هدر |
| تقرير الليل (ساعة) | ECS task مجدول على Fargate | Lambda أقصاها ١٥ دقيقة |
| برنامج المحاسبة (Windows + license) | EC2 | محتاج OS معين وتحكم كامل |
| مدونة عم حسن (WordPress) | Lightsail | سعر ثابت وبسيط، مش محتاج تعقيد |

**جرّب لوحدك:** لو التقرير بقى ٥ دقايق بس، هل Lambda بقت مناسبة؟ (أيوه، وغالبًا أرخص).

## ⚖️ قارن: الخريطة في جدول واحد

| | EC2 | Elastic Beanstalk | ECS/EKS + Fargate | Lambda | Lightsail |
| --- | --- | --- | --- | --- | --- |
| بتدير الـ OS؟ | **أيوه** | جزئيًا (هو بيظبطه) | لأ | لأ | أيوه (بسيط) |
| وحدة التشغيل | سيرفر | تطبيق | container | function | سيرفر |
| بتدفع على | وقت تشغيل السيرفر | الموارد اللي اتعملت | CPU/memory للـ task | المرات × المدة | شهري ثابت |
| أطول تشغيل | مفيش حد | مفيش حد | مفيش حد | ١٥ دقيقة | مفيش حد |
| مناسب لـ | تحكم كامل، legacy | رفع كود بسرعة | microservices، Docker | events، شغل متقطع | مواقع صغيرة |

<Box type="interview" title="كلمات بتشاور على الإجابة">

«run code without provisioning or managing servers» ← **Lambda**.
«containers without managing servers» ← **Fargate**.
«Kubernetes» ← **EKS**.
«upload code and AWS handles deployment, capacity, load balancing» ← **Elastic Beanstalk**.
«full control over the operating system» ← **EC2**.
«simple, predictable monthly price» ← **Lightsail**.

</Box>
