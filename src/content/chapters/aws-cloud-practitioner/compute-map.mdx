## سيناريو: ٤ workloads في شركة media

الفريق عنده برنامج transcoding قديم محتاج packages على Linux، موقع حملة صغير، API ويب عادية، وfunction تعمل thumbnail كل ما فيديو يترفع. كلهم «compute»، لكن شكل الحمل ومسؤولية التشغيل مختلفين.

<Hl c="y">قبل اسم الخدمة اسأل: محتاج OS كامل؟ الحمل مستمر ولا event؟ مين هيدير النشر والـ scaling؟</Hl>

## Timeline للقرار

1. **برنامج قديم:** يحتاج root access وdaemon مستمرة؛ يبدأ التقييم من `EC2`.
2. **موقع حملة:** فريق صغير واحتياج بسيط وباقة واضحة؛ `Lightsail` مرشح.
3. **API ويب:** الفريق يريد رفع الكود مع إدارة environment؛ `Elastic Beanstalk` مرشح.
4. **Thumbnail:** حدث قصير ومتقطع عند upload؛ `Lambda` مرشحة.
5. قبل production، الفريق يقارن quotas والتكلفة والـ observability وخطة الفشل.

النجاح إن الخدمة توافق شكل التشغيل ويعرف الفريق ما يديره. الفشل إن Lambda تختار لمهمة طويلة لا تناسب limits، أو Beanstalk تتعامل كأن الموارد تحتها مجانية.

<Box type="story" icon="🧭" title="الاختيار مش ترتيب جودة">

الخدمات مش مستويات من «ضعيف» إلى «قوي». EC2 تعطي تحكمًا أكبر مقابل تشغيل أكبر، وLambda تقلل إدارة السيرفر مقابل constraints مختلفة.

</Box>

دي نقطة بداية، مش قانون. مثلًا Beanstalk نفسه بيستخدم موارد AWS تحت الغطا، وLambda ممكن تقف قدام API عن طريق API Gateway.

## قارن القريب

- **EC2:** OS كامل، workloads مستمرة أو خاصة، وأنت تدير patching والتوسع اللي لم تؤتمته.
- **Lightsail:** تجربة مبسطة وباقات لمشاريع مباشرة؛ تكاملات ومرونة أقل من تصميم AWS أوسع.
- **Elastic Beanstalk:** platform لنشر web apps وتنسيق موارد مثل EC2 وELB وAuto Scaling؛ الموارد نفسها تُحاسب.
- **Lambda:** تنفيذ event-driven من غير إدارة servers، بمدة وquotas ونموذج تكلفة مختلف.

<Box type="warn" title="Managed مش معناها مجاني">

راجع صفحة التسعير والـ Region قبل أي تجربة. Beanstalk ملوش رسم خدمة منفصل عادةً، لكن EC2 والـ load balancer وباقي موارده بتتحاسب. Lightsail له bundles، وLambda لها حساب طلبات ومدة وموارد. مفيش هنا وعد بـ Free Tier.

</Box>

## 🧪 تمرين ورقة: أربع كروت

شركة SaaS عندها worker مستمر، microsite، API، ومعالجة PDF عند الرفع. لكل workload سجل مدة التنفيذ، pattern الحمل، احتياج OS، مسؤولية patching، وطريقة scaling، ثم اختار خدمة وعلامة نجاح بعد أسبوع. التمرين بلا resources.

## قرار الامتحان

لو السؤال شدّد على full control فالمرشح `EC2`. لو قال simple bundled experience فكر في `Lightsail`. لو قال deploy web code مع إدارة البنية فكر في `Elastic Beanstalk`. لو قال event-driven ومن غير servers فكر في `Lambda`.

في الفصل الجاي هنفتح اختيار `EC2` ونفهم الـ AMI والـ instance من جوّه.
