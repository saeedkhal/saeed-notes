## مين بيتوصل بمين؟

قبل اختيار خدمة، اسأل: شبكة كاملة؟ جهاز موظف؟ وصلة مخصصة؟ خدمة واحدة؟ ولا عشرات VPCs؟

## نوعين VPN

<Card title="Site-to-Site VPN" c={5}>

</Card>

</Box>

## Direct Connect

<En>AWS Direct Connect</En> وصلة شبكة مخصصة من موقعك إلى موقع Direct Connect، بعيدًا عن مسار الإنترنت العام. تدي تجربة أكثر ثباتًا وقد توفر bandwidth أعلى حسب الإعداد.

هي **مش تشفير تلقائيًا** لمجرد إنها خاصة؛ لو المتطلب encryption، صمّم طبقة تشفير مناسبة، مثل VPN فوق الاتصال حسب السيناريو.

التركيب بياخد تخطيط ووقت وتكلفة، فـ Site-to-Site VPN ممكن يبقى بداية أو backup.

## PrivateLink

<En>AWS PrivateLink</En> يعرّض **خدمة محددة** لمستهلكين عبر interface endpoints وعناوين خاصة، من غير فتح اتصال شبكي كامل أو تعريضها للـ public internet.

ده اختيار client-to-service، مش بديل لربط شبكتين بكل عناوينهم. ومفيد حتى لو CIDRs متداخلة.

## Transit Gateway

<En>AWS Transit Gateway</En> راوتر مركزي مُدار يربط VPCs وشبكات on-premises. بدل شبكة peering متشابكة، كل شبكة تتوصل بالـ hub.

## خريطة اختيار سريعة

- فرع كامل بسرعة إعداد معقولة: Site-to-Site VPN.
- موظف واحد أو فريق remote: Client VPN.
- وصلة مخصصة أكثر ثباتًا: Direct Connect.
- استهلاك API خاصة فقط: PrivateLink.
- ربط شبكات كتير بهيكل hub: Transit Gateway.

## 🧪 تمرين ورقي آمن

ارسم مقر المدرسة، موظف support، وثلاث VPCs. اختار لكل خط خدمة واكتب سببًا من كلمتين: "شبكة لشبكة"، "جهاز مستخدم"، "service only"، أو "hub".

التمرين ورقي. كل الخدمات دي ممكن تحمل رسوم اتصال، ساعات، endpoints، بوابات أو نقل بيانات؛ راجع Pricing قبل أي lab ونظّف كل resource.
