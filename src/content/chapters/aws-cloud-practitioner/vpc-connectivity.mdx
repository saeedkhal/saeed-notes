## 🧠 افهم: تلات أسئلة بعد ما الشبكة اتبنت

شبكة دُكّان اتعملت في الفصل اللي فات. دلوقتي في تلات أسئلة:

1. **مين يكلم مين جوه الشبكة؟** السيرفر يكلم الـ database على port `5432` بس، ومحدش تاني.
2. **إزاي الـ VPC دي تكلم VPC تانية؟** فريق الشحن عنده VPC لوحده في حساب تاني.
3. **السيرفرات في الـ private subnet محتاجة توصل لـ S3**، من غير ما تطلع على الإنترنت وتدفع NAT.

<Hl c="y">Security Group = firewall على الـ resource (stateful). NACL = firewall على الـ subnet (stateless). Peering وTransit Gateway بيوصلوا VPCs. والـ VPC endpoints بتوصلك لخدمات AWS من جوه الشبكة.</Hl>

<Box type="story" icon="🛂" title="أمن الكومباوند">

- **NACL** = **البوابة على مدخل العمارة**: بتفحص كل حد داخل **وكل حد خارج** لوحده، ومش فاكرة مين دخل. ممكن تقول «ممنوع فلان» صراحة.
- **Security Group** = **البواب على باب الشقة**: عنده ليستة المسموحلهم بس. ولو سمح لحد يدخل، بيفتكره وبيسيبه يخرج من غير ما يسأل.
- **VPC endpoint** = **ممر داخلي** من العمارة لمكتب البريد (S3) من غير ما تطلع الشارع خالص.

</Box>

## 🔍 من جوه: كل أداة بتعمل إيه

### Security Group ضد NACL

| | Security Group | Network ACL |
| --- | --- | --- |
| بيتحط على | الـ ENI (الـ instance، RDS، ALB…) | الـ subnet |
| State | **stateful**: الرد مسموح أوتوماتيك | **stateless**: لازم تسمح بالرد صراحة |
| القواعد | allow بس | allow **و** deny |
| الترتيب | كل القواعد بتتقيّم مع بعض | بالترتيب بالرقم، أول match بيكسب |
| الافتراضي | inbound ممنوع، outbound مسموح | الـ default NACL بيسمح بكل حاجة |
| أشهر استخدام | الحماية الأساسية لكل resource | طبقة إضافية: block لـ IP معين |

<Box type="tip" title="Security Group يشاور على Security Group">

بدل ما تكتب IPs، تقدر تقول «اسمح بـ port `5432` من **sg-app**». أي سيرفر جديد بـ sg-app هيتسمح له أوتوماتيك، حتى لو Auto Scaling طلّعه بـ IP جديد.

</Box>

### توصيل VPCs ببعض

<Grid2>
<Card title="VPC Peering" c={1}>

وصلة مباشرة بين VPCين (حتى في حسابات أو Regions مختلفة). **مش transitive**: لو A متوصلة بـ B وB بـ C، الـ A مش هتوصل لـ C. مناسب لعدد قليل من الـ VPCs.

</Card>
<Card title="AWS Transit Gateway" c={2}>

**hub مركزي**: كل VPC (وكل VPN وDirect Connect) بيتوصل بيه مرة، وهو بيوجّه بينهم. مناسب لما الـ VPCs تكتر، بدل ما تعمل peering لكل اتنين.

</Card>
</Grid2>

### VPC endpoints

| النوع | لإيه | التكلفة |
| --- | --- | --- |
| **Gateway endpoint** | S3 وDynamoDB بس | مجاني |
| **Interface endpoint** (AWS **PrivateLink**) | معظم خدمات AWS (SQS، Secrets Manager…) وخدمات شركات تانية | بالساعة + بالـ GB |

الفايدة: الترافيك مبيطلعش على الإنترنت، ومش محتاج NAT للخدمات دي.

### VPC Flow Logs

بتسجّل **مين كلم مين** على مستوى الشبكة (IPs، ports، accepted ولا rejected)، وتبعتها لـ CloudWatch Logs أو S3. مفيدة جدًا لما تسأل «ليه الاتصال ده مش شغال؟» أو للتحقيق الأمني. **مش بتسجل محتوى الطلبات.**

## 🛠️ طبّق: اقفل database دُكّان صح

⚠️ Security Groups مجانية. Flow Logs بتتحاسب على حجم الـ logs، فشغّلها دقايق وامسحها.

1. **اعمل ٣ Security Groups** في الـ VPC بتاعة دُكّان:

```bash
aws ec2 create-security-group --group-name sg-alb --description "ALB" --vpc-id vpc-xxxx
aws ec2 create-security-group --group-name sg-app --description "App servers" --vpc-id vpc-xxxx
aws ec2 create-security-group --group-name sg-db  --description "Database" --vpc-id vpc-xxxx
```

2. **اكتب القواعد** (استبدل الـ IDs):

```bash
# الإنترنت → ALB على 443
aws ec2 authorize-security-group-ingress --group-id sg-ALB --protocol tcp --port 443 --cidr 0.0.0.0/0
# ALB → app على 80 (بالـ Security Group مش بالـ IP)
aws ec2 authorize-security-group-ingress --group-id sg-APP --protocol tcp --port 80 --source-group sg-ALB
# app → database على 5432 بس
aws ec2 authorize-security-group-ingress --group-id sg-DB --protocol tcp --port 5432 --source-group sg-APP
```

3. **اقرا السلسلة:** الإنترنت ← ALB ← app ← db. كل حلقة بتسمح بالحلقة اللي قبلها بس. **المتوقع:** لو حد وصل للـ ALB، مش هيقدر يكلم الـ database مباشرة.
4. **(اختياري) Flow Logs:** `VPC` ← اختار `dukkan` ← `Flow logs` ← `Create` ← destination: CloudWatch Logs ← filter `REJECT`. جرّب اتصال ممنوع وشوف السطر بيظهر.

🧹 **تنضيف:** امسح الـ Flow log والـ log group، وامسح الـ Security Groups لو مش هتكمل.

## ⚖️ قارن: مين بيحل أنهي مشكلة؟

| المشكلة | الحل |
| --- | --- |
| السماح لترافيك معين يوصل لـ instance | **Security Group** |
| منع IP معين على مستوى subnet كاملة | **NACL** (deny rule) |
| VPCين محتاجين يكلموا بعض | **VPC peering** |
| ٢٠ VPC + data center محتاجين يتوصلوا | **Transit Gateway** |
| private subnet توصل لـ S3 من غير إنترنت ومجانًا | **Gateway endpoint** |
| private subnet توصل لـ SQS أو خدمة SaaS بشكل خاص | **Interface endpoint / PrivateLink** |
| عايز تشوف الاتصالات المرفوضة | **VPC Flow Logs** |

<Box type="interview" title="الفرق الأشهر في الامتحان">

**stateful** ← Security Group. **stateless** ← NACL.
**instance level** ← Security Group. **subnet level** ← NACL.
**deny rules** ← NACL بس.

</Box>
