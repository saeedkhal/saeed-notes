## المثال الأول: App خاصة تقرأ S3

`80` ECS task في private subnets تقرأ `5 TB/day` من S3 وتحتاج كمان package updates من الإنترنت.

١. S3 traffic تستخدم `Gateway VPC endpoint` بدل NAT.
٢. internet egress العام يمر من NAT Gateway في public subnet ثم IGW.
٣. app Security Group تسمح الاتصالات المطلوبة فقط.
٤. endpoint policy وIAM يحددوا buckets/actions؛ وجود endpoint لا يمنح صلاحية تلقائيًا.

## IGW وNAT

`Internet Gateway` target للـ internet routing، مش firewall. public resource تحتاج route وpublic address وقواعد سماح.

Public NAT Gateway تسمح لمورد خاص يبدأ IPv4 connection للخارج ويستقبل الرد المرتبط، لكنها لا تتيح inbound عام يبدأ من الإنترنت. لها تكلفة بالساعة ومعالجة data، وتصميم multi-AZ يحتاج مراعاة resilience ومسار cross-AZ والتكلفة.

## Security Group ضد NACL

<Grid2>
<Card title="Security Group" c={3}>

على ENI/resource، allow rules فقط، وstateful: الرد على اتصال مسموح يمر تلقائيًا. استخدم SG references بين app وdatabase بدل CIDRs واسعة لما يناسب.

</Card>
<Card title="Network ACL" c={4}>

على subnet، allow وdeny، وstateless. rules تُقيّم بالرقم وأول match تكسب؛ لازم تسمح return traffic والـ ephemeral ports حسب المسار.

</Card>

## Incident timeline

- `16:00`: تغيير NACL يسمح inbound `443` لكنه يمنع ephemeral return ports.
- `16:02`: health checks تبدأ تفشل رغم إن SG صحيحة.
- `16:05`: الفريق يقارن flow logs والقواعد ويكتشف إن NACL stateless.
- `16:08`: rollback يرجع الخدمة.

الدرس: route تحدد الطريق، SG/NACL تحدد السماح، وDNS/TLS/application health طبقات أخرى. اختبر كل طبقة بدل افتراض إن "الشبكة مفتوحة".

## Endpoints

- Gateway endpoints لـ S3 وDynamoDB، ولا تعتمد على PrivateLink.
- Interface endpoints تنشئ private ENIs وتستخدم AWS PrivateLink لخدمات مدعومة.

Gateway endpoints لـ S3 وDynamoDB لا تحمل رسمًا بحد ذاتها حسب الوضع الحالي في أكتوبر 2026، بينما interface endpoints لها تكلفة؛ راجع pricing والـ Region والـ service قبل التصميم.

<Box type="warn" title="Endpoint لا يلغي IAM">

لازم identity policy وresource policy وendpoint policy يتوافقوا. Private path مش معناه authorized request.

</Box>

## 🧪 تمرين: قلل NAT bill

App تنقل `12 TB/month` إلى S3 عبر NAT، وتعمل `2 TB/month` internet egress. ارسم المسار الحالي والجديد مع S3 Gateway endpoint. اكتب SG وNACL assumptions، ثم افترض فشل NAT في AZ-A وحدد أثره على tasks بكل AZ.
