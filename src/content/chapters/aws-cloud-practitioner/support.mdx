## Production outage الساعة 02:10

Checkout واقع في 3 Regions؟ لأ، account واحدة فيها RDS issue. الفريق جمع timestamps وresource IDs وrecent changes وشال secrets، وبعدين فتح case بالseverity الصحيحة.

1. 02:10 alarm.
2. 02:14 internal triage أكد impact: 100% checkout failures.
3. 02:18 Support case اتفتح تحت الخطة المؤهلة.
4. أول response target مش معناه حل نهائي؛ التحقيق والـ mitigation كملوا.
5. بعد recovery، team راجع architecture وrunbook بدل اعتبار Support بديل للتصميم.

## خطط أكتوبر ٢٠٢٦

- `Basic Support`: لكل العملاء؛ account/billing help، quota requests، docs وre:Post وقدرات أساسية متاحة.
- `Business Support+`: 24/7 technical support؛ الحد الأدنى المنشور `$29/account/month` أو النسبة، أيهما أكبر.
- `Enterprise Support`: mission-critical وdesignated TAM؛ الحد الأدنى المنشور `$5,000/month` أو النسبة.
- `Unified Operations`: عمليات كبيرة ومعقدة؛ الحد الأدنى المنشور `$50,000/month` أو النسبة.

الأسماء والأسعار والresponse times تتغير. `Developer Support` و`Business Support` و`Enterprise On-Ramp` القديمة مقرر ينتهي دعمها **١ يناير ٢٠٢٧** في commercial AWS، مع تفاصيل انتقال واستثناءات GovCloud. CLF-C02 قد يستخدم taxonomy القديمة؛ قرار الشراء يرجع للصفحة الرسمية.

## اختار المصدر

- سؤال عام بلا بيانات حساسة → `re:Post`.
- حلول شائعة → `Knowledge Center` داخل re:Post.
- case خاص بالحساب أو incident → AWS Support.
- تقارير واتفاقيات compliance → `AWS Artifact`.
- شراء ونشر software أو data من vendor → `AWS Marketplace`.
- شركة consulting أو implementation → `AWS Partner Network`.
- guidance استباقي → TAM في الخطة المؤهلة.

Artifact لا يعمل audit لتطبيقك. Marketplace لا يضمن إن المنتج مناسب أو إن AWS تشغله نيابة عن vendor. APN partner مش بديل تلقائي عن عقد Support.

## Tradeoff

قارن تكلفة الخطة بتكلفة downtime والاحتياج لـ TAM، مش بحجم الشركة فقط. SaaS يخسر `$40,000/hour` ممكن يبرر دعم أعلى؛ workload داخلي noncritical ممكن لا.
