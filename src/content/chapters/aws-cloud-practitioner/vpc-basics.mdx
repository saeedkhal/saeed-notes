## 🧠 افهم: سور حوالين موارد دُكّان

لما بتعمل EC2 أو RDS، لازم يقعدوا في **شبكة**. السؤال: مين يقدر يوصلهم؟

- الـ Load Balancer لازم الزباين يوصلوله من الإنترنت.
- السيرفرات المفروض يكلمها الـ Load Balancer بس.
- الـ database **ممنوع** أي حد من الإنترنت يوصلها.

**Amazon VPC (Virtual Private Cloud)** هي شبكتك الخاصة المعزولة جوه AWS. إنت بتحدد نطاق الـ IPs، وبتقسّمها لأجزاء (**subnets**)، وبتحدد كل جزء يوصل لإيه.

<Hl c="u">VPC = شبكتك المعزولة في Region. Subnet = جزء منها في AZ واحدة. والـ subnet بتبقى public لو الـ route table بتاعتها فيها طريق لـ Internet Gateway، وprivate لو مفيش.</Hl>

<Box type="story" icon="🏘️" title="كومباوند فيه عمارات">

- **الـ VPC** = الكومباوند كله بسوره.
- **الـ subnets** = العمارات. كل عمارة في حي (AZ) معين.
- **الـ public subnet** = العمارة اللي على الشارع وليها باب على الطريق العمومي (Internet Gateway).
- **الـ private subnet** = العمارة اللي جوه، ملهاش باب على الشارع. سكانها يقدروا يبعتوا جواب برّه عن طريق **مكتب البريد** (NAT Gateway)، بس محدش من برّه يقدر يخبط عليهم.
- **الـ route table** = اللافتات اللي بتقول «للخروج للشارع، من هنا».

</Box>

## 🔍 من جوه: المكونات

### CIDR والـ IPs

الـ VPC بتاخد نطاق IPs زي `10.0.0.0/16` (حوالي ٦٥ ألف عنوان). كل subnet بتاخد حتة منه، زي `10.0.1.0/24` (٢٥٦ عنوان، AWS بتحجز ٥ منهم). الرقم بعد `/` كل ما يصغر، النطاق يكبر.

### Subnets

- كل subnet في **AZ واحدة**. عشان الـ high availability اعمل subnets في AZين على الأقل.
- **Public:** الـ route table فيها `0.0.0.0/0 → igw-xxxx`.
- **Private:** مفيش طريق لـ IGW. ممكن يبقى فيها `0.0.0.0/0 → nat-xxxx` للخروج بس.

### Route table

قايمة «لو العنوان كذا، روح من هنا». كل subnet مربوطة بـ route table واحدة.

| Destination | Target | معناها |
| --- | --- | --- |
| `10.0.0.0/16` | `local` | أي حاجة جوه الـ VPC، روح مباشرة |
| `0.0.0.0/0` | `igw-…` | أي حاجة تانية، اطلع للإنترنت (public subnet) |
| `0.0.0.0/0` | `nat-…` | أي حاجة تانية، اطلع عن طريق NAT (private subnet) |

### Internet Gateway ولا NAT Gateway؟

<Grid2>
<Card title="Internet Gateway (IGW)" c={2}>

باب الـ VPC على الإنترنت، **في الاتجاهين**. واحد لكل VPC. مجاني في نفسه.

</Card>
<Card title="NAT Gateway" c={5}>

بيخلّي موارد الـ private subnet **تطلع** للإنترنت، ومحدش يدخلها من برّه. بيتحاسب **بالساعة + كل GB بيعدي**، فهو من أشهر مفاجآت الفاتورة.

</Card>
</Grid2>

<Box type="tip" title="Default VPC">

كل Region فيها **default VPC** جاهزة بـ public subnets في كل AZ، عشان تجرب بسرعة. للـ production اعمل VPC بتصميمك.

</Box>

## 🛠️ طبّق: اعمل شبكة دُكّان

⚠️ الـ VPC والـ subnets والـ route tables والـ IGW مجانيين. الـ **NAT Gateway بيتحاسب**، فاختار `None` في الـ Lab ده.

1. **`VPC` ← `Create VPC` ← `VPC and more`.** ده wizard بيعمل كل حاجة مع بعض.
2. **الإعدادات:**
   - Name: `dukkan`، و IPv4 CIDR: `10.0.0.0/16`
   - Number of AZs: `2`
   - Public subnets: `2`، Private subnets: `2`
   - NAT gateways: **`None`**
   - VPC endpoints: `S3 Gateway` (مجاني، هنفهمه في الفصل الجاي)
3. بص على الـ **Preview** على اليمين قبل ما تضغط Create: هتشوف نفس رسمة الفصل.
4. بعد الإنشاء، افتح `Route tables`:
   - الـ public route table فيها `0.0.0.0/0 → igw-…`.
   - الـ private route tables فيها `local` بس (وطريق الـ S3 endpoint).

**المتوقع:** فهمت إن «public» و«private» مجرد **سطر في route table**، مش إعداد سحري على الـ subnet.

5. **جرّب (اختياري):** شغّل EC2 في private subnet من غير public IP. مش هتقدر توصلها من الإنترنت حتى لو الـ Security Group مفتوح. الطريق نفسه مش موجود.

🧹 **تنضيف:** امسح أي instances جوه الـ VPC الأول، وبعدين `Your VPCs` ← اختار `dukkan` ← `Delete VPC` (بيمسح الـ subnets والـ route tables والـ IGW معاه).
