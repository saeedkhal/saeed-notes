## بورت لكل تطبيق

تطبيق على 3000 وتطبيق على 4000، والشارع داخل من بورت 80:

<File name="/etc/nginx/sites-available/apps">

```nginx
server {
    listen 80;
    server_name app.example.com;

    location /api/ {
        proxy_pass http://127.0.0.1:3000/;
    }

    location /web/ {
        proxy_pass http://127.0.0.1:4000/;
    }
}
```

</File>

اتجرّب نفس الشكل على Nginx 1.27.5. طلب `/api/` رجّع جسم التطبيق الأول (`from-3000`)، وطلب `/web/` رجّع جسم التطبيق التاني (`from-4000`).

لو كل تطبيق له دومين، اعمل بلوك `server` لكل دومين وكل واحد `proxy_pass` من غير ما تقسم المسارات.

## الشرطة في proxy_pass

<Hl c="o">وجود مسار في `proxy_pass` بيغيّر الرابط قبل ما يوصل للتطبيق.</Hl>

- **`proxy_pass http://127.0.0.1:3000;`** من غير مسار: الطلب يروح كما هو. `/api/users` يفضل `/api/users`.
- **`proxy_pass http://127.0.0.1:3000/;`** فيها `/`: جزء الـ `location` يتشال. `/api/users` يوصل للتطبيق كـ `/users`.

التجربة اللي فوق كانت بالنوع التاني، عشان كل تطبيق يستقبل `/` مش `/api/`.

لو التطبيق واقع أو البورت غلط، الزائر يشوف `502 Bad Gateway`. دور في لوج Nginx، وتأكد إن التطبيق سامع على `127.0.0.1` مش على واجهة مش موجودة.

<Box type="tip" title="upstream">

لو حابب تسمّي البورت:

```nginx
upstream api {
    server 127.0.0.1:3000;
}

location / {
    proxy_pass http://api;
}
```

الاسم من غير مسار، زي السطر اللي من غير شرطة.

</Box>
