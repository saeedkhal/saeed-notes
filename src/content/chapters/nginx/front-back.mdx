## باب واحد وشقتين

الفرونت سامع على `127.0.0.1:3000`، والباك سامع على `127.0.0.1:7000`. الزائر يفتح دومين واحد. Nginx يفرّق بالمسار:

- **`/`** صفحات وملفات الفرونت، تروح 3000.
- **`/api/`** طلبات الباك، تروح 7000.

<File name="/etc/nginx/sites-available/app">

```nginx
server {
    listen 80;
    server_name app.example.com;

    location /api/ {
        proxy_pass http://127.0.0.1:7000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

</File>

Nginx يختار أطول `location` مطابق. طلب `/api/users` يروح بلوك الباك، وطلب `/` أو `/login` يروح الفرونت. مش محتاج ترتّب البلوكين بإيدك.

<Hl c="y">السطر بتاع الباك من غير شرطة في الآخر، عشان `/api/users` يوصل للبورت 7000 بنفس الاسم.</Hl>

لو الباك أصلاً راوتاته من غير بادئة `/api` (يعني هو سامع على `/users` مش `/api/users`)، ساعتها بس حط الشرطة:

```nginx
proxy_pass http://127.0.0.1:7000/;
```

كده `/api/users` يتحول لـ `/users` قبل ما يوصل.

## الفرونت وهو بيتطور

بورت 3000 غالباً سيرفر تطوير (Vite أو Next). التحديث السريع بيستخدم WebSocket، عشان كده بلوك الفرونت فيه `Upgrade`. من غيره الصفحة تفتح والتحديث الحي يقطع.

لو الفرونت نسخة إنتاج متبنية وملفاتها على الديسك، متبعتش `/` لبورت 3000. خدّم المجلد بـ `root`، وسيب `proxy_pass` للباك بس. راجع الـ docs لأمر `try_files`.

## SSL بعدين

نفس البلوك يتنقل على `listen 443 ssl` زي فصل الشهادة. الفرونت والباك يفضلوا HTTP جوّه على 3000 و7000. الجدار الناري يفتح بورت Nginx بس.
