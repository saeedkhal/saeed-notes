## الاختيارين في Zod

`parse` بيرجع الداتا لو صحيحة، ويرمي `ZodError` لو غير صحيحة:

<File name="parse.ts">

```ts
userSchema.parse(data);
```

</File>

`safeParse` مش بيرمي Exception تلقائيًا. بيرجع نتيجة فيها `success`:

<File name="safe-parse.ts">

```ts
const result = userSchema.safeParse(data);

if (!result.success) {
  console.error(result.error);
  return;
}

console.log(result.data);
```

</File>

## أنهي واحد مع TanStack Query؟

بالنسبة للـ API layer مع TanStack Query، الميل لـ `parse()` لما يكون عدم تطابق الـ response مع الـ contract معناه إن الـ query فشلت فعلًا. ده بيخلّي الخطأ يوصل مباشرةً إلى `isError`.

أما `safeParse()` فمفيد لما تكون عايز تتحكم في الخطأ بنفسك، أو تعمل fallback آمن، أو تتعامل مع أجزاء من الداتا بشكل منفصل.

<Hl c="p">الاختيار الافتراضي: `parse()` في دوال الـ API.</Hl> اعمل handling مركزي للـ errors والـ logging، وسيب كل شاشة تعرض رسالة مناسبة لسياقها.
