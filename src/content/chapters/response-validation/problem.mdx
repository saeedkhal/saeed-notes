## تلات حاجات مختلفة

في React مع TypeScript وTanStack Query، لازم نفرّق بين تلات حاجات:

- **الـ Typing:** إيه نوع الداتا اللي الكود متوقع يتعامل معاها؟
- **الـ Runtime Validation:** هل الداتا اللي رجعت من الـ API مطابقة فعلًا للنوع المتوقع؟
- **الـ Error Handling:** هنعمل إيه لو الداتا مش مطابقة؟

## TypeScript مش بيعمل validation للـ API

تخيّل إن عندك API بترجع بيانات المستخدم بالشكل ده:

<File name="user.ts">

```ts
type User = {
  id: number;
  name: string;
  email: string;
};
```

</File>

وعندك الـ API request:

<File name="get-user.ts">

```ts
const getUser = async (): Promise<User> => {
  const response = await fetch("/api/user");

  return response.json();
};
```

</File>

هنا أنت بتقول لـ TypeScript إن الدالة بترجع `User`، لكن هل TypeScript اتأكد إن الـ API رجعت فعلًا `id` من نوع number و`name` من نوع string؟

<Hl c="y">لأ. الـ `Promise&lt;User&gt;` وعد للكومبايلر، مش فحص للداتا.</Hl>

الـ API ممكن ترجع:

<File name="wrong.json">

```json
{
  "id": "wrong-id",
  "name": null,
  "email": 123
}
```

</File>

ومع ذلك، TypeScript مش هيكتشف المشكلة وقت تشغيل البرنامج. الـ JSON بيانات خارجية، وTypeScript بيعمل type checking وقت التطوير والـ compilation، مش runtime validation.

<Hl c="p">الحل إننا نستخدم Runtime Schema Validation.</Hl>
