## نوعين… أربعة أخطاء

لازم نفرّق بين أنواع الأخطاء، لأن التعامل مش واحد:

| نوع الخطأ | مثال | التعامل المناسب |
| --- | --- | --- |
| Network error | السيرفر مش متاح | رسالة اتصال أو إعادة المحاولة |
| HTTP error | `401` أو `500` | التعامل مع الـ status code |
| Validation error | `id` رجع string بدل number | تسجيل الخطأ ومراقبته، ورسالة مناسبة للمستخدم حسب الشاشة |
| Business error | المستخدم مش مسموح له ينفذ العملية | رسالة مفهومة للمستخدم |

## TanStack Query بتاخد الـ throw

لو بنستخدم TanStack Query، فالـ validation error اللي بترميه `parse()` هيخلي الـ Query تدخل حالة `error` تلقائيًا.

<File name="UsersList.tsx">

```tsx
const userQuery = useQuery({
  queryKey: ["user"],
  queryFn: getUser,
});

if (userQuery.isPending) {
  return <div>Loading...</div>;
}

if (userQuery.isError) {
  return <div>Failed to load user</div>;
}

return <div>{userQuery.data.name}</div>;
```

</File>

ده كفاية عشان تمنع عرض الداتا غير الصحيحة.

<Box type="warn" title="متعرضش تفاصيل الـ schema">

في production الأفضل إنك ما تعرضش تفاصيل الـ schema الداخلية للمستخدم. لو الـ API رجعت `id` غلط، المستخدم مش محتاج يشوف رسالة زي `Expected number, received string at id`.

الأفضل تعرض رسالة عامة مناسبة، وتبعت تفاصيل الخطأ للـ logging أو الـ monitoring.

</Box>
