## `@repo/types`: zod schemas مشتركة

دي أحلى حاجة في الـ monorepo للـ fullstack: <Hl c="g">schema واحدة = validation في الـ API + validation في الفورم + TypeScript types</Hl>. لو حد غيّر قاعدة، الاتنين يتغيّروا مع بعض، والـ typecheck يمسك أي مكان اتكسر.

<File name="packages/types/src/job.ts">

```ts
import { z } from "zod";

export const jobTypeEnum = z.enum(["full_time", "part_time", "contract"]);

export const createJobSchema = z.object({
  title: z.string().min(3, "العنوان قصير"),
  description: z.string().min(20),
  type: jobTypeEnum,
  salaryMin: z.number().int().positive().optional(),
  salaryMax: z.number().int().positive().optional(),
  remote: z.boolean().default(false),
}).refine(
  (j) => !j.salaryMin || !j.salaryMax || j.salaryMin <= j.salaryMax,
  { message: "الحد الأدنى أكبر من الأقصى", path: ["salaryMax"] },
);

export type CreateJobInput = z.infer<typeof createJobSchema>;
```

</File>

<File name="packages/types/src/index.ts">

```ts
export * from "./job";
```

</File>

<Box type="warn" title="نقطة مهمة جدًا: NestJS مش Vite">

Vite و Next (مع `transpilePackages`) يقدروا يقروا ملفات `.ts` من package داخلية ويعملولها transpile. لكن **NestJS بيتبني بـ tsc ويشتغل على Node**، و Node مش هيفهم `.ts` جوه node_modules. الحل الأنضف: <Hl c="o">ابني `@repo/types` لـ `dist` بصيغتين (CJS + ESM)</Hl> باستخدام <En>tsup</En>، وخلّي الـ `dependsOn: ["^build"]` يتكفل بالترتيب.

</Box>

### في الـ API (NestJS)

<File name="apps/api/src/common/zod-validation.pipe.ts">

```ts
import { BadRequestException, PipeTransform } from "@nestjs/common";
import type { ZodSchema } from "zod";

export class ZodValidationPipe implements PipeTransform {
  constructor(private readonly schema: ZodSchema) {}

  transform(value: unknown) {
    const result = this.schema.safeParse(value);
    if (!result.success) {
      throw new BadRequestException(result.error.flatten());
    }
    return result.data;
  }
}
```

</File>

<File name="apps/api/src/jobs/jobs.controller.ts">

```ts
import { Body, Controller, Post } from "@nestjs/common";
import { createJobSchema, type CreateJobInput } from "@repo/types";
import { ZodValidationPipe } from "../common/zod-validation.pipe";
import { JobsService } from "./jobs.service";

@Controller("jobs")
export class JobsController {
  constructor(private readonly jobs: JobsService) {}

  @Post()
  create(@Body(new ZodValidationPipe(createJobSchema)) dto: CreateJobInput) {
    return this.jobs.create(dto);
  }
}
```

</File>

### في الـ Front (React + react-hook-form)

<File name="apps/web/src/features/jobs/CreateJobForm.tsx">

```tsx
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { createJobSchema, type CreateJobInput } from "@repo/types";
import { Button, TextField } from "@repo/ui";
import { useCreateJob } from "./useCreateJob"; // TanStack Query mutation

export function CreateJobForm() {
  const form = useForm<CreateJobInput>({ resolver: zodResolver(createJobSchema) });
  const createJob = useCreateJob();

  return (
    <form onSubmit={form.handleSubmit((data) => createJob.mutate(data))}>
      <TextField label="Title" {...form.register("title")}
        error={form.formState.errors.title?.message} />
      <Button type="submit" loading={createJob.isPending}>Publish</Button>
    </form>
  );
}
```

</File>

## `@repo/ui` + Storybook

<File name="packages/ui/package.json">

```json
{

    "build-storybook": "storybook build",
    "lint": "eslint .",
    "typecheck": "tsc --noEmit"
  },
  "peerDependencies": { "react": "^18 || ^19", "react-dom": "^18 || ^19" },
  "devDependencies": {
    "@repo/tsconfig": "workspace:*",
    "@repo/eslint-config": "workspace:*"
  }
}
```

</File>

هنا اخترنا الطريقة التانية: <Hl c="b">Just-in-Time package</Hl> — الـ `exports` بيشاور على `.ts` مباشرة من غير build. ده شغال تمام لأن المستهلك الوحيد هو `web` (Vite) وهو اللي بيعمل transpile.

| | Just-in-Time (src مباشرة) | Compiled (dist) |
| --- | --- | --- |
| Setup | أبسط حاجة | محتاج tsup/vite lib |
| HMR | فوري 🔥 | محتاج watch |
| الكاش في Turbo | مفيش build يتكيّش | يتكيّش |
| ينفع مع NestJS/Node؟ | ❌ | ✅ |
| استخدامه هنا | `ui` | `types` |

<Box type="tip" title="ليه React في peerDependencies؟">

عشان مايتنزّلش نسختين React (واحدة للـ ui وواحدة للـ web) — وده بيعمل الـ error الشهير بتاع "Invalid hook call". الـ ui بتقول "أنا محتاجة React، بس استخدم النسخة اللي عند الـ app". وحطها كمان في `devDependencies` عشان Storybook يشتغل.

</Box>

```bash
cd packages/ui
pnpm dlx storybook@latest init   # اختار React + Vite

```
