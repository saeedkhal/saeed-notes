## هنبني إيه؟

endpoint واحد `POST /orders` لمحل كشري. الطلب لازم يكون فيه:

- **عميل:** اسم من 2 لـ 50 حرف، وموبايل مصري، وإيميل اختياري.
- **أصناف:** من 1 لـ 20 صنف، كل صنف `sku` من قايمة معروفة و`qty` integer من 1 لـ 10.
- **طريقة دفع:** `cash` أو `card` أو `wallet`.
- **ملاحظات:** اختيارية ولحد 200 حرف.
- **ومفيش أي حقل زيادة:** عشان محدش يبعت `isAdmin` أو `discount`.

## الـ validator والـ middleware

<File name="validate.js">

```js
import { readFileSync } from "node:fs";
import Ajv from "ajv/dist/2020.js";
import addFormats from "ajv-formats";

// instance واحد للتطبيق كله
export const ajv = new Ajv({ allErrors: true, strict: true });
addFormats(ajv);

const load = (file) => JSON.parse(readFileSync(new URL(`./schemas/${file}`, import.meta.url)));
ajv.addSchema(load("order.json"));

// يحوّل errors بتاعة Ajv لشكل نضيف يرجع للـ client
export function formatErrors(errors = []) {
  return errors.map((e) => {
    let field = e.instancePath || "/";
    if (e.keyword === "required") field = `${e.instancePath}/${e.params.missingProperty}`;
    if (e.keyword === "additionalProperties") field = `${e.instancePath}/${e.params.additionalProperty}`;
    return { field, rule: e.keyword, message: e.message };
  });
}

// middleware: بياخد الـ $id بتاع الـ schema
export function validateBody(schemaId) {
  const validate = ajv.getSchema(schemaId);
  if (!validate) throw new Error(`schema not found: ${schemaId}`);
  return (req, res, next) => {
    if (validate(req.body)) return next();
    res.status(400).json({ error: "ValidationError", details: formatErrors(validate.errors) });
  };
}
```

</File>

- **الـ `getSchema` بره الـ middleware:** بيحصل مرة واحدة لما الـ route يتسجل، مش مع كل request.
- **الـ `throw` لو الـ schema مش موجودة:** السيرفر يقع وقت الـ startup أحسن ما يقع مع أول request.
- **الـ `formatErrors`:** بيصلّح مكان الحقل في `required` و`additionalProperties`، وبيخبّي `schemaPath`.

## السيرفر

<File name="server.js">

```js
import express from "express";
import { validateBody } from "./validate.js";

const app = express();
app.use(express.json({ limit: "10kb" })); // حد للحجم قبل الـ validation

app.post("/orders", validateBody("https://koshary.example/schemas/order.json"), (req, res) => {
  // هنا الـ body مضمون شكله
  const count = req.body.items.reduce((sum, i) => sum + i.qty, 0);
  res.status(201).json({ ok: true, customer: req.body.customer.name, count });
});

// errors الـ JSON parser نفسه (قبل الـ schema)
app.use((err, req, res, next) => {
  if (err.type === "entity.parse.failed") return res.status(400).json({ error: "InvalidJSON" });
  if (err.type === "entity.too.large") return res.status(413).json({ error: "PayloadTooLarge" });
  next(err);
});

const port = process.env.PORT ?? 3000;
app.listen(port, () => console.log(`listening on http://localhost:${port}`));
```

</File>

- **الـ `limit: "10kb"`:** أول خط دفاع. الـ body الضخم بيترفض قبل ما يتعمله parse أو validation خالص.
- **الـ handler بقى بسيط:** مفيش ولا `if` على الشكل. `req.body.items.reduce` آمنة لأن الـ schema ضمنت إن `items` array فيها `qty` integer.

<Box type="tip" title="زوّد عليه">

- **الـ query والـ params:** اعمل schemas ليهم بـ Ajv instance تاني فيه `coerceTypes: true`، لأن قيمهم دايمًا strings.
- **الـ tests:** اكتب test لكل حالة فوق بـ `node:test` و`fetch`، عشان أي تعديل في الـ schema يتلقط.
- **الـ OpenAPI:** نفس `order.json` ينفع يتحط في `components/schemas` في OpenAPI 3.1 زي ما هو (فصل ١١).

## نفس الحكاية في Fastify: built-in

Fastify بيستخدم Ajv جوّاه، فمش محتاج middleware:

<File name="fastify.js">

```js
import Fastify from "fastify";

const app = Fastify();

app.post("/users", {
  schema: {
    body: {
      type: "object",
      properties: {
        name: { type: "string", minLength: 2 },
        age: { type: "integer", minimum: 0 },
      },
      required: ["name"],
      additionalProperties: false,
    },
    response: {
      201: {
        type: "object",
        properties: { id: { type: "integer" }, name: { type: "string" } },
      },
    },
  },
}, async (req, reply) => {
  reply.code(201);
  return { id: 7, name: req.body.name, age: req.body.age, password: "secret123" };
});

await app.ready();
for (const payload of [{ name: "Saeed", age: "30" }, { name: "S", isAdmin: true }, { age: 5 }]) {
  const r = await app.inject({ method: "POST", url: "/users", payload });
  console.log(r.statusCode, r.body);
}
```

</File>

<File name="output">

```text
201 {"id":7,"name":"Saeed"}
400 {"statusCode":400,"code":"FST_ERR_VALIDATION","error":"Bad Request","message":"body/name must NOT have fewer than 2 characters"}
400 {"statusCode":400,"code":"FST_ERR_VALIDATION","error":"Bad Request","message":"body must have required property 'name'"}
```

</File>

- **الـ `schema.body`:** Fastify بيعملها compile وقت الـ startup، وبيرد `400` لوحده.
- **فيه كمان:** `schema.querystring` و`schema.params` و`schema.headers`.
- **الـ `schema.response`:** بيتعمل بيها **serializer** سريع بـ `fast-json-stringify` بدل `JSON.stringify`.
- **لاحظ الـ response:** الـ handler رجّع `password` و`age`، بس الرد طلع `{"id":7,"name":"Saeed"}` بس. الـ serializer بيطلّع الحقول اللي في الـ schema بس. <Hl c="g">ده بيحميك من تسريب حقول بالغلط.</Hl>
- **الـ response schema مش validation:** هو بيشكّل الـ output، مش بيرفضه لو غلط. متعتمدش عليه كـ test.

<Box type="warn" title="الـ defaults بتاعة Fastify مش زي Ajv">

لاحظ إن `"age": "30"` **عدّى** في أول request! Fastify بيشغّل Ajv بالـ options دي by default (من الـ source بتاع `@fastify/ajv-compiler`):

- **`coerceTypes: "array"`:** بيحوّل `"30"` لـ `30`.
- **`removeAdditional: true`:** بيمسح الحقول الزيادة **بهدوء** لو فيه `additionalProperties: false`. جرّبنا `{"name":"Saeed","isAdmin":true}` والـ handler استلم `{"name":"Saeed"}` بـ `200`، من غير أي رفض.
- **`useDefaults: true`:** بيحط الـ defaults.
- **`allErrors: false`:** بيرجّع أول غلط بس.
- **وdraft-07:** فـ `prefixItems` و`unevaluatedProperties` بيرموا error وقت الـ startup.

لو عايز الرفض الصريح:

</Box>

<File name="fastify-strict.js">

```js
const app = Fastify({
  ajv: { customOptions: { removeAdditional: false, coerceTypes: false } },
});
// {"name":"Saeed","isAdmin":true} ← 400 body must NOT have additional properties
// {"name":"Saeed","age":"30"}     ← 400 body/age must be integer
```

</File>
