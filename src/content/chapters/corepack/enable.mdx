## `pnpm` ميعرفش Corepack

لما تكتب `pnpm install`، pnpm مش بيدور على Corepack. الـ shell يدور في `PATH` من الأول للآخر ويشغّل **أول ملف اسمه `pnpm`**.

بعد `corepack enable`، Corepack يحط ملف وسيط اسمه `pnpm` جنب تثبيت Node. لو الملف ده هو الأول في `PATH`، الرحلة تبقى:

<Flow items={[{"t": "shell", "s": "دور على pnpm", "c": 1}, "→", {"t": "Corepack shim", "s": "اقرأ packageManager", "c": 2}, "→", {"t": "pnpm المطلوب", "s": "شغّل install", "c": 3}]} />

لو pnpm عالمي قديم جاي قبله في `PATH`، القديم هو اللي يشتغل ومش هيعدّي على Corepack. افحص:

<File name="terminal">

```bash
command -v pnpm       # Windows: where pnpm
corepack enable
command -v pnpm
pnpm --version
```

</File>

<Hl c="b">حقل packageManager مش زر تشغيل. لازم الأمر نفسه يعدّي على Corepack shim.</Hl>

## هل كل Node بينزل معاه npm؟

توزيعات Node الرسمية عادةً بتشحن npm معاها، لكنهم مشروعين وإصدارين منفصلين. إصدار Node يختار نسخة npm وقت نشره، وتقدر تحدّث npm منفصل:

<File name="terminal">

```bash
node --version
npm --version
npm install -g npm@11
```

</File>

لما تغيّر Node بـ nvm مثلًا، أنت بتنتقل لتثبيت Node تاني وغالبًا معاه npm تاني. متفترضش إن تحديث npm حدّث Node، أو العكس.

Corepack قصة تالتة: اتوزع مع Node من ١٤٫١٩ لحد قبل ٢٥، لكنه مش مفعّل لمجرد وجوده. من Node ٢٥ اتشال من توزيعة Node. اعمل onboarding يتحمل الحالتين:

<File name="terminal">

```bash
npm install -g corepack@0.36.0
corepack enable
```

</File>

<Box type="tip" title="ليه رقم لـ Corepack نفسه؟">

لو كل المطورين والـ CI يثبتوا `latest`، سلوك البوابة نفسها ممكن يتغير في أيام مختلفة. المثال يثبّت 0.36.0 لأنه الإصدار اللي اتراجع عليه الشرح. حدّثه بقرار، وراجع الـ docs قبل ما تنسخ الرقم بعد فترة.

</Box>

## npm مش في التفعيل الافتراضي

`corepack enable` من غير أسماء يفعّل Yarn وpnpm. npm اللي جاي مع Node يفضل هو اللي يشتغل، وCorepack مش هيشوفه. يعني مشروع pnpm ممكن يرفض `yarn install`، لكن `npm install` يعدّي من الباب الجانبي.

عشان `npm` كمان يعدّي على نفس البوابة:

<File name="terminal">

```bash
corepack enable npm
```

</File>

أو نادِه صراحةً: `corepack npm install`. الحالتان تخلي npm يمر على الفحص.

## اقفلها لو خربت المسار

`corepack disable` يشيل الوسائط. `corepack disable pnpm` يشيل pnpm بس. مفيد لو فعّلت و`pnpm` بقى بيشير لمكان غلط، أو عايز ترجع للنسخة العامة مؤقتًا عشان تجرب.

على نظام الملفات للقراءة بس، `enable` يفشل لأنه مش قادر يكتب جنب `node`. الحل في الوثائق aliases في الشيل، زي `alias pnpm="corepack pnpm"`. ده جهازك، مش اتفاق الفريق.

## لو مش عايز تغيّر PATH

تقدر تنادي المدير صراحةً من خلال Corepack:

<File name="terminal">

```bash
corepack pnpm@10.15.0 --version
corepack pnpm install
```

</File>

السطر التاني لسه بيتحقق من حقل المشروع. `corepack yarn install` جوه مشروع pnpm يقع؛ النداء الصريح مش ثغرة.
