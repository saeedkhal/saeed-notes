## طالما الحزم مقفولة، نسخة npm تفرق ليه؟

الـ lockfile يقفل **ناتج حل الحزم**، لكنه مش بيقفل البرنامج اللي هيقرأ الناتج. إصدار مختلف من npm أو pnpm ممكن يختلف في:

- صيغة الـ lockfile، وهل يعيد كتابته.
- قواعد `peerDependencies` و `optionalDependencies`.
- شكل `node_modules` والـ linking.
- تشغيل lifecycle scripts والتحذيرات والسياسات.
- قبول lockfile قديم أو اعتباره محتاج تحديث.

وكمان `npm install` و `pnpm install` العاديين مسموح لهم يصلحوا أو يحدّثوا القفل. التثبيت القابل للتكرار يحتاج ٣ حاجات مع بعض:

<File name="terminal">

```bash
# npm
npm ci

# pnpm
pnpm install --frozen-lockfile
```

</File>

## Corepack مكانه فين؟

<En>Corepack</En> مش runtime ومش package manager. هو launcher صغير يقف قبل مدير الحزم:

<Flow items={[{"t": "pnpm install", "c": 1}, "→", {"t": "Corepack shim", "s": "يقرأ المشروع", "c": 2}, "→", {"t": "pnpm 10.15.0", "s": "النسخة المحددة", "c": 3}, "→", {"t": "node_modules", "c": 5}]} />

لو المشروع كاتب `pnpm@10.15.0`، Corepack يجهّز ويشغّل الرقم ده. لو كتبت Yarn، يرفض. لو مفيش اتفاق مكتوب، مفيش ضمان إن أفراد الفريق شغّالين بنفس الأداة.

<Box type="interview" title="إجابة السؤال في سطرين">

"طالما dependency versions محددة، ليه أثبّت npm؟" — لأن dependencies بيانات، ومدير الحزم هو الخوارزمية اللي تفسّرها وتبنيها. ثبّت الاتنين: الشجرة بالـ lockfile، والأداة بـ `packageManager`.

</Box>
