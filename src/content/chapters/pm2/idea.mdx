## Node سريع، بس الـ process ليها حدود

كود JavaScript بتاع process واحدة بيتنفذ على event loop رئيسية. Node يقدر يستنى I/O كتير من غير thread لكل request، لكن ده مش معناه إن نفس الكود بيتنفذ بالتوازي على ٨ cores.

لو السيرفر فيه ٨ cores وشغّلت `node server.js` مرة، عندك process واحدة. نظام التشغيل وNode ممكن يستخدموا threads داخلية لحاجات معينة، لكن كود JavaScript الرئيسي مش هيتوزع تلقائيًا على الثمانية.

<Hl c="y">PM2 يقدر يشغّل نسخ متعددة من التطبيق؛ هو مش بيحوّل الـ process الواحدة إلى multi-threaded.</Hl>

## سيرفر هنستخدمه في كل التجارب

<File name="server.js">

```js
import http from "node:http";

const port = Number(process.env.PORT ?? 3000);

http
  .createServer((req, res) => {
    res.end(`pid=${process.pid} port=${port}\n`);
  })
  .listen(port, () => {
    console.log(`pid ${process.pid} listening on ${port}`);
  });
```

</File>

كل response يطبع PID. لما نكرر `curl`، تغيير الرقم يثبت إن الطلبات وصلت إلى processes مختلفة.

## PM2 مسؤول عن إيه؟

PM2 يشغّل التطبيق، يراقبه، يعيده لو وقع، يجمع metadata وlogs، ويقدر يحفظ process list ويرجعها بعد reboot. عنده طريقتان للتنفيذ:

<Flow items={[{"t": "Fork mode", "s": "process مستقلة", "c": 2}, "→", {"t": "أو", "c": 5}, "→", {"t": "Cluster mode", "s": "workers على port واحد", "c": 4}]} />

الـ default هو Fork mode. استخدام `-i` مع Node app يدخل Cluster mode تلقائيًا، لكن في ecosystem file اكتب `exec_mode` صراحةً عشان النية تبقى واضحة.
