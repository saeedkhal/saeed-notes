## الفكرة الأساسية

Node بيشغّل كود الـ JavaScript بتاعك على **thread واحد**. يعني لو السيرفر فيه 8 cores، الـ process الواحدة هتشغّل كودك على core واحد بس، والسبعة التانيين قاعدين.

<Hl c="y">السؤال اللي المذكرة كلها بتجاوب عليه: إزاي أستغل باقي الـ cores؟</Hl>

وفي PM2، الإجابة دي اسمها `exec_mode`، وليها قيمتين بس:

<Grid2>
<Card title="fork" c={2}>

كل instance هي process مستقلة تمامًا، ومفيش بينها وبين التانية أي مشاركة.

</Card>
<Card title="cluster" c={3}>

workers كتير بيشتغلوا من خلال process رئيسية، وكلهم بيشاركوا نفس الـ port.

</Card>
</Grid2>

القيمتين دول مش اختراع من PM2. الاتنين مبنيين على حاجات موجودة في Node نفسه: `child_process.fork()` والـ `cluster` module.

## طب إزاي Node بيخدم ألف request وهو thread واحد؟

لأن أغلب شغل السيرفر هو **انتظار**: query على الداتابيز، أو request لـ API تاني، أو قراية ملف. وأثناء ما Node مستني، بيروح يخدم request تاني. وده اسمه concurrency.

لكن لو الكود نفسه بيحسب حاجة تقيلة، زي loop كبيرة أو تشفير أو معالجة صورة، فالـ thread بيبقى مشغول، وكل الـ requests التانية بتستنى وراه. وهنا بتحتاج processes أكتر، أو `worker_threads` لو الحساب جوه request واحدة. وده هنرجعله في فصل المقارنة.

## السيرفر اللي هنجرّب عليه

<File name="server.js">

```js
const http = require("node:http");

const PORT = process.env.PORT || 3000;

http
  .createServer((req, res) => res.end(`pid ${process.pid} on port ${PORT}\n`))
  .listen(PORT, () => console.log(`pid ${process.pid} listening on ${PORT}`));
```

</File>

كل response فيه الـ `pid`. فلما تبعت كذا request وتلاقي الرقم بيتغيّر، تعرف إن الطلبات راحت لـ processes مختلفة.

## الـ default في PM2

<File name="terminal">

```bash
pm2 start server.js           # fork، process واحدة
pm2 start server.js -i 4      # cluster تلقائي، 4 workers
pm2 start server.js -i max    # cluster، worker لكل core
pm2 start server.js -i 4 -x   # 4 processes بس fork
```

</File>

- الـ default هو **fork**.
- أول ما تكتب `-i` في الـ CLI على Node app، PM2 بيحوّل لـ cluster لوحده حتى لو مقولتلوش.
- لو عايز كذا instance في fork، استخدم `-x` (اسمها `--execute-command`). مفيش flag اسمه `--exec-mode` في الـ CLI.
- أي حاجة مش Node، زي Python أو bash أو binary، بتشتغل fork دايمًا.

<Box type="tip" title="متعتمدش على الـ default">

في الـ ecosystem file اكتب `exec_mode` صريح دايمًا. كده أي حد يقرا الملف يعرف الـ mode من غير ما يفتكر القواعد دي، والـ mode مش هيتغيّر فجأة لو حد زوّد `instances`. وتقدر تشوف الـ mode الشغال فعلًا من عمود `mode` في `pm2 list`.

</Box>
