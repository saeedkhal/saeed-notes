## فك الأمر الطويل

<File name="terminal">

```bash
pm2 start ./bin/www -i 8 --merge-logs --time --name ".COM::backend"
```

</File>

- `./bin/www`: ملف التشغيل بتاع Express.
- `-i 8`: يعني 8 instances. ومع Node app بيحوّل لـ cluster لوحده.
- `--merge-logs`: كل الـ instances بيكتبوا في نفس ملف الـ out ونفس ملف الـ error، بدل ملف لكل instance برقمها.
- `--time`: بيحط timestamp قدام كل سطر log.
- `--name`: الاسم اللي هتستخدمه في باقي الأوامر.

<Box type="warn" title="merge-logs مش بتدمج out مع error">

هي بتدمج الـ instances مع بعض، لكن الـ out يفضل ملف والـ error ملف تاني.

</Box>

## نفس الأمر في ecosystem file

الأمر الطويل بيضيع في الـ shell history. الملف ده بيتحط في Git وأي حد يقدر يراجعه:

<File name="ecosystem.config.js">

```js
module.exports = {
  apps: [
    {
      name: ".COM::backend",
      script: "./bin/www",
      exec_mode: "cluster",
      instances: "max", // بدل 8 ثابتة
      merge_logs: true,
      time: true,
      env: { NODE_ENV: "production", PORT: 4000 },
    },
  ],
};
```

</File>

## الأوامر اللي هتستخدمها كل يوم

<File name="terminal">

```bash
pm2 start ecosystem.config.js
pm2 list                          # كل الـ apps والـ mode والـ memory
pm2 logs ".COM::backend" --lines 100
pm2 monit                         # CPU وmemory لايف
pm2 describe ".COM::backend"      # المسارات والـ env وعدد الـ restarts
pm2 scale ".COM::backend" 4       # غيّر عدد الـ workers
pm2 stop ".COM::backend"
pm2 delete ".COM::backend"
```

</File>

## Restart ولا Reload؟

- **`pm2 restart`:** بيقفل الكل وبعدين يشغّلهم تاني، فبيحصل downtime ولو ثواني.
- **`pm2 reload`:** في cluster، بيشغّل worker جديد، ولما يجهز يقفل القديم، وهكذا واحد واحد. ده اللي بيخليه **zero-downtime**.
- في fork، `reload` بيبقى restart عادي.

<Hl c="g">استخدم reload للـ deploy، وrestart لما تحتاج تبدأ من الصفر.</Hl>

### reload بيبقى من غير downtime بشرطين

- **أولًا:** التطبيق يقفل بأدب. PM2 بيبعت `SIGINT`، فاقفل السيرفر وخلّص الـ requests اللي شغالة:

<File name="bin/www (إضافة)">

```js
process.on("SIGINT", () => {
  server.close(() => process.exit(0)); // بيستنى الـ requests المفتوحة
});
```

</File>

- **ثانيًا:** الـ worker الجديد يكون جاهز قبل ما القديم يقفل. لو التطبيق بيحتاج وقت عشان يتصل بالداتابيز، استخدم `wait_ready: true` وابعت `process.send("ready")` لما يخلص.
- لو الـ worker القديم مقفلش خلال `kill_timeout`، PM2 بيقفله بالعافية. ولو الجديد مبعتش ready خلال `listen_timeout`، PM2 بيكمل برضه. وفي الحالتين ممكن requests تضيع، فاختبر الـ reload على staging.
