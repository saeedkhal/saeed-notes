## المقارنة

| | Fork | Cluster |
|---|---|---|
| الـ port | port لكل process | port واحد للكل |
| مين بيوزّع؟ | Nginx أو LB برّه | PM2 (الـ primary) |
| اللغة | أي حاجة | Node بس |
| `pm2 reload` بدون downtime | لأ، بيبقى restart | أيوه |
| memory مشتركة؟ | لأ | برضه لأ |

<Hl c="b">السطر الأخير هو أهم سطر: في الوضعين، كل instance ليها memory لوحدها.</Hl> cluster معناه port مشترك، مش memory مشتركة.

## المشاكل اللي بتظهر لما التطبيق يبقى N نسخة

أي حاجة متخزنة في متغير جوه الـ process هتبقى N نسخة مختلفة:

<Grid2>
<Card title="Session أو cache في RAM" c={1}>

المستخدم يعمل login عند worker 1، والـ request الجاي يروح worker 2 فميلاقيش الـ session. الحل إنك تحطها في Redis أو في الداتابيز.

</Card>
<Card title="Rate limiter في RAM" c={2}>

كل worker بيعد لوحده. حد 100 request مع 4 workers بيبقى في الحقيقة 400. الحل store مشتركة.

</Card>
</Grid2>

<Grid2>
<Card title="Cron جوه التطبيق" c={4}>

الـ job بتشتغل N مرة، مرة في كل worker. يعني إيميل التقرير يوصل 8 مرات. الحل إنك تشغّل الـ cron في process لوحدها (fork، instance واحدة)، أو تستخدم lock في Redis.

</Card>
<Card title="Socket.io" c={5}>

الـ client متوصل بـ worker معين، فرسالة من worker تاني مش هتوصله. محتاج Redis adapter، ومحتاج sticky sessions لو فيه polling.

</Card>
</Grid2>

<Box type="tip" title="لو مضطر تشغّل حاجة في worker واحد بس">

PM2 بيدي كل instance رقم في `process.env.NODE_APP_INSTANCE`، من `0` لحد `N-1`. تقدر تكتب `if (process.env.NODE_APP_INSTANCE === "0")` وتشغّل الـ cron جواها. وده حل سريع، بس process منفصلة للـ cron أنضف، لأن worker صفر ممكن يعمل restart في نص الـ job.

</Box>

## إمتى تستخدم إيه؟

- **API أو web server بـ Node على VPS:** cluster مع `instances: "max"`، وبشرط إن التطبيق stateless.
- **Worker بيسحب من queue، أو cron، أو سكريبت:** fork، instance واحدة.
- **أي حاجة مش Node:** fork. مفيش اختيار تاني.
- **Docker أو Kubernetes:** غالبًا process واحدة لكل container، وزوّد الـ replicas. الـ orchestrator هو اللي بيوزّع ويرجّع اللي يقع، فـ cluster جوه كل container بيبقى طبقة زيادة.
- **request واحدة بتعمل حساب تقيل:** cluster مش هيسرّعها، لأنه بيوزّع requests مختلفة بس. استخدم `worker_threads` أو job queue.
