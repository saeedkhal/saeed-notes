## الفكرة

PM2 عنده حاجة جاهزة للموضوع ده، وهي خطوتين: **startup** و**save**.

<Grid2>
<Card title="pm2 startup" c={2}>

بيخلي PM2 نفسه يقوم مع الـ boot.

</Card>
<Card title="pm2 save" c={3}>

بيقول لـ PM2 أنهي apps يرجّعها لما يقوم.

</Card>
</Grid2>

<Hl c="y">واحدة من غير التانية مش كفاية.</Hl> startup من غير save يعني PM2 هيقوم فاضي. وsave من غير startup يعني القائمة محفوظة ومحدش هيقراها.

## ١. خلي PM2 يقوم مع السيستم

<File name="terminal">

```bash
pm2 startup
```

</File>

الأمر ده بيعرف نوع الـ init system عندك (غالبًا systemd على Ubuntu)، وبيطبعلك أمر جاهز يبدأ بـ `sudo`، شكله كده:

<File name="terminal">

```bash
sudo env PATH=$PATH:/usr/bin pm2 startup systemd -u ubuntu --hp /home/ubuntu
```

</File>

- **انسخ الأمر اللي طلعلك إنت بالظبط ونفذه، متكتبوش من دماغك.** الأمر فيه مسار الـ node واسم اليوزر والـ home بتوعك.
- الأمر ده بيعمل service اسمها `pm2-<username>`، بتقوم مع الـ boot.
- شغّل `pm2 startup` نفسه **من غير sudo**. هو بس اللي بيطبع الأمر، والأمر المطبوع هو اللي فيه sudo.

## ٢. احفظ الـ apps الشغالة

شغّل الـ apps الأول، وبعدين احفظ القائمة:

<File name="terminal">

```bash
pm2 start ecosystem.config.js
pm2 save
```

</File>

الأمر `pm2 save` بيكتب الـ apps الشغالة حاليًا في ملف `~/.pm2/dump.pm2`. ولما السيرفر يقوم، PM2 بيقرأ الملف ده ويرجّع كل حاجة زي ما كانت.

## ٣. اتأكد إن الـ service شغالة

اسم الـ service هو `pm2-` وبعده اسم اليوزر اللي نفّذ أمر الـ `startup`. يوزر `ubuntu` يبقى `pm2-ubuntu`. يوزر `saeed` يبقى `pm2-saeed`.

<File name="terminal">

```bash
whoami
systemctl is-enabled pm2-$(whoami)
systemctl is-active pm2-$(whoami)
systemctl status pm2-$(whoami)
```

</File>

- **`is-enabled`:** هتقوم مع الـ boot ولا لأ. الناتج المطلوب `enabled`.
- **`is-active`:** شغالة دلوقتي ولا لأ. `active` يعني systemd هو اللي ماسك الـ daemon. `inactive` أول مرة بعد `pm2 startup` مش دايمًا مشكلة، لأنك ممكن تكون شغّلت الـ apps بإيدك والـ service لسه متعملهاش `start`. بعد أول reboot المفروض تبقى `active`.
- **`status`:** يجمع الاتنين، ويعرض آخر سطور من اللوج. لو وقعت، دور على `failed`.

بعد reboot، `pm2 list` **من نفس اليوزر** لازم يوريك الـ apps. `systemctl` بيقول إن المنبّه صحّى البواب. `pm2 list` بيقول إن السكان رجعوا.

## كل يوزر له service

الـ service مش بتاع السيرفر كله. مربوطة باليوزر في تلات حتت:

- **الاسم:** `pm2-<username>`.
- **سطر `User=`** جوه ملف الـ service، وفي `PM2_HOME=/home/<username>/.pm2`.
- **القائمة:** `pm2 resurrect` بيقرا `dump.pm2` اللي في الهوم ده بس.

لو على الجهاز يوزر `ubuntu` ويوزر `deploy`، وكل واحد شغّل `pm2 startup` وبعدين `pm2 save`، هيبقى فيه خدمتين:

| الـ service | بتقوم بإيه |
| --- | --- |
| `pm2-ubuntu` | تطبيقات `/home/ubuntu/.pm2/dump.pm2` |
| `pm2-deploy` | تطبيقات `/home/deploy/.pm2/dump.pm2` |

مفيش واحدة فيهم بتشوف تطبيقات التانية. كل يوزر لازم ينفّذ `pm2 startup` و`pm2 save` وهو داخل بحسابه. `pm2 list` من غير `sudo` يوريك بتوعك بس.

<File name="terminal">

```bash
systemctl list-units --type=service 'pm2-*'
ls /etc/systemd/system/pm2-*.service
```

</File>

لو عملت `pm2 save` بحساب و`startup` بحساب تاني، الـ service هتقوم وتلاقي قائمة فاضية أو قائمة قديمة بتاعة الحساب التاني.

## حاجات لازم تاخد بالك منها

- **بعد أي تغيير في الـ apps:** ضفت app أو مسحت واحدة أو غيرت الإعدادات أو عدد الـ instances، اعمل `pm2 save` تاني. وإلا هيرجع للنسخة القديمة بعد الـ restart.
- **نفس اليوزر في `startup` وفي `save`.** الـ service بتقرا هوم اليوزر المكتوب في اسمها، مش هوم اليوزر التاني.
- **لو بتستخدم nvm وغيرت نسخة Node:** اعمل `pm2 unstartup` وبعدها `pm2 startup` تاني، لأن الـ service فيها مسار الـ node القديم (في سطر `Environment=PATH=...`).
- **لو حدّثت PM2 نفسه:** اعمل `pm2 update` عشان الـ daemon اللي شغال يتحدث. تحديث الـ package بس مش بيغيّر الـ daemon اللي في الـ memory.
- **الـ env variables** (زي `SSL_PUBLIC_KEY` و`SERVERHTTPS`): الأضمن تحطها في الـ ecosystem file أو في `.env` يتقري من الكود، مش في الـ shell، عشان تبقى موجودة بعد الـ reboot.

<File name="terminal (لو غيرت Node بـ nvm)">

```bash
pm2 unstartup     # هيطبع أمر sudo يشيل الـ service القديمة، نفّذه
pm2 startup       # هيطبع أمر sudo جديد بمسار الـ node الجديد، نفّذه
pm2 resurrect     # لو الـ apps وقفت مع الـ unstartup
pm2 save
```

</File>

<Box type="warn" title="ليه الـ env في الـ shell خطر؟">

`pm2 save` بيحفظ نسخة من الـ env وقت الحفظ في `dump.pm2`، فممكن الـ app يقوم بعد الـ reboot وتفتكر إن كله تمام. لكن أول ما تعمل `pm2 delete` و`pm2 start` من terminal جديد، أو تنقل لسيرفر تاني، المتغيرات هتختفي، لأن مصدرها الحقيقي كان `export` في session اتقفلت. وكمان `dump.pm2` بيبقى فيه الأسرار دي كـ نص عادي، فخلي صلاحيات `~/.pm2` لليوزر بس.

</Box>

<File name="ecosystem.config.js">

```js
module.exports = {
  apps: [
    {
      name: "LMS::backend",
      script: "./bin/www",
      cwd: "/home/ubuntu/lms-backend", // عشان .env يتقري من مكان ثابت
      exec_mode: "cluster",
      instances: "max",
      env: { NODE_ENV: "production", PORT: 4000, SERVERHTTPS: "1" },
    },
  ],
};
```

</File>

والأسرار نفسها، زي مسار الـ private key أو باسوورد الداتابيز، متتحطش في Git. حطها في `.env` على السيرفر بصلاحيات `600`، والكود يقراها.

## لو عايز تلغيه

<File name="terminal">

```bash
pm2 unstartup
```

</File>

ده بيطبع أمر sudo، والأمر ده بيعمل `systemctl stop` وبعدين `disable` وبعدين بيمسح ملف الـ service.

<Box type="warn" title="unstartup ممكن يقفل الـ apps">

لو الـ daemon الحالي اتشغّل من systemd، وده حالك بعد أول reboot، فالـ `stop` بينفّذ `pm2 kill`، والـ apps كلها هتقف. شغّلها تاني بـ `pm2 resurrect` أو `pm2 start ecosystem.config.js`. وده بيحصل برضه في خطوة nvm اللي فوق، فاعملها في وقت هادي.

</Box>
