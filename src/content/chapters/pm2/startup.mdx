## `save` تحفظ إيه؟

بعد ما تشغّل التطبيقات بالإعداد الصحيح:

<File name="terminal">

```bash
pm2 list
pm2 save
```

</File>

PM2 تحفظ snapshot للـ process list: الأسماء، العدد، script path والإعدادات اللازمة للـ resurrect. الملف عادةً تحت `~/.pm2/dump.pm2`.

<Hl c="b">`pm2 save` تحفظ القائمة، لكنها لا تجعل النظام يشغّل PM2 عند الإقلاع. محتاج startup service.</Hl>

## الطريقة الرسمية مع systemd

شغّل الأمر الأول **من غير sudo** وأنت داخل بالمستخدم اللي يشغّل التطبيق:

<File name="terminal">

```bash
pm2 startup
```

</File>

PM2 تكتشف init system وتطبع أمرًا شبيهًا بـ:

<File name="terminal">

```bash
sudo env PATH=$PATH:/home/youruser/.nvm/versions/node/v22/bin \
  pm2 startup systemd -u youruser --hp /home/youruser
```

</File>

انسخ الأمر الناتج عندك كما هو ونفّذه؛ الجزء ده يحتاج صلاحية root عشان ينشئ systemd service، لكن الخدمة نفسها مربوطة بـ `youruser`.

## حاجات لازم تاخد بالك منها

### أي تغيير محتاج `save` جديدة

لو ضفت app أو مسحت واحدة أو غيرت عدد instances أو الإعدادات، اعمل:

<File name="terminal">

```bash
pm2 list
pm2 save
```

</File>

وإلا reboot الجاي ممكن يرجّع snapshot القديمة بدل الحالة اللي شايفها دلوقتي.

### نفس المستخدم في كل الخطوات

نفّذ `start` و`save` و`startup` لنفس مستخدم التطبيق. لو `ubuntu` عمل `pm2 save` وroot عمل startup لنفسه، كل واحد له `HOME` و`PM2_HOME` وprocess list مختلفة؛ الخدمة تقوم لكن apps المطلوبة متظهرش.

<File name="terminal">

```bash
whoami
echo "$HOME"
echo "${PM2_HOME:-$HOME/.pm2}"
```

</File>

### غيّرت Node مع nvm؟ جدّد الخدمة

أمر startup الناتج يحتوي مسار Node الحالي. بعد تثبيت أو تفعيل نسخة Node جديدة:

<File name="terminal">

```bash
pm2 unstartup
pm2 startup
# انسخ ونفّذ أمر sudo الجديد اللي PM2 تطبعه
pm2 save
```

</File>

الخدمة القديمة ممكن تفضل تشير إلى فولدر نسخة Node اتحذفت.

### حدّثت PM2؟ حدّث الـ daemon

تحديث الحزمة العالمية لا يبدّل تلقائيًا الـ daemon القديمة الموجودة في الذاكرة:

<File name="terminal">

```bash
pm2 update
pm2 list
```

</File>

راجع release notes واختبر التطبيق قبل تحديث production.

### الـ Environment مش جلسة SSH

متغير عملته بـ `export` في terminal مش مضمون يوصل إلى systemd بعد reboot. حط القيم غير السرية في ecosystem file:

<File name="ecosystem.config.cjs">

```js
module.exports = {
  apps: [{
    name: "backend",
    script: "./bin/www",
    env_production: {
      NODE_ENV: "production",
      SERVERHTTPS: "true",
    },
  }],
};
```

</File>

أو خلي التطبيق يقرأ `.env` من مسار ثابت. الأسرار زي `SSL_PRIVATE_KEY` متتحطش في Git؛ استخدم secret manager أو ملفًا محميًا بصلاحيات مناسبة. بعد تغيير environment، أعد تشغيل التطبيق بالطريقة المناسبة وراجع القيم ثم `pm2 save`.

<Hl c="o">نفس المستخدم + snapshot حديثة + PATH صحيح + env ثابتة = التطبيق يعرف يرجع بعد reboot.</Hl>

## بديل Cron لما systemd مش متاح

ده fallback، مش أفضل من service manager:

<File name="terminal">

```bash
command -v pm2
crontab -e
```

</File>

في crontab **لنفس المستخدم**:

<File name="crontab">

```cron
@reboot /home/youruser/.npm-global/bin/pm2 resurrect
```

</File>

استخدم المسار اللي طلع فعلًا، وتأكد إن `HOME` و`PM2_HOME` لنفس المستخدم. Cron environment محدودة، عشان كده المسار المطلق مهم.

## متحذفش log شغال بـ `rm`

لو process فاتحة file descriptor وحذفت الملف، ممكن تفضل تكتب في inode محذوف وتستهلك مساحة من غير ملف واضح. استخدم:

<File name="terminal">

```bash
pm2 flush
pm2 restart all
```

</File>

`flush` يفضي logs المدارة. Restart يخلي التطبيق يفتح الملفات من جديد، لكنه يعمل downtime في Fork mode؛ الأفضل log rotation بدل الحذف اليدوي.
