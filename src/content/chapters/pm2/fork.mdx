## معنى Fork هنا

في PM2، Fork mode يشغّل البرنامج كـ process مستقلة. لتطبيق Node، PM2 يستخدم آلية تشغيل process مناسبة ويديرها، لكن مفيش Node cluster بيوحّد الـ server handle بين النسخ.

لو شغّلت ٣ نسخ من `server.js` وكلهم بيحاولوا يمسكوا port 3000، أول واحدة تكسب والباقي يقع بـ `EADDRINUSE`.

<Box type="warn" title="fork() مش معناه memory مشتركة">

`child_process.fork()` اسمه جاي من API Node، لكنه بيشغّل Node process جديدة بقناة IPC. كل process عندها heap وevent loop وglobals منفصلين.

</Box>

## من غير PM2

<File name="fork-launcher.js">

```js
import { fork } from "node:child_process";

for (const port of [3001, 3002, 3003]) {
  const start = () => {
    const child = fork("./server.js", {
      env: { ...process.env, PORT: String(port) },
    });

    child.once("exit", (code) => {
      console.log(`port ${port} exited with ${code}`);
      setTimeout(start, 1000);
    });
  };

  start();
}
```

</File>

كل process على port. العميل محتاج load balancer قدامهم:

<File name="/etc/nginx/conf.d/api.conf">

```nginx
upstream node_api {
  server 127.0.0.1:3001;
  server 127.0.0.1:3002;
  server 127.0.0.1:3003;
}

server {
  listen 80;

  location / {
    proxy_pass http://node_api;
  }
}
```

</File>

## بـ PM2 وports متزايدة

<File name="ecosystem.fork.config.cjs">

```js
module.exports = {
  apps: [{
    name: "api-fork",
    script: "server.js",
    exec_mode: "fork",
    instances: 3,
    increment_var: "PORT",
    env: { PORT: 3001 },
  }],
};
```

</File>

`increment_var` يخلي النسخ تاخد 3001 ثم 3002 ثم 3003. شغّل:

<File name="terminal">

```bash
pm2 start ecosystem.fork.config.cjs
pm2 list
pm2 logs api-fork
```

</File>

استخدمنا `.cjs` لأن المشروع ممكن يكون `"type": "module"`، بينما ملف ecosystem هنا مكتوب بـ `module.exports`.

## Fork مناسب لإيه؟

- process واحدة بسيطة أو script.
- queue consumer وbackground worker مبيفتحش HTTP port.
- Python أو Bash أو binary؛ Cluster mode خاص بتطبيقات Node الشبكية.
- Docker/Kubernetes لما كل container يشغّل process واحدة، والـ orchestrator هو اللي يكرر replicas.
