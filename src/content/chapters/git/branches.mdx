<Hl c="p">الـ branch مش نسخة من المشروع. هو اسم لازق على commit واحد، وبيتحرك لقدام لوحده كل ما تعمل commit جديد</Hl>.

عشان كده عمل branch في Git سريع جدًا ومش بياخد مساحة: Git بيكتب hash في ملف صغير، وخلاص.

## شكلها عامل إزاي

```text
A ← B ← C        ← main
         ↖
           D ← E ← feature/cart
```

`main` لازق على `C`، و `feature/cart` لازق على `E`. الاتنين بيشاركوا نفس التاريخ لحد `C`، وبعد كده كل واحد مشي في طريق.

## الـ HEAD

الـ HEAD هو "إنت واقف فين دلوقتي". غالبًا بيشاور على branch، والـ branch بيشاور على commit.

```bash
git switch -c feature/cart   # اعمل branch جديد وروحله
git switch main              # ارجع لـ main
git branch                   # كل الـ branches، والنجمة جنب اللي إنت عليه
```

لما تعمل commit، الـ branch اللي الـ HEAD بيشاور عليه هو اللي بيتحرك للـ commit الجديد. الـ branches التانية مبتتحركش.

<Box type="story" icon="🔖" title="الفواصل في الكتاب">

الكتاب هو التاريخ كله. الـ branch فاصل بتحطه على صفحة. الـ HEAD هو إيدك: الفاصل اللي إنت ماسكه دلوقتي. لما تكتب صفحة جديدة، الفاصل اللي في إيدك بس هو اللي بيتنقل عليها.

</Box>

## `switch` ولا `checkout`؟

`git checkout` قديم وبيعمل حاجات كتير: يغيّر branch، ويرجّع ملف، ويروح لـ commit. عشان كده اتقسم في Git 2.23 لأمرين أوضح:

- `git switch`: تغيّر الـ branch.
- `git restore`: ترجّع ملف (فصل ٦).

`checkout` لسه شغال، وهتلاقيه في كل حتة على الإنترنت، بس الجداد أوضح.

## الـ detached HEAD

لو عملت `git switch --detach a3f9c21` أو `git checkout a3f9c21`، الـ HEAD بيشاور على commit مباشرة، مش على branch. ده اسمه **detached HEAD**.

ده مفيد عشان تبص على الكود القديم. بس لو عملت commits وإنت كده، مفيش branch بيتحرك معاك. ولو رحت لـ branch تاني، الـ commits دي ملهاش اسم، وممكن تتوه.

<Box type="warn" title="عملت commits وإنت detached؟">

قبل ما تمشي، ادّيها اسم:

```bash
git switch -c fix/old-bug
```

ولو مشيت خلاص ونسيت، متقلقش. `git reflog` (فصل ٦) هيلاقيها.

</Box>
