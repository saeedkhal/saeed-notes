## أسئلة المتابعة

<Grid2>
<Card title="🎬 ملف ٥ جيجا؟" c={1}>

**Multipart upload**: الملف يتقسم أجزاء (مثلًا ١٠ ميجا)، كل جزء له pre-signed URL، وبيترفعوا بالتوازي. جزء فشل؟ تعيده هو بس. وفي الآخر `CompleteMultipartUpload`.

</Card>
<Card title="📶 النت قطع في النص؟" c={2}>

**Resumable**: احفظ الأجزاء اللي خلصت (مع الـ multipart)، وكمّل من عندها. أو بروتوكول جاهز زي tus.

</Card>
</Grid2>

<Grid2>
<Card title="🌍 التنزيل بطيء بعيد عن الـ region؟" c={3}>

**CDN** (CloudFront مثلًا) قدام الـ bucket بـ signed URLs أو signed cookies خاصة بيه، فالملف يتخدّم من أقرب مكان.

</Card>
<Card title="🖼️ thumbnail وفحص فيروسات؟" c={4}>

**Background job**: S3 يبعت event لما ملف يتحط، يروح لـ queue، و worker يعمل الـ processing ويحدّث الحالة في الـ DB. الـ request مايستناش.

</Card>
</Grid2>

<Box type="tip" title="لو الـ interviewer سأل: ليه مش تعمل complete بالـ event بس؟">

ممكن، وده أأمن في حاجة: الـ event جاي من S3 مش من الـ client. بس الـ events ممكن تتأخر أو تتكرر، فالـ worker لازم يبقى **idempotent**. كتير من الأنظمة بتعمل الاتنين: `complete` من الـ client عشان الـ UI يرد بسرعة، والـ event عشان الـ processing.

</Box>

## أرقام تقولها بثقة

| النقطة | رقم معقول |
| --- | --- |
| عمر الـ pre-signed URL | ٥–١٥ دقيقة |
| حجم الجزء في multipart | ٥–١٠٠ ميجا (S3 بيشترط ٥ ميجا على الأقل لكل جزء ما عدا الأخير) |
| إمتى multipart | فوق ١٠٠ ميجا تقريبًا |
| مسح الـ uploads المعلّقة | lifecycle rule بعد يوم |
