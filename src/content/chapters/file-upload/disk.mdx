## الحل اللي بييجي في دماغك الأول

المستخدم يرفع الملف للسيرفر، والسيرفر يحفظه على الديسك ويكتب المسار في الـ database. ولما حد يطلبه، السيرفر يقراه من الديسك ويرجّعه.

<File name="upload.ts">

```ts
import express from "express";
import multer from "multer";

const upload = multer({ dest: "uploads/", limits: { fileSize: 10 * 1024 * 1024 } });
const app = express();

app.post("/files", requireAuth, upload.single("file"), async (req, res) => {
  const file = await db.file.create({
    data: { ownerId: req.user.id, path: req.file!.path, name: req.file!.originalname },
  });
  res.status(201).json({ id: file.id });
});
```

الملف اتحفظ على ديسك A، والطلب اللي بعده راح لـ B. بالنسبة لـ B الملف مش موجود. السيرفر بقى **stateful**: شايل حاجة لازم الطلبات اللي بعد كده ترجعله هو بالذات.

## المشكلة التانية والتالتة

<Grid2>
<Card title="🏋️ السيرفر شايل حاجات مش شغله" c={4}>

بيستقبل الـ upload، ويخدّم الـ download، ويدير المساحة، بدل ما يركز في الـ business logic. ملف ٥٠٠ ميجا بيمسك connection و memory طول ما هو بيعدّي.

</Card>
<Card title="💥 الملفات ممكن تضيع" c={2}>

السيرفر وقع، أو اتبدّل في deployment (container جديد)، والديسك راح معاه. ومفيش نسخ احتياطي إلا لو عملته بإيدك.

</Card>
</Grid2>

<Box type="warn" title="sticky sessions مش حل">

ممكن تقول "خلّي الـ load balancer يبعت كل مستخدم لنفس السيرفر". ده بيأجل المشكلة بس: مستخدم تاني عايز يشوف الملف هيروح لسيرفر تاني، والسيرفر لو وقع الملفات راحت برضه.

</Box>
