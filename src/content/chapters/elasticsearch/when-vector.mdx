مفيش قاعدة تقول: مليون صف استخدم SQL، وعشر مليون استخدم Elasticsearch. العدد لوحده بيضيّع السؤال.

## Vector: البحث بالمعنى

لحد هنا البحث بالكلمات: التوكن موجود أو قريب إملائيًا. اليوزر ساعات يكتب النِيّة: "موبايل تصويره كويس بالليل". الوصف ممكن يقول low light و night mode من غير كلمة "بالليل".

<En>Vector search</En> يحوّل النص لـ <En>embedding</En>: قائمة أرقام يمثلها موديل. Elasticsearch يخزنها في حقل `dense_vector` ويدور على أقرب المتجهات. ده <En>semantic search</En>. الموديل هو اللي يطلّع الأرقام. متألفش المتجه في الكود.

<File name="src/embed.js">

```js
export async function embed(text) {
  const res = await fetch(process.env.EMBED_URL, {
    method: "POST",
    headers: { "content-type": "application/json" },
    body: JSON.stringify({ text }),
  });
  if (!res.ok) throw new Error("embed_failed");
  const json = await res.json();
  return json.vector;
}
```

</File>

<File name="src/knn.js">

```js
export function knnQuery(vector) {
  return {
    field: "embedding",
    query_vector: vector,
    k: 20,
    num_candidates: 100,
  };
}
```

</File>

طول `dims` في الـ mapping لازم يساوي طول متجه الموديل بالظبط. غيّرت الموديل؟ الإندكس القديم مش هيتقارن مع المتجه الجديد. ده reindex، مش زرار.

<Box type="warn" title="الـ SKU مش سؤال معنى">

اليوزر لو لصق رقم موديل أو SKU، التطابق الحرفي هو الصح. أقرب معنى ممكن يرجّع منتج شبيه ويفوّت الكود نفسه. الـ vector مش بديل للـ keyword search.

</Box>

## Hybrid: القائمتين يتلموا بالترتيب مش بالدرجة

درجة BM25 ودرجة القرب بين المتجهات مش على نفس المسطرة. تجمعهم رقم واحد بيفسد الاتنين. <En>Hybrid search</En> يشغّل البحث بالكلمة والبحث بالمتجه، وبعدين يدمج **الترتيب** بـ <En>RRF</En> (Reciprocal Rank Fusion): كل نتيجة تاخد نقاط من مكانها في كل قائمة، واللي فوق في الاتنين يطلع الأول.

<Flow items={[
  { t: "Keyword", s: "BM25 + فلاتر", c: 4 }, "+",
  { t: "Vector", s: "أقرب معنى", c: 2 }, "→",
  { t: "RRF", s: "دمج بالترتيب", c: 3 },

<File name="src/hybrid.js">

```js
import { textQuery } from "./search-text.js";
import { embed } from "./embed.js";

export async function hybridSearch(es, q) {
  const vector = await embed(q);
  return es.search({
    index: "products",
    retriever: {
      rrf: {
        retrievers: [
          { standard: { query: textQuery(q) } },
          { knn: { field: "embedding", query_vector: vector, k: 30, num_candidates: 100 } },
        ],
        rank_window_size: 50,
        rank_constant: 60,
      },
    },
  });
}
```

</File>

شكل الـ `retriever` اتظبط بين الإصدارات. راجع الـ docs قبل ما تنقله. لو الإصدار عندك لسه من غير RRF، نفّذ البحثين وادمّج الترتيب في Express بنفس الفكرة، ومتجمعش `_score` مع مسافة المتجه.

الفلاتر (مخزون، سعر، براند) لسه لازمة على الناحيتين. نتيجة "قريبة في المعنى" بس خلصت من المخزن، أو من قسم تاني، بتبوّظ الصفحة زي ما الكفر كان بيبوّظ الترتيب.
