## الاتنين فيهم الكلمة، وواحد بس هو المقصود

اليوزر كتب `iPhone 15 Pro`. عندك:

- **Apple iPhone 15 Pro** — المنتج نفسه، والكلمات في الاسم.
- **Case compatible with iPhone 15 Pro** — إكسسوار، والكلمات في وصف توافق.

الاتنين match. لو رجّعت الصفوف زي ما الداتابيز لقيتها، الكفر ممكن يبقى فوق. اليوزر هيحس إن البحث مكسور حتى لو "الكلمة موجودة".

<Hl c="y">الترتيب بالنِيّة اسمه relevance ranking.</Hl> Elasticsearch بيدي كل نتيجة `_score`. الأعلى يظهر الأول. الافتراضي من سنين هو خوارزم <En>BM25</En>.

<Box type="story" icon="🍜" title="طلب كشري مخصوص">

العميل قال "كشري مخصوص". طبق الكشري الكامل أولى من طبق السلطة اللي فيه شوية رز. الاتنين فيهم رز. النِيّة مش كده.

</Box>

## BM25 بيبص على إيه؟

من غير ما نحفظ المعادلة، ثلاث حاجات بتحرّك الرقم:

1. **تكرار الكلمة في الحقل.** بس مش خط مستقيم. تكرار زيادة بيفرق في الأول وبعدين التأثير بيقل، عشان حد ميحشي الوصف بكلمة `iphone` عشرين مرة ويطلع الأول.
2. **ندرة الكلمة.** `pro` موجودة في منتجات كتير، فوزنها أقل من كلمة نادرة زي موديل قليل. كلمة الناس كلها كاتباها مش بتفرّق أوي.
3. **طول الحقل.** نفس الكلمة في اسم قصير أقوى من وجودها وسط وصف من فقرتين. الاسم إشارة أوضح.

الـ `_score` رقم داخلي للمقارنة بين نتائج **نفس** السؤال. مش نسبة من ١٠٠، ومتعرضهوش لليوزر كـ "تطابق ٨٧٪". سؤال تاني بأرقام تانية خالص.

## الـ Boosting: الاسم أهم من الوصف

تقدر تقول للمحرك: خد تطابق `name` بوزن أعلى من `description`. ده <En>boosting</En>، وبيتعمل في الكويري مش في الـ mapping (الـ boost القديم على الحقل نفسه بقى قديم).

<File name="src/search-text.js">

```js
export function textQuery(q) {
  return {
    bool: {
      should: [
        { term: { sku: { value: q, boost: 20 } } },
        {
          multi_match: {
            query: q,
            fields: ["name^3", "description"],
            type: "best_fields",
          },
        },
      ],
      minimum_should_match: 1,
    },
  };
}
```

</File>

`name^3` يعني مساهمة الاسم تتضرب في ٣ قبل ما تتقارن بالوصف. الرقم مش قانون سماوي. جرّب ٣ و ٥ على منتجات حقيقية: موبايل، كفر، شاحن متوافق، وإكسسوار اسمه فيه الكلمة بالصدفة. الـ SKU لو اتطابق بالظبط ياخد دفعة كبيرة عشان ميتوهش وسط نص شبيه.

<Box type="tip" title="الترتيب بالسعر بيسيب الـ score">

لو اليوزر اختار "الأرخص"، ابعت `sort: [{ price: "asc" }]`. ساعتها BM25 مش هو اللي بيرتّب الصفحة. ده قرار مقصود: هو دلوقتي بيتصفح مش بيدور على الأقرب. من غير `sort`، الترتيب الافتراضي `_score` تنازلي.

</Box>

## شوف ليه النتيجة دي خدت الرقم ده

<File name="src/explain.js">

```js
import { es } from "./es.js";
import { textQuery } from "./search-text.js";

const explained = await es.explain({
  index: "products",
  id: "p-1001",
  query: textQuery("iphone 15 pro"),
});

console.log(explained.explanation);
```

</File>

الـ API بيرجع شجرة: أنهي حقل ساهم، وأنهي كلمة كانت نادرة. استخدمه وأنت بتظبط الأوزان، مش في كل طلب بحث من الموقع. تقيل، وشكله مش لليوزر.
