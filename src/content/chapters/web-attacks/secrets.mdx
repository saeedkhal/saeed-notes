## الفكرة في سطر

<Flow items={[{"t": "API Key", "c": 1, "s": "في الكود أو .env اتعمله commit"}, "→", {"t": "Public Repo", "c": 3, "s": "أو frontend bundle"}, "→", {"t": "Bots", "c": 2, "s": "بيلاقوه في دقايق"}]} />

في bots بتعمل scan للريبوهات العامة على GitHub طول الوقت، وبتدوّر على أشكال المفاتيح المعروفة (AWS و Stripe و OpenAI…). المفتاح اللي يتعمله push بيتلقط في <Hl c="o">دقايق، مش أيام</Hl>، وبيتستخدم في mining أو spam على حسابك.

<Box type="story" icon="🗝️" title="المفتاح تحت الدوّاسة">

حطيت مفتاح الشقة تحت الدوّاسة وعملت post على الفيسبوك بصورة الباب. حتى لو مسحت البوست بعد دقيقة، حد شافه. الحل مش إنك تمسح البوست، الحل إنك **تغيّر الكالون**.

</Box>

## ليه المسح مش كفاية

لو عملت commit فيه secret ومسحته في commit تاني، المفتاح **لسه في الـ history**. أي حد عمل clone أو fork، أو أي cache، معاه نسخة.

<Box type="warn" title="الترتيب الصح لما سر يتسرب">

1. **Rotate**: اعمل revoke للمفتاح القديم واطلع واحد جديد، فورًا.
2. شوف الـ logs بتاعة الخدمة: حد استخدمه؟
3. بعدين نضّف الـ history لو محتاج (`git filter-repo` مثلًا)، بس ده تجميل، مش الحل.

</Box>

## الفخ بتاع الـ frontend

أي متغيّر بيدخل في الـ bundle بتاع React **عام**. أي حد يفتح DevTools يشوفه.

<File name=".env">

```bash
# ✅ عام بطبيعته: عادي يبقى في الـ bundle
VITE_API_URL=https://api.example.com

# ❌ ده هيتحط في JavaScript اللي بيروح لكل زائر
VITE_STRIPE_SECRET_KEY=sk_live_...

# ✅ سر: يفضل على السيرفر بس، من غير prefix
STRIPE_SECRET_KEY=sk_live_...
```

</File>

الـ prefix زي `VITE_` و `NEXT_PUBLIC_` معناه "حط ده في كود المتصفح". لو الـ frontend محتاج يكلّم خدمة بمفتاح سري، يبقى يكلّم **الـ backend بتاعك**، والـ backend هو اللي معاه المفتاح.

<Box type="tip" title="قلّل الضرر">

اعمل كل مفتاح بأقل صلاحيات (read-only لو كفاية)، وحط عليه حد للاستخدام أو للميزانية، وفعّل التنبيهات. ولو الخدمة بتدعمه، استخدم tokens قصيرة العمر بدل مفاتيح دايمة، زي OIDC في GitHub Actions بدل AWS keys ثابتة.

</Box>
