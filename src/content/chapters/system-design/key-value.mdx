## الفكرة

داتابيز بسيطة جدًا: `put(key, value)` و `get(key)`. سهلة على سيرفر واحد (hash table في الميموري). لما الداتا تكبر لازم نوزّعها — وهنا تبدأ الحكاية.

## نظرية CAP

في أي سيستم موزع، مش هتقدر تضمن التلاتة مع بعض:

<Chips items={["C — Consistency", "A — Availability", "P — Partition tolerance"]} />

- **C:** الكل يشوف نفس الداتا.
- **A:** دايمًا فيه رد.
- **P:** يكمل لو الشبكة اتقطعت.

ولأن انقطاع الشبكة لازم هيحصل، الاختيار الحقيقي بيبقى بين الاتنين دول:

<Grid2>
<Card title="CP" c={5}>

زي نظام بنكي: أرفض أرد أحسن ما أدي رقم غلط. الاتساق أهم من إنك ترد فورًا وقت انقطاع الشبكة.

</Card>
<Card title="AP" c={3}>

أرد بداتا ممكن تكون قديمة شوية. زي كتالوج منتجات: الأحسن تشوف سعر متأخر دقيقة من إن الصفحة تقع.

</Card>
</Grid2>

## المكونات الأساسية

| الموضوع | الحل بالمصري |
| --- | --- |
| Partitioning | Consistent hashing + virtual nodes من الفصل اللي فات |
| Replication | كل key يتنسخ على N سيرفرات (أول N سيرفرات مختلفة مع عقارب الساعة)، ويفضّل في داتا سنترز مختلفة |
| Quorum | `W` = كام نسخة لازم تأكد الكتابة، `R` = كام نسخة لازم ترد في القراية. لو `W + R > N` يبقى strong consistency. `W=1` أو `R=1` أسرع |
| Consistency | Strong، Weak، و Eventual (الأشهر في Dynamo و Cassandra: النسخ بتتفق في الآخر) |
| Vector clocks | أزواج `[server, version]` مع كل قيمة عشان تعرف فيه conflict ولا لأ. عيبها إنها بتكبر |
| Gossip | كل نود بيبعت heartbeat لنودز عشوائية. لو نود ماحدش سمع منه فترة، يعتبروه واقع |
| Hinted handoff | فشل مؤقت؟ نود تاني يشيل الكتابة مكانه، ولما يرجع يسلّمهاله |
| Merkle tree | فشل دايم؟ تقارن النسخ بشجرة hashes عشان تزامن الجزء المختلف بس |
