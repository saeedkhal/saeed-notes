## موقع محتوى مش تطبيق جوّه المتصفح

Astro معمول لمواقع **المحتوى هو البطل**: مدونة، لاندينج، توثيق، بورتفوليو، متجر واجهته صفحات، موقع شركة. الزائر عايز يقرأ بسرعة، ومحرك البحث عايز HTML واضح من أول طلب.

أُطر كتير اتبنت الأول عشان **تطبيقات** جوّه المتصفح: داشبورد، شات، كانبان. النموذج ده اسمه <En>SPA</En>: الصفحة فاضية تقريبًا، وجافاسكربت يبني الواجهة بعد التحميل. Astro ماشي على النموذج التاني، <En>MPA</En>: كل رابط صفحة HTML كاملة، والانتقال الافتراضي تحميل عادي.

<Hl c="y">الافتراضي في Astro إن الصفحة توصل HTML و CSS، ومن غير JavaScript للزائر.</Hl>

<Box type="story" icon="🧾" title="المنيو المطبوع">

الـ SPA زي ما تدي الزبون شاشة فاضية وبرنامج يرسم المنيو قدامه. Astro بيدي الزبون **المنيو مطبوع**. لو حتة واحدة محتاجة زرار حي (عداد الطلبات)، تحط البرنامج على الحتة دي بس.

</Box>

## معمارية الجزر

الصفحة جزيرة كبيرة من HTML ثابت. جوّاها **جزر** صغيرة: مكوّنات واجهة بتتبعت للمتصفح وتشتغل هناك. كل جزيرة ليها أمر صريح يقول امتى تشتغل. من غير الأمر ده، حتى مكوّن React بيترندر HTML على السيرفر و**مش** بينزّل جافاسكربت بتاعه.

<Flow items={[{"t": "صفحة .astro", "c": 1, "s": "HTML على السيرفر"}, "→", {"t": "مكوّن React", "c": 2, "s": "من غير directive = HTML بس"}, "→", {"t": "client:visible", "c": 4, "s": "الجزيرة تشتغل لما تبان"}]} />

Astro مش مربوط بإطار واحد. نفس المشروع يقدر يستخدم React و Svelte و Vue و Preact و Solid ومكوّنات الويب، كل واحد في الجزيرة بتاعته.

<Box type="warn" title="مش كل مشروع محتاجه Astro">

لو المنتج **تطبيق** حالته كلها في المتصفح (محرر زي Figma، أو داشبورد كل بكسل فيه تفاعلي)، إطار SPA ممكن يكون أوضح. Astro لسه ينفع كصدفة HTML حوالين الجزر دي، بس مش هتكسب أوي من "صفر جافاسكربت" لو الصفحة كلها جزر.

</Box>

<Box type="interview" title="سؤال إنترفيو">

"ليه Astro أسرع في أول تحميل؟" — لأن الزائر بيستلم HTML جاهز، وجافاسكربت الواجهة **مش** بيتبعت إلا للجزيرة اللي علّمت عليها `client:*`. باقي الصفحة مش بتستنى hydration.

</Box>
