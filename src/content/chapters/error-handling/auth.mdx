`401` يعني الجلسة خلصت أو التوكن مرفوض. المستخدم مش هيصلح ده من الخانة، ومش محتاج توست يقول «غير مصرّح». محتاج يروح يسجّل دخوله.

المكان Axios instance، مش جوه كل `useQuery`. أي طلب يعدّي من الـ instance يتفحص رده.

<File name="src/shared/api/client.ts">

```ts
import axios from "axios";
import { router } from "@/app/router";

export const api = axios.create({
  baseURL: "/api",
});

api.interceptors.response.use(
  (response) => response,
  (error) => {
    if (!axios.isAxiosError(error)) return Promise.reject(error);

    const status = error.response?.status;
    const url = error.config?.url ?? "";

    if (status === 401 && !url.includes("/login")) {
      router.navigate({ to: "/login" });
    }

    return Promise.reject(error);
  },
);
```

</File>

`router` هو نفس راوتر التطبيق. `navigate` يغيّر العنوان لـ `/login` من غير ما كل شاشة تعرف.

الرفض يكمل بعد التحويل. TanStack Query لسه شايفة إن الطلب فشل، عشان الزرار يبطل التحميل. التوست ساكت على `401`، زي ما إعداد الكاش عمل.

<Box type="warn" title="طلب الدخول نفسه">

لو صفحة تسجيل الدخول بتطلب `/login` والرد `401` لأن الباسورد غلط، التحويل تاني يلف. الشرط `!url.includes("/login")` يمنع كده. غلط الباسورد في الفورم رسالة فوق الحقول، مش رجوع لنفس الصفحة.

</Box>

<Hl c="b">401 مش توست. التحويل هو الرد.</Hl>

سجّل الـ interceptor على الـ instance الواحد اللي الكويري بتستخدمه. instance تاني من غير الـ interceptor هيكمّل الطلب ويفتح توست بدل ما يحوّل.
